# 알파작업완료확인 프로그램 v2.12.0

**[v2.12.0 프로그램 ZIP 다운로드](https://github.com/swsgood79-beep/Tool/raw/refs/heads/main/releases/AlphaWorkComplete-Windows-x64-v2.12.0.zip)**

Windows 10/11 x64용입니다. 기존 프로그램의 **종료** 버튼을 누르고 새 ZIP의 `AlphaWorkComplete.exe`를 실행하세요. 기존 수주·검사 기록·Excel 자동 저장은 유지됩니다.

## 고정 QR은 어떻게 동작하나요?

QR은 `https://swsgood79-beep.github.io/Tool/`의 고정 페이지를 엽니다. 프로그램이 실행 중인 회사 PC의 최신 연결 주소만 GitHub에 갱신하고, 페이지가 해당 PC의 작업자 화면으로 안내합니다. 재시작으로 Cloudflare 임시 주소가 바뀌어도 인쇄한 QR은 유지됩니다.

ngrok 계정이나 유료 도메인은 필요하지 않습니다. 대신 아래의 **GitHub 최초 설정 2가지**가 필요합니다. PC·프로그램·인터넷은 켜져 있어야 하며 GitHub/Cloudflare 서비스가 정상이어야 합니다.

## 처음 한 번: GitHub Pages 활성화

1. [Tool 저장소의 Pages 설정](https://github.com/swsgood79-beep/Tool/settings/pages)을 엽니다.
2. Build and deployment에서 **Source: Deploy from a branch**를 선택합니다.
3. **Branch: gh-pages**, 폴더 **/ (root)**를 선택하고 **Save**합니다.
4. 게시에는 몇 분 걸릴 수 있습니다. [고정 페이지](https://swsgood79-beep.github.io/Tool/)가 열리는지 확인하세요. 주소만 열었을 때 ‘작업장 QR을 다시 스캔해 주세요’라는 안내가 나오면 정상입니다.

정적 페이지 파일은 gh-pages 브랜치에 준비되어 있습니다. 페이지를 위한 파일만 들어 있고 EXE·작업자 기록·Excel은 올리지 않습니다.

## 처음 한 번: PC의 GitHub 연결 키 저장

1. [Fine-grained personal access token 만들기](https://github.com/settings/personal-access-tokens/new)를 엽니다.
2. Resource owner를 **swsgood79-beep**, Repository access를 **Only select repositories → Tool**로 제한합니다.
3. Repository permissions에서 **Contents: Read and write**를 지정합니다. Pages 관리나 Actions 권한은 필요하지 않습니다.
4. 발급한 키를 복사하고, EXE의 **고정 QR 설정**을 엽니다.
5. 연결 방식 **GitHub Pages 고정 QR**을 선택하고 **GitHub 연결 키**에 입력한 뒤 저장합니다. 키를 채팅·GitHub 파일·이메일에 보내지 마세요.
6. EXE에서 **인터넷 연결**을 누릅니다. ‘GitHub 고정 QR 연결됨’이 표시되면 **수주·QR 관리**에서 QR을 저장합니다.

기존 임시/ngrok QR은 **이번에 한 번 새로 출력**하세요. 이후 프로그램 업데이트·PC 재시작에도 이 QR을 사용합니다. 저장소/사용자 이름/Pages 주소 또는 PC 기록 파일을 바꾸거나 삭제하지 마세요. 인증키가 만료되면 새 키로 저장하면 되며 QR은 유지됩니다.

프로그램은 Pages가 게시되었는지 확인하고, PC 연결 주소 등록에 성공한 다음 연결됨을 표시합니다. 고정 페이지는 브라우저의 교차 출처 접속 확인 없이 검증된 최신 작업자 주소로 바로 이동합니다. 실제 연결 전에 QR을 출력한 경우 접수는 아직 불가능할 수 있습니다. 첫 등록이나 주소 반영에는 잠시 시간이 걸릴 수 있습니다.

## 저장되는 정보

- GitHub의 `qr-endpoint.json`: 현재 임시 접속 주소·연결 여부·갱신시각·연결 구분용 임시 ID만 저장합니다.
- 작업자 이름·검사 기록·Excel·프로그램 인증키·QR 접근 키는 해당 JSON에 넣지 않습니다.
- QR 접근 키는 URL의 fragment(`#k=...`)에 들어 있어 GitHub 페이지 요청/연결정보 파일 요청으로 전송하지 않습니다.
- GitHub 인증키는 `%APPDATA%\WanryoTalk\connection-v1.dat`에 Windows 계정으로 암호화하고, 설정 화면에 다시 노출하지 않습니다.
- PC가 꺼져 있으면 페이지가 안내하고 재시도할 수 있습니다. 비정상 종료 때 상태가 남으면 Cloudflare의 연결 종료 화면이 나타날 수 있습니다. 이 경우 관리자 PC에서 연결을 다시 시작하세요.

## 기존 검사·Excel 기능

세팅검사를 먼저 완료한 뒤 출하검사가 활성화됩니다. 검사별 작업자·시각을 별도로 저장합니다. 두 검사 모두 끝나면 작업자 목록에서 사라지고 관리자 기록은 남습니다.

문서 폴더 **완료톡/작업완료기록.xlsx** 하나에 한국시간 기준 월별 시트(예: **2026-11**, **2026-12**)를 추가합니다. EXE의 **엑셀 폴더**로 위치를 엽니다. 보이는 열은 **수주번호·프로젝트명·검사구분·작업자·완료일자·완료시간** 순서입니다. 중복 방지용 내부 기록번호 열은 숨김 처리합니다. Excel 파일이 잠겨 있으면 PC 원본에 먼저 기록하고 파일을 닫으면 자동 재시도합니다. 브라우저 Excel 다운로드는 사본입니다.

## 월별 시트와 기존 파일 통합

한국시간으로 12월이 되면 **2026-12**, 다음 해 1월이 되면 **2027-01** 시트를 자동 생성합니다. 다음 날에도 같은 월별 시트에 기록을 추가합니다. 프로그램이 꺼져 있었다면 다음 실행 때 해당 월 시트를 만듭니다.

기존 날짜별 시트는 처음 새 버전으로 실행할 때 월별로 합칩니다. 원본은 같은 폴더의 `작업완료기록-일별원본-<식별값>.xlsx`에 한 번 별도 보관하고, 기본 `작업완료기록.xlsx`를 계속 사용합니다. Excel을 열어 파일이 잠겨 있으면 닫은 뒤 자동 재시도를 기다리세요. 이전 버전 EXE로 다시 실행하면 날짜별 시트가 다시 생길 수 있으므로 새 버전을 계속 사용하세요.

기존 날짜 시트에 별도 수식, 충돌하는 분석 열 제목 또는 기록번호 오류가 있으면 원본을 덮어쓰지 않고 저장 대기 상태로 안내합니다. 수식이 있는 경우 원본 파일을 보관하고 이름을 바꾸면 PC 기록에서 새 월별 파일을 생성할 수 있습니다. 일반적인 추가 메모와 셀 서식은 함께 옮깁니다.

**전체 CSV 저장**은 전체 완료 기록을 별도의 표 파일로 내보내는 기능입니다. 최근 100건 제한이 없고 Excel에서도 열 수 있지만 월별 시트나 Excel 서식은 없습니다. CSV와 브라우저에서 받은 XLSX는 사본이며 자동 갱신되지 않습니다.

## 완료한 작업자 표시

세팅검사 완료 후에도 작업자 화면 왼쪽 검사명 아래에 작업자 이름을 표시합니다. 다른 작업자 화면에도 자동 반영됩니다.

## 수주번호별 엑셀 정렬

월별 시트 안에서 수주번호 → 프로젝트명 → 세팅검사 → 출하검사 순으로 자동 정렬합니다. 같은 검사 내에서는 완료시각 순입니다. 기존 시트도 정렬하고 새 기록도 같은 수주에 모읍니다. 완료일자·시각·기록번호는 보존하며 같은 달의 여러 날짜는 하나의 시트에 합치고, 완료일자 열에는 각 날짜를 그대로 저장합니다. 추가한 행별 메모와 셀 서식은 기록과 함께 이동합니다. Excel이 열려 있으면 닫은 뒤 자동 저장을 기다리세요. 예전에 받은 사본은 다시 다운로드해야 합니다.

## 관리자 수정

완료 접수 표의 **수정**에서 작업자 이름을 고치거나 잘못 접수한 완료를 되돌릴 수 있습니다. 수정 사유·수정이력·취소기록은 남기지 않습니다. 이름은 기존 행에 반영하고, 완료를 되돌리면 해당 기록을 PC 목록과 자동 저장 Excel에서 삭제합니다. 이미 다운로드한 사본은 다시 받아야 합니다.

출하검사만 되돌리면 세팅검사 완료는 유지합니다. 세팅검사를 되돌리면 해당 작업 주기의 출하검사도 함께 초기화합니다. 작업자 화면은 약 5초 안에 자동 반영됩니다. 숨김/검사 다시 열기 기능과 별개로 개별 완료를 수정할 수 있습니다.

## 엑셀 열 순서와 수주별 색상

보이는 열을 **수주번호 → 프로젝트명 → 검사구분 → 작업자 → 완료일자 → 완료시간** 순서로 바꿨습니다. 기록번호는 숨겨서 화면에 보이지 않게 합니다. 중복 저장 방지와 수정·삭제 연결을 위해 내부 값은 유지하므로 숨김 열을 삭제하지 마세요. 기존 분석 열은 그대로 둡니다.

같은 수주번호의 행을 묶고 수주가 바뀌면 옅은 파랑/크림색을 번갈아 쓰며 윗부분 구분선을 넣습니다. 같은 프로젝트에 세팅·출하검사 기록이 모두 있으면 **연한 초록색**으로 강조합니다. 초록색도 인접 수주끼리 농도를 달리해 구분합니다. 완료 여부는 보관 중인 검사 기록을 기준으로 하며, 두 검사 기록이 다른 달에 있어도 반영합니다. 완료 기록을 지우면 색상도 다시 계산합니다. 날짜·시간은 실제 Excel 값으로 유지합니다.

기존 자동 저장 파일도 다음 동기화 때 새 형식으로 바꿉니다. 같은 폴더에 `작업완료기록-열변경원본-<식별값>.xlsx`로 원본을 한 번 보관한 뒤 변경합니다. Excel을 닫아 파일 잠금을 해제하고 새 EXE를 실행하세요. 파일이 잠겨 있으면 원본은 유지하고 재시도합니다. 이전 버전 EXE로 돌아가지 마세요.

기존 파일에 사용자 수식이 있으면 참조를 임의로 변경하지 않고 열 변경을 보류합니다. 이때 원본을 보관하고 파일명을 바꾸면 PC 원본 기록에서 새 형식 파일을 만들 수 있습니다. 월별 시트·수주번호 정렬·메시지 Excel 제외 정책·QR은 그대로입니다. 이 변경은 XLSX 파일에 적용되며 CSV 내보내기 형식은 유지합니다.

## 금일 출하 완료 목록

작업자 화면의 **출하검사 대기** 오른쪽에 **금일 출하 완료** 탭을 추가했습니다. 한국시간 기준 오늘 출하검사를 완료한 수주의 **수주번호·프로젝트명**을 조회합니다. 세팅검사만 완료한 수주와 비고 메시지는 포함하지 않습니다. 같은 프로젝트의 당일 출하 기록이 여러 건이면 목록에는 한 번 표시합니다.

수주번호·프로젝트명 검색을 그대로 사용할 수 있습니다. 목록은 조회 전용으로 검사 완료 버튼이 없습니다. 출하 완료나 관리자 기록 변경은 약 5초 안에 이미 열린 화면에도 반영되고, 자정이 지나면 새 날짜의 목록으로 갱신됩니다. 과거 검사 기록과 월별 Excel 기록은 삭제하지 않습니다. 프로젝트를 삭제해도 보관 중인 완료 기록은 오늘 목록에 나타날 수 있고, 완료 기록 자체를 삭제하면 해당 항목도 반영됩니다.

모바일에서는 네 가지 탭을 2열로 표시해 **출하검사 대기 / 금일 출하 완료**가 나란히 보이도록 했습니다. 휴대폰 알림 추가는 사용자 요청에 따라 보류했습니다. 기존 인쇄 QR·GitHub 고정 주소·연결키는 변경하지 않았습니다.

## 관리자 목록과 Windows 창 디자인

관리자 수주 목록은 **8건씩** 페이지로 나누며, 검색과 **전체 / 접수 중 / 검사 완료 / 숨김** 필터를 제공합니다. 수주를 펼치면 검사 작업자·시각, 숨기기/검사 다시 열기/수주 삭제 기능을 이용합니다. 목록 영역의 높이를 제한해 프로젝트 수가 많아도 페이지가 계속 길어지지 않습니다.

받은 소식은 **10건씩** 표시하고 **전체 소식 / 검사 기록 / 비고 메시지**로 구분합니다. 프로젝트·작업자·메시지 검색이 가능합니다. 비고 전체 내용은 수정 화면에서 확인합니다.

작업자 버튼 표시는 **세팅검사**, **출하검사**로 간소화했습니다. 버튼의 동작은 해당 검사를 완료 접수하는 기존 방식이며, 세팅검사 후 출하검사가 활성화되는 순서는 유지합니다.

Windows 실행 창은 알림 카드와 맞춘 화이트·골드 테마, 연결 상태 표시, 둥근 버튼과 영역, 카드형 수신 내역을 사용합니다. 창 크기 조절을 지원하고 수신 내역을 더블클릭하면 상세 내용을 엽니다. X로 알림 영역에 숨기기와 종료 동작은 유지합니다. Windows 대상 빌드·정적 검사를 수행했으며 실제 Windows에서의 글꼴/배율/렌더링은 이 Linux 개발 환경에서 실행하지 못했습니다.

## 비고 · 문제 전달

작업자가 프로젝트를 펼치면 검사 양식 아래에 **비고 · 문제 전달**이 있습니다. 작업자 이름과 최대 1,000자의 내용을 입력하고 **관리자에게 보내기**를 누르면 됩니다. 여러 줄을 쓸 수 있고 검사 완료와 별도로 여러 번 전송할 수 있습니다. 비고 전송은 세팅/출하검사 상태를 바꾸거나 수주를 목록에서 없애지 않습니다.

관리자 PC에는 프로젝트명·수주번호·작업자·내용 미리보기와 함께 **비고 알림**이 뜹니다. 알림의 **비고 내용 전체 보기**를 누르면 관리자 화면에서 전체 내용을 확인합니다. 관리자 **완료·비고 접수** 내역에 메시지로 보관합니다. **비고는 Excel과 CSV에 저장하지 않습니다.** 이전 v2.8에서 자동 저장된 비고 행과 **비고내용(자동)** 열도 다음 Excel 동기화 때 정리합니다. 검사 기록과 사용자가 따로 작성한 분석 열은 보존합니다.

비고 상세에서는 작성자 이름 수정과 기록 삭제가 가능합니다. 비고는 검사 완료가 아닌 별도 전달이며, 검사 완료 취소 버튼은 표시하지 않습니다. PC/프로그램이 실행되고 인터넷 연결이 정상일 때 수신합니다. 저장 성공 후에만 접수 완료를 표시하고 알림을 생성합니다. 완료 화면에서 목록으로 돌아오면 새로운 비고를 쓸 수 있습니다.

관리자/다른 작업자가 검사 상태를 바꿔 카드가 갱신되어도 같은 접수 주기라면 작성 중인 비고와 이름을 유지합니다. 검사 재접수 주기가 바뀌거나 수주가 숨겨짐·완료·삭제되면 이전 양식은 사용할 수 없으니 목록에서 다시 선택하세요. 일반적인 페이지 새로고침·이동 시 미전송 비고는 저장되지 않습니다.

이번 버전도 기존 QR 주소·접근키·연결키는 그대로 유지합니다. 이전 버전 EXE로 되돌아가지 말고 새 버전을 사용하세요. 실제 Windows 알림 렌더링/소리는 개발 환경에서 실행하지 못했으며 브라우저와 알림 데이터 흐름, Windows 빌드로 검증했습니다.

## 모바일 수주 검색

모바일 목록을 접힌 수주 카드로 정리했습니다. 수주번호·프로젝트명·대기 중인 검사 단계가 보이고, 원하는 수주를 누르면 이름 입력과 완료 버튼이 펼쳐집니다. 완료된 세팅검사 작업자 이름은 카드에도 표시됩니다.

상단의 **수주번호 · 프로젝트명 검색**에 일부만 입력해도 즉시 찾습니다. 영문 대소문자와 공백 차이를 구분하지 않으며, 검색창은 스크롤 중에도 상단에 남습니다. **전체 / 세팅검사 대기 / 출하검사 대기**로 좁혀 보고 검색어와 함께 사용할 수 있습니다. 수주번호는 숫자 순서를 고려해 정렬합니다.

완료 후 다른 수주 보기로 돌아와도 같은 탭의 검색 조건을 유지합니다. 관리자 등록·삭제 및 다른 작업자의 완료가 반영돼도 검색 조건, 펼친 수주와 입력 중인 이름을 가능한 한 유지합니다. 재접수 주기가 바뀌면 이전에 입력한 이름을 지웁니다.

이번 변경은 기존 QR 주소·접근키·GitHub 연결 설정과 월별 기록 저장 방식을 유지합니다. 기존 QR을 다시 출력하지 마세요.

## 접속주소 갱신과 오류 1033 보완

인쇄한 QR의 GitHub 주소는 고정입니다. 프로그램의 인터넷 재연결 때 내부 Cloudflare 임시주소는 새로 발급되고 GitHub에 자동 갱신됩니다. QR을 다시 출력하지 않습니다.

안내 페이지는 가능한 경우 GitHub 공개 API에서 접속정보 파일의 최신 커밋을 찾고, 해당 커밋의 고정된 파일을 읽어 분기 주소 캐시의 영향을 줄입니다. 공개 API가 일시 차단되거나 요청 제한에 걸리면 기존 raw 주소 조회로 대체합니다. 브라우저는 교차 출처 준비상태 요청 없이 작업자 화면으로 직접 이동합니다. 회사 PC 연결이 없는 오래된 작업자 탭은 닫고 고정 QR을 다시 여세요.

PC 프로그램은 터널 등록 로그에 이어 공개 접속주소에서 현재 PC가 새 확인값에 응답하는지 최대 45초 확인한 뒤 주소를 게시합니다. 이후 약 20초 간격으로 점검하고 2회 연속 실패하면 주소를 오프라인 처리하고 재연결합니다. 연속 시작 실패는 3회 시도 후 상태 오류를 표시합니다. GitHub 인증/게시 실패는 반복하지 않고 오류를 표시합니다. 회사 PC에서의 외부 HTTP 확인이며 모든 휴대폰/회사망에서 접속을 보장하지는 않습니다.

개발 환경에서 회사 터널과 GitHub API 실제 연결은 네트워크 정책상 확인하지 못했습니다. 모의 응답 및 Chromium으로 주소 선택·캐시 회피·공개 API 요청 제한 대체·준비상태·1033 감지·자격증명 비전송 등을 검증했습니다. 회사 정책으로 터널이 차단된 경우 보안 제한을 우회하지 말고 전산 담당자 확인이 필요합니다.

## 수주 목록 삭제

수주 오른쪽의 **수주 삭제**를 누르고 다음 화면에서 대상 번호·프로젝트를 확인한 뒤 확인 항목을 체크하고 **수주 삭제 확정**을 누릅니다. 해당 수주만 관리자 목록과 작업자 화면에서 사라집니다. 이미 열린 작업자 화면에는 약 5초 안에 반영되며, 삭제 전 열었던 미제출 완료 양식으로 추가 접수할 수 없습니다.

기존 완료 접수·CSV·월별 Excel 기록은 보관합니다. 기록까지 지우려면 완료 접수의 **수정 → 기록 삭제**를 별도로 사용하세요. 삭제한 수주는 복원할 수 없으며 다시 필요하면 새로 등록해야 합니다. 다른 수주와 고정 QR에는 영향이 없습니다.

## 불필요한 기록 삭제

완료 접수 표의 **수정 → 기록 삭제**에서 확인 항목을 체크하고 삭제합니다. 선택한 한 건만 완료 목록·CSV·자동 저장 Excel에서 제거합니다. 프로젝트의 검사 완료 상태는 유지하므로 작업자 목록에 다시 나타나지 않습니다. 이전 검사 구분이 없는 기록도 삭제할 수 있습니다. 별도 삭제 이력은 남기지 않으며 삭제는 되돌릴 수 없습니다. 재접수가 필요하면 **완료 취소**를 사용하세요.

## 업데이트와 검증

기존 프로그램에서 **종료** 후 새 EXE를 실행하세요. 같은 Windows 계정의 `%APPDATA%\WanryoTalk` 데이터를 이어 사용하므로 QR·연결키·기존 기록은 유지됩니다. 저장 형식은 3으로 이전하며, 기존 암호화 파일을 `projects-v2-backup-*.dat`로 한 번 백업합니다. 이 백업은 데이터 이전용이며 수정 이력을 쌓는 기능은 아닙니다. 업데이트 뒤에는 새 EXE를 계속 사용하세요.

Chromium에서 검사 순서, 다른 작업자 화면의 자동 반영, 이름 수정, 완료 되돌리기, 재접수, 실제 Excel 다운로드를 검증했습니다. 관리자 권한·동시 요청·저장 실패·기존 데이터 이전을 포함한 Go 테스트 74개와 경쟁 상태 검사를 통과했습니다. Windows EXE를 교차 빌드하고 vet 검사했습니다.

이 개발 환경에서는 실제 Windows 알림·DPAPI·소리와 회사망의 휴대폰 접속을 직접 확인하지 못했습니다. EXE의 디지털 코드 서명은 포함하지 않았습니다.

## 안 읽은 알림 숫자와 다시 보기 (v2.11.0)

팝업이 사라져도 화면 오른쪽 아래에 작은 숫자가 남습니다. 숫자를 클릭하면 아직 안 읽은 메시지가 다시 팝업으로 나타납니다. 숫자를 오른쪽 클릭하면 전체 안 읽은 알림 목록을 엽니다. 메인 창을 X로 숨겨도 숫자는 남고, 프로그램을 종료하면 사라졌다가 다음 실행 때 복원됩니다.

팝업 표시·시간 만료·X 닫기는 읽음 처리가 아닙니다. 팝업 본문을 클릭하거나 수신 내역을 더블클릭하여 상세 내용을 실제로 열면 해당 알림을 읽음으로 저장합니다. 저장 실패 시 숫자는 유지하고 상세 화면에서 재시도할 수 있습니다. 관리자 화면의 **안 읽은 알림**에서도 조회할 수 있으며, **현재 알림 모두 읽음**은 목록을 열 때까지 도착한 알림만 처리합니다. 그 뒤 도착한 새 메시지는 남습니다. 0건이면 작은 숫자는 숨깁니다.

읽음 상태는 같은 Windows 계정의 기존 암호화 수주 파일에 보관하며 검사 상태·Excel 데이터에 영향을 주지 않습니다. 기존 버전에는 읽음 추적 기능이 없었으므로 업데이트 전 기록은 읽음으로 초기화하고 새 알림부터 집계합니다. 원본 암호화 파일을 `projects-v3-backup-*.dat` 등으로 먼저 보관한 뒤 버전 4 형식으로 갱신합니다. 이전 EXE로 다시 실행하지 마세요. 기존 QR·고정 주소·연결키는 유지합니다.

저장·권한·브라우저 상세 읽음 처리와 Windows 교차 빌드/정적 검사를 확인했습니다. 이 환경에서는 실제 Windows 바탕화면의 표시·클릭 동작을 실행 검증할 수 없습니다.

## 휴대폰 브라우저 알림 (v2.12.0)

별도 앱 설치 없이 **최신 삼성 인터넷 또는 Chrome 일반 모드**에서 Web Push를 등록합니다. 휴대폰 알림은 PC 팝업과 별개로 보내며, 브라우저 화면을 계속 열어둘 필요는 없습니다. 실제 수신은 Android·브라우저 알림 권한·인터넷·배터리 설정에 따릅니다. 강제 종료·절전 제한·방해금지·사이트 데이터 삭제로 중단되거나 지연될 수 있습니다. 잠금 상태 수신을 보장하는 실시간 경보 시스템은 아닙니다.

1. 새 EXE를 실행하고 **인터넷 연결**을 완료합니다. 기존 GitHub 고정 QR 연결을 사용합니다.
2. **수주 · 메시지 관리 → 내 휴대폰 알림**을 엽니다.
3. **휴대폰 연결용 QR 만들기**를 누릅니다. 본인 휴대폰에서만 스캔하고 삼성 인터넷으로 엽니다.
4. 휴대폰에서 **알림 허용하고 연결**을 누르고 알림을 허용합니다. QR은 10분간 1회만 사용할 수 있습니다. 주소가 갱신되거나 시간이 지났다면 새 연결 QR을 만드세요.
5. PC의 연결 상태를 새로고침하고 **휴대폰 테스트 알림 보내기**를 누릅니다. 휴대폰 브라우저 화면을 닫고 잠근 상태에서도 실제 도착하는지 확인하세요. PC의 ‘푸시 서버 접수 완료’는 휴대폰 표시 완료를 뜻하지 않습니다.

휴대폰 연결용 QR은 관리자 본인 등록을 위한 별도 QR입니다. **기존 작업자 QR·주소·연결키는 변경하지 않습니다.** 휴대폰 1대를 연결하며 다시 연결하면 이전 등록을 교체합니다. 이후 검사 완료·비고 메시지를 PC와 휴대폰에 각각 보냅니다. 이미 있던 기록은 처음 연결 시 소급 전송하지 않습니다. 정상 실행 중 약 5초 간격으로 전송을 확인하고, 일시 실패 시 최대 5분 간격으로 재시도합니다. 새로 시작해도 전송 대기 기록을 확인합니다. 알림 서비스가 접수한 뒤의 보관 시간은 최대 24시간이며 브라우저 정책에 따라 더 짧을 수 있습니다. 중단 시점에 따라 같은 알림이 중복될 수 있습니다.

휴대폰에서 알림을 누르면 이 브라우저에 저장한 최근 100개 소식이 열립니다. 긴 비고는 알림 크기 제한에 맞춰 줄이며 전체 내용은 PC에서 확인할 수 있습니다. 휴대폰에서 내용을 읽어도 PC의 안 읽은 숫자는 별도로 유지됩니다. 브라우저 사이트 데이터를 지우면 휴대폰 보관함도 지워집니다.

프로젝트명·수주번호·작업자·비고를 표준 Web Push 메시지로 암호화해 브라우저 알림 서비스를 통해 전달합니다. 잠금화면에 내용을 표시할지는 휴대폰 설정을 따릅니다. 알림 구독정보·발신키·전송 진행상태는 `%APPDATA%\WanryoTalk\phone-push-v1.dat`에 기존 Windows 계정으로 암호화하여 보관하고, GitHub에는 저장하지 않습니다. 회사 PC에서 브라우저 알림 서비스(삼성 인터넷/Chrome은 일반적으로 FCM)로 HTTPS 전송할 수 있어야 합니다. 허용되지 않은 회사망은 전산 담당자에게 확인하세요.

GitHub Pages에는 `/Tool/phone/` 하위의 연결·수신 페이지와 해당 범위만 제어하는 서비스워커를 추가합니다. 작업자 QR의 루트 페이지·이동 코드·주소는 그대로 유지합니다. 삼성 인터넷 실제 단말·잠금화면과 회사망의 실제 FCM 수신은 이 개발 환경에서 검증하지 못했습니다. Chromium에서 실제 서비스워커·알림 표시·오프라인 보관함을 검증했으며, 구독 생성과 푸시 도착은 테스트용으로 모의 주입했습니다.
