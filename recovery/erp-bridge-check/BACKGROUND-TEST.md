# ERP 가려진 창 내보내기 시험 v0.3

목표는 **ERP가 다른 창 뒤에 가려진 상태에서 Excel 내보내기와 저장을 할 수 있는지** 확인하는 것입니다. 정기 자동 수집이나 서버 작업목록 반영까지 연결한 버전은 아닙니다. PC 1.4.105와 관리자 APK 1.0.11은 그대로 사용합니다.

## 실행 순서

1. ERP의 저장창이 남아 있으면 취소합니다. ERP 창을 펼치고 **구매관리 → 발주대비미입고현황 → 거래처 가공사업부 → 검색**한 목록을 열어 둡니다.
2. ZIP을 새 폴더에 풀고 **Alpha-ERP-Background-Test.exe**를 실행합니다.
3. 첫 안내에서 확인을 누른 뒤, ERP의 **Excel 버튼 위에 마우스를 올리고 F8**을 누릅니다. 클릭하지 않습니다. Excel 이외 버튼을 지정하지 마세요.
4. 다음 안내에서 확인을 누르고 **Chrome 등 다른 창으로 ERP의 Excel 버튼을 완전히 가립니다.** ERP의 크기·위치·탭은 바꾸지 마세요.
5. 다른 창을 보고 있는 상태에서 **F9**를 누릅니다. 이후 최대 약 110초 동안 저장창에 입력하지 말고 완료 안내를 기다립니다.
6. 자동으로 열린 결과 폴더에서 **ERP-background-test.json**을 대화에 첨부해 주세요. 정상 저장되면 같은 폴더에 새 XLSX도 있습니다.

위치 지정 중 Esc로 취소할 수 있습니다. 시험 후 저장창이 남아 있으면 직접 취소해 주세요. **최소화와 PC 화면 잠금은 이번 시험 대상이 아닙니다.** 이 시험에서는 ERP를 켜고 해당 목록을 조회해 둬야 합니다. 창이 닫힌 상태에서 데이터를 읽는 DB/API 방식은 아닙니다.

## v0.4 시험과 차이

v0.4는 실제 마우스 클릭과 키보드 입력으로 XLSX 저장에 성공했습니다. 이 시험은 별도 진입점으로 실행하며, ERP를 앞으로 띄우는 API, 실제 마우스 이동·클릭, 전역 키보드 입력과 v0.4 처리로의 전환을 하지 않습니다. ERP가 앞에 나타났을 때 원래 업무 창으로 돌아가는 제한된 요청은 추가했습니다. F8으로 현재 도구 모음 HWND와 내부 좌표를 지정하고, F9 직전에 다른 창에 가려졌는지·창/도구 모음의 크기와 위치가 같은지·ERP 프로세스가 PrimeXAR.exe인지 확인합니다. HWND를 다음 실행에 재사용하지 않습니다.

Excel 버튼이 독립 UIA 버튼으로 노출되지 않았기 때문에, 지정한 도구 모음에 WM_MOUSEMOVE/WM_LBUTTONDOWN/WM_LBUTTONUP 창 메시지 한 세트를 보냅니다. 메시지를 보냈다는 사실만으로 내보내기 성공으로 판정하지 않습니다. 같은 ERP 프로세스의 저장창이 실제로 열리고, Win32로 하단의 파일 이름 Edit1001/1152 및 저장 Button1을 확인해 파일 이름 칸에만 문자 메시지를 보내 새 전체 경로를 입력한 뒤, 다시 읽은 값이 정확히 일치하면 해당 저장창에 저장 명령을 전달합니다. 컨트롤을 찾지 못했고 입력도 하지 않은 경우에만 UI Automation으로 재시도합니다. 실제로 새 파일이 만들어지고, 새 XLSX의 통합문서/워크시트 구조와 압축 파일 내용 검증까지 통과해야 `success: true`입니다. 실패하면 실제 마우스/키보드로 전환하지 않습니다. 다른 폴더를 탐색하거나 ERP 기존 파일을 찾아 읽지 않습니다.

**ERP나 Windows 저장창 자체가 앞으로 나타날 가능성은 있습니다.** 도구가 명시적으로 창을 활성화하지 않는 것과 실제로 전혀 방해받지 않는 것은 다릅니다. 결과에는 실행 전 가려짐, 50ms 간격으로 관찰한 앞쪽 창 변경 횟수·ERP/자식 창 표본 수, 실행 끝에 원래 다른 창이 앞에 남았는지를 기록합니다. 창 이름·다른 프로그램 이름·표 내용·입력값은 보고서에 기록하지 않습니다. 50ms보다 짧은 변화까지 없었다는 보장은 하지 않습니다.

새 저장 폴더는 EXE 옆에 만들고 권한이 없으면 임시 폴더에 만듭니다. JSON/XLSX는 로컬에만 저장합니다. 발주/입고 등록·수정, ERP 조회 조건 변경, DB 접속 또는 자동 업로드를 하지 않습니다. 사용자 지정 Excel 위치를 잘못 선택하지 않도록 주의해 주세요.

## 검증과 남은 확인

도구 모음/좌표 제한, 변경된 크기·위치 거부, 기존 XLSX/JSON/파일 보존 시험, 배경 실행 경로의 전역 입력·ERP 활성화 금지 검사, 업무 창 복귀 PID 조건 검사, Linux/Windows vet, Windows x64 교차 빌드와 소스 ZIP 재빌드 일치를 확인합니다. 실제 Windows/PrimeERP의 가려진 창 메시지 처리와 UIA 저장 지원 여부는 사용자의 현장 JSON으로 확인해야 합니다. 지원된다고 미리 확정하지 않습니다.

## v0.2 수정과 해석

v0.1 현장 결과는 `covered_at_start: true`, `save_dialog_found: true`였지만 UIA에서 파일명/저장 버튼 후보가 모두 0개였습니다. ERP 자식 창이 앞에 나타났으며 XLSX 저장은 실패했습니다.

v0.2는 저장창이 준비될 시간을 주고 Win32 컨트롤을 먼저 찾습니다. WM_SETTEXT로 화면 글자만 바꾸지 않고, 파일명 입력칸의 선택 영역에 **WM_CHAR** 메시지를 직접 전달해 일반 편집 변경 처리를 유도합니다. 이 메시지는 검증한 입력칸만 대상으로 하며 사용자가 보고 있는 다른 프로그램에 타이핑하지 않습니다. 정확히 일치하는 경로를 확인한 뒤 저장창의 식별된 저장 버튼 명령을 요청합니다. 문자 전달 실패나 값 불일치 때는 저장하지 않습니다.

ERP가 포커스를 가져간 경우, F9 직전에 캡처한 업무 창이 여전히 존재하고 최소화되지 않았으며 ERP/이 도구의 창이 아닌지 확인합니다. 현재 다른 업무 앱이 앞에 있으면 건드리지 않습니다. 조건을 만족할 때만 원래 업무 창으로 복귀를 요청하고 횟수/성공 여부를 기록합니다. Windows가 거부하면 키보드 입력이나 강제 스레드 연결로 우회하지 않습니다. 이 요청 자체가 ERP 저장창이 잠깐 나타나는 현상을 없앤다고 보장하지 않습니다.

`success: true`는 새 XLSX가 검증됐다는 뜻입니다. `foreground_restore_attempts`/`foreground_restore_successes`는 업무 창 복귀 시도/확인 수이고, `foreground_preserved_at_end`는 끝에 원래 창이 앞에 있었는지를 뜻합니다. 같은 앱 안에서 새 엑셀 문서 탭이 열리는 것까지 관찰하지는 않으므로 실제 업무 방해 여부는 사용자가 본 화면과 함께 확인해야 합니다. 정기 자동 수집으로 운영하기 전 실제 저장과 방해 여부를 검증해야 합니다.

전체 소스는 ZIP의 `source/`에 있습니다. 빌드: `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags="-s -w -X main.operation=background" -o Alpha-ERP-Background-Test.exe .`

## v0.3 · ERP가 자동으로 여는 엑셀 처리

v0.2 현장 시험에서는 가려진 ERP의 새 XLSX 저장이 성공했지만, ERP가 엑셀을 자동 실행하면서 앞으로 표시했습니다. v0.3은 실행 중인 Microsoft Excel에 연결해 **이번 시험의 새 전체 경로와 정확히 일치하는 통합문서만** 닫습니다. 다른 엑셀 문서와 Excel 프로그램 자체는 닫지 않습니다. 시험 중 자동으로 열린 새 문서는 수정하지 마세요. 저장되지 않은 변경이 있으면 해당 문서도 열어 둡니다. COM 연결이 안 되거나 확인이 실패하면 강제로 닫지 않고 JSON에 결과를 남깁니다.

대상 문서가 앞에 있었고 닫기가 확인된 뒤에도 Excel이 앞에 있으면 원래 업무 창으로 복귀를 요청합니다. 다른 앱으로 전환한 경우에는 건드리지 않습니다. 엑셀 창이 잠깐 뜨는 것까지 막는 방식은 아닙니다. `export_excel_cleanup.close_verified`는 대상 문서 닫기 확인, `export_excel_work_restore_confirmed`는 업무 창 복귀 확인입니다. `success`는 XLSX 저장 검증 결과이며 닫기 성공과 구분합니다. 실제 Microsoft Excel/ERP 동작은 현장 시험이 필요합니다.
