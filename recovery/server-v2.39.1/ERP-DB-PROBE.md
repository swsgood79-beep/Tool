# 1.4.111 수정

config_read/config_invalid 결과는 접속 전 설정 해석 실패입니다. SQL 접속 차단이나 비밀번호 오류로 확정할 수 없습니다. PowerShell의 SqlConnectionStringBuilder 사전/속성 접근 충돌을 피하도록 CLR getter/setter로 처리하며, config_parse/connection_options 단계와 고정 config_reason을 추가했습니다. 실제 값·오류 원문은 계속 제외합니다. 업데이트 후 같은 버튼으로 다시 진단합니다. 회사 ERP 설정 파일은 변경하지 않습니다. 실제 Windows SQL 접속은 현장 재확인 전입니다.

# DB 연결 확인 · PC 1.4.110

이 기능은 **회사 Windows PC에서 실행하는 연결·구조 진단**입니다. 현재 ERP 화면 수집을 DB 자동 수집으로 바꾼 기능은 아닙니다. 실제 연결 결과와 자료 구조를 확인한 다음 필요한 발주·입고 조회를 설계합니다.

## 사용

1. PC 프로그램을 1.4.110로 업데이트합니다.
2. 대표 관리자 → 전체 → 가공 작업 · 입고 확인 → ERP 자동 연결에서 **DB 연결 확인**을 누릅니다.
3. ERP 설치 폴더는 우선 비워 둡니다. 실행 중인 PrimeXAR의 설치 폴더를 찾고, 없으면 알려진 기본 설치 폴더를 확인합니다. ERP 화면 크기·탭·최소화 여부와 관계없이 진단합니다.
4. 자동으로 찾지 못하면 ERP 아이콘의 파일 위치 열기로 확인한 설치 폴더만 입력합니다. 계정이나 비밀번호는 입력하지 않습니다. 네트워크 공유 경로나 임의 연결 문자열은 받지 않습니다.
5. 완료되면 **진단 결과 받기 · ERP-db-check.json**으로 결과를 내려받습니다. 실패해도 결과 파일의 단계와 오류 코드로 원인을 좁힐 수 있습니다.

진단은 한 번에 하나만 실행하고 최대 약 45초로 제한합니다. 회사 내부망에서 DB 접속 자체가 가능한지는 이 버튼을 실행해야 확인할 수 있습니다. 외부 개발 환경에서는 내부 DB에 접속하지 않았습니다.

## DB 연결 확인 버튼의 조회 범위와 정보 보호

아래 범위는 구조 진단 버튼에 한합니다. 1.4.112의 별도 발주 미리보기는 실제 가공사업부 발주 항목을 반환하며 ERP-DB-PREVIEW.md를 참고합니다.

기존 ERP 폴더 `ini/DB_Information` 또는 `DB_Information.ini`의 주석 처리되지 않은 DatabasePath 한 개만 읽습니다. Login_Info는 읽지 않습니다. 접속 값은 회사 PC의 진단 프로세스 메모리에서만 사용하며 명령줄·결과·로그·설정 저장에 복사하지 않습니다. 실제 비밀번호를 업로드할 필요가 없습니다.

SQL Server 시스템 카탈로그의 테이블·뷰·열·형식·기본 키 여부·외래 키 관계만 SELECT합니다. 업무 테이블의 행, 수주·금액·직원 자료, 뷰/프로시저 정의나 로그인 목록은 조회하지 않습니다. INSERT/UPDATE/DELETE, 권한 변경, 계정 생성, 프로시저 실행을 하지 않습니다. 현재 ERP 계정을 사용하는 것이며 ApplicationIntent=ReadOnly만으로 계정 권한이 바뀌지는 않습니다. 파일 자동 첨부(UserInstance/AttachDBFilename) 연결은 거부합니다.

접속은 암호화를 요청하고 사내 SQL Server의 자체 서명 인증서 호환을 위해 인증서 신뢰 옵션을 사용합니다. 암호화를 끄는 자동 재시도는 하지 않습니다. 연결 8초, 각 구조 조회 12초, 열 20,000개·관계 5,000개 한도입니다. 넘치면 결과에 truncated를 표시합니다. 원본 오류 문구 대신 정해진 상태와 숫자 오류 코드만 반환합니다.

결과는 프로그램 메모리에 보관하고 대표 관리자에게만 내려받기를 제공합니다. 자동 외부 업로드하지 않습니다. 결과에는 서버 주소·DB 계정·비밀번호·INI 원문·설치 경로를 넣지 않습니다. 프로그램 종료 시 결과는 지워지므로 필요한 결과는 직접 내려받습니다. 종료 시 진단 프로세스도 소유 작업 단위로 정리합니다.

## 최근 ERP 목록에서 제외된 품목

이전에는 있었지만 최근 엑셀에서 찾지 못한 품목을 일반 작업 카드와 분리해 페이지 아래에 표시합니다. 동일 수주 안에 정상/제외 품목이 섞여 있어도 각각의 목록과 팝업에는 해당 품목만 표시합니다. 검색과 작업 상태 필터는 두 목록에 적용하며 전체 수량/상태 집계는 둘을 포함합니다.

목록 제외는 가공 완료·취소·삭제의 뜻이 아닙니다. 조회 날짜·조건 변경이나 ERP 입고 처리 등으로 보고서에서 빠졌을 수 있습니다. 작업자·관리자 모두 아래 목록에서 기존 작업을 확인할 수 있고 작업 기록·수량은 유지합니다. 실제 작업 진행과 관리자 확인 규칙은 그대로 적용합니다.

## 검증

대표 관리자/CSRF/중복 진단 제한, 결과에 예상하지 않은 비밀 필드 제외, 고정 시스템 카탈로그 SELECT 검사, 정상/제외 혼합 수주의 목록·팝업 분리, 진단 시작/결과 다운로드 브라우저 검증, 전체 Go 회귀와 Windows 교차 빌드 및 소스 재빌드를 확인합니다. 화면의 성공 결과는 시험 자료이며 실제 회사 DB 접속과 Windows PowerShell SQL 실행은 현장 확인 전입니다.

## PC 1.4.120 입고 연동 구조 진단

대표 관리자에게만 별도 버튼을 제공합니다. 기존 INI로 연결해 고정 시스템 카탈로그 SELECT만 실행합니다. 프로시저 이름/매개변수, 입고 관련 트리거/뷰/함수와 의존 관계, 지정 입고/발주/재고 테이블의 키/인덱스/identity/default 존재 여부만 수집합니다. 프로시저/트리거 본문, 기본값 식, 업무 행, ERP 사용자/권한 행, 비밀번호/접속 문자열은 수집하지 않습니다. 이 진단으로 ERP 로그인 권한이나 담당자 연결이 검증되는 것은 아닙니다. 정의 열은 본문 조회 가능 여부를 나타내는 boolean으로만 반환합니다.

POST mode=receipt는 기존 대표 관리자/CSRF/중복 실행/45초 제한을 사용합니다. SQL은 최대5000행, 전체 출력8MiB 제한이며 결과 잘림과 DB VIEW DEFINITION 권한 제한을 화면에 표시합니다. 권한 제한으로 목록이 비어도 모듈이 없다는 증거가 아닙니다. ERP 프로그램 내부 동적 SQL, 전표번호 규칙, 실제 입고 동작의 동등성은 추가 분석 대상입니다. 저장 프로시저 실행이나 운영 DB 변경은 없습니다. 다운로드 이름은 ERP-receipt-check.json이며 메모리 결과는 재시작 시 지워지고 자동 업로드하지 않습니다.
