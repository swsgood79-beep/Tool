서버 PC의 프로그램을 완전히 종료하고 새 EXE를 실행한 뒤 관리자/공용 화면도 새로고침하세요. 브라우저 음성을 쓰면 해당 화면의 음성 알림을 다시 켭니다. 음성 자체는 인터넷·제공사 준비 시간이 남을 수 있습니다.

**v1.4.16 현재 음성 사용법:** 서버 PC에서 기존 프로그램을 완전히 종료한 뒤 새 EXE를 실행하세요. 관리자/공용 화면을 새로고침하고 ‘🔊 음성 알림 켜기’ 또는 ‘🔊 공용 PC 음성 알림 켜기’ → 미리듣기를 누르세요. Python 설치/별도 API 키는 필요 없습니다. 첫 음성은 포함된 런타임을 준비하느라 조금 더 걸릴 수 있습니다. gTTS 합성에는 서버 PC 인터넷 연결이 필요합니다.

현재는 음성 설정에서 gTTS·선희·인준·SAPI를 선택합니다. 기본은 gTTS(lang=ko, slow=False)입니다. 아래 이전 버전의 SAPI/Google·SunHi·Heami 선택 설명은 현재 사용하지 않습니다.

이 배포본은 복구 운영판입니다. 기존 프로그램의 독립 재구현이며 원본과 100% 동일성을 인증한 것은 아닙니다. Windows 실기기·회사 계정 연동의 최종 확인은 아래 순서대로 해 주세요.

## 1. 실행 전 준비

1. 원래 회사 PC의 **같은 Windows 계정**으로 실행합니다.
2. 기존 알파 프로그램을 **트레이에서 완전히 종료**합니다. X 버튼으로 숨기는 것과 다릅니다. 테스트판도 종료하면 화면 혼동을 피할 수 있습니다.
3. `%AppData%\WanryoTalk` 전체와 기존 Documents의 완료 엑셀을 별도 드라이브/폴더에 복사해 보관합니다. 원본 프로그램과 원본 자료를 삭제하지 않습니다.
4. ZIP을 **새 폴더**에 풉니다. 기존 프로그램 폴더에 덮어쓰지 않습니다. 새 실행 파일 이름은 `AlphaWorkComplete-Recovered.exe`입니다.

## 2. EXE 하나로 실행 (권장)

`AlphaWorkComplete-Recovered.exe`를 더블클릭합니다. .cmd를 고를 필요가 없습니다.

- 기존 v1.4 운영 자료가 있으면 그대로 이어서 엽니다. 새로 가져오거나 덮어쓰지 않습니다.
- 첫 실행 선택창에서 **예 = 기존 WanryoTalk 자료**, **아니요 = 테스트판 업무 자료**입니다. 테스트 자료가 없으면 아니요도 취소입니다. 원본은 보존됩니다.
- 기존 자료가 없는 PC는 빈 자료로 시작할지 묻습니다. 원래 자료를 가져오려던 경우에는 취소하고 원래 PC의 계정을 확인하세요.
- 이후 실행·업데이트도 같은 EXE만 실행합니다.

아래 .cmd는 호환/자동화용이며 일반 실행에는 필요 없습니다.

### 명령 파일로 직접 선택하는 경우

**권장: 원래 운영 프로그램의 최신 자료로 시작**

- `start-production.cmd` 실행.
- 첫 실행에만 `%AppData%\WanryoTalk`를 새 운영 폴더로 복사합니다. 원본은 읽기만 합니다.
- 다음 실행부터는 이미 만들어진 운영 자료를 이어서 엽니다. 매번 원본을 다시 복사하지 않습니다.

**테스트판에서 수정한 수주·기록을 그대로 운영에 쓰려면**

- 아직 운영판을 한 번도 시작하지 않은 상태에서 `promote-test-to-production.cmd` 실행.
- 현재 선택된 테스트 복사본의 업무 자료를 새 운영 자료로 복사합니다. 접속·휴대폰·패스키·시세·일정·백업 설정과 관리자 비밀번호/기존 QR 키는 원래 WanryoTalk에서 가져옵니다. 테스트용으로 초기화된 연동 설정을 그대로 운영에 쓰지 않습니다.
- 기존 운영 자료와 테스트 자료의 업무 내용을 자동 병합하지 않습니다. 선택한 테스트 자료가 기준이 됩니다. 원본 프로그램과 테스트 프로그램의 폴더는 수정하지 않습니다.
- 이미 운영 자료가 있으면 다시 전환하거나 빈 자료로 덮어쓰는 동작을 거부합니다.

운영 폴더는 `%AppData%\AlphaWorkCompleteRecovered`이며 그 안의 선택된 `copies\copy-날짜-고유번호`에 실제 파일이 있습니다. 관리자 주소는 `http://127.0.0.1:18791/`입니다. 기존 원본 프로그램과 운영판은 같은 Windows 단일 실행 뮤텍스를 사용하여 동시 실행을 막습니다.

## 3. 현장 사용 전에 확인

- 관리 창의 ‘수주 · 메시지 관리’를 엽니다. 로그인창이 나오면 기존 관리자 비밀번호를 사용합니다. 비밀번호가 없으면 새 비밀번호를 설정합니다.
- 실제 수주번호 몇 건, 설계담당자, 업체 특이사항과 사진을 확인합니다.
- 일반 목록은 과거 완료 수주를 숨기므로, 과거 기록은 엑셀 내려받기와 수주번호 직접 조회로 확인합니다. ‘금일 검사 완료’는 오늘 출하검사까지 최종 승인한 수주입니다.
- 시험용 수주 1건으로 작업자 신청 → 관리자 알림/목록 → 관리자 완료 → 다음 단계 → 엑셀 저장을 확인한 뒤 현장에 안내합니다.
- 엑셀 사본을 사용하려면 설정 → 엑셀 저장 설정에서 파일을 연결하고 ‘현재 파일로 연결 다시 검사’를 누릅니다. **엑셀만 올려도 수주/완료 상태가 복원되는 기능은 아닙니다.** 업무 상태는 2번의 데이터 복사에서 가져옵니다.
- 이후에는 `start-production.cmd` 또는 EXE로만 운영합니다. 예전 프로그램을 다시 켜서 접수하지 마세요. 예전 자료와 새 운영 자료는 자동 동기화되지 않습니다.

## 4. 휴대폰·노트북 연결

1. 설정 → 고정 QR 설정에서 기존 GitHub 연결 설정을 확인합니다. 기존 값을 읽어오지만 비어 있거나 만료됐다면 다시 입력합니다. GitHub Pages + Cloudflare 방식을 지원합니다. ngrok 실행은 지원하지 않습니다.
2. 저장된 설정이 준비돼 있으면 실행 시 인터넷 연결을 시작합니다. 연결되지 않으면 관리 창의 ‘인터넷 연결’을 누르고 연결 상태를 확인합니다.
3. 현재 PC의 준비 상태를 확인한 뒤에만 고정 접속 포인터가 게시됩니다. 기존 QR 키는 원래 자료에서 유지하므로 기존 QR/바로가기를 먼저 시험합니다. 실제 휴대폰에서 작업자 화면이 열리는지 확인합니다.
4. ‘내 휴대폰 알림’에서 연결 상태 확인 후 시험 메시지를 보냅니다. 기존 구독이 만료됐으면 다시 연결합니다. 삼성 인터넷의 사이트 알림 권한/휴대폰 알림 설정을 확인합니다.
5. 휴대폰 관리자 접속을 켜고 고정 관리자 바로가기에서 비밀번호/지문 로그인을 확인합니다. 실제 검사 신청 알림의 ‘확인’을 눌러 해당 수주 검사 화면으로 가는지도 확인합니다.
6. 다른 노트북에는 관리 화면에 표시되는 **고정 작업자 주소**를 북마크합니다. 잠깐 사용되는 trycloudflare 주소를 직접 북마크하지 않습니다.

회사 PC의 프로그램이 종료되거나 PC가 꺼짐/절전 상태면 원격 접속과 알림도 중단됩니다. 홈 화면 아이콘은 서버가 계속 켜져 있는 것과 별개입니다.

## 5. 시세·납기·백업 확인

- 시장 정보 설정에서 코스피/코스닥/코인/환율 조회 상태를 확인합니다. 토스 허용 IP에는 API를 호출하는 회사 PC의 공인 IP가 필요합니다. 키가 만료됐거나 IP가 바뀌면 설정을 갱신합니다. 값과 기준시각을 실제 시세와 비교합니다. 초단위 체결 WebSocket 서비스가 아니라 주기적 조회입니다.
- 일정 설정에서 OneDrive 공유 URL 또는 로컬 파일 경로를 확인하고 ‘조립일정’의 발송예정일이 실제 수주에 매칭되는지 확인합니다. 미정/ASAP는 날짜 없는 일정이며 충돌한 날짜는 기존 값을 유지합니다.
- GitHub 백업 설정에서 **복구키 파일을 내려받아 PC 밖에도 보관**합니다. 실제 백업 성공 표시와 마지막 백업 시각을 확인합니다. 코드/실행 파일이 GitHub에 있다는 사실만으로 회사 데이터가 백업된 것은 아닙니다.
- 백업 상한은 256MB입니다. 초과/실패가 표시되면 성공한 것으로 취급하지 말고 운영 폴더 전체의 별도 복사도 보관하세요. 회사 PC 포맷 전에는 반드시 복구키와 실제 데이터 백업을 확인합니다.

## 6. 새 PC/포맷 후 복원

- 새 Windows 계정에서는 원래 DPAPI 파일을 폴더 복사만으로 열지 못할 수 있습니다.
- 새 PC에서 `start-empty-for-restore.cmd`로 빈 운영 자료를 만들고, 관리자 비밀번호를 설정한 뒤 백업 복원에서 복구키/암호화 백업을 사용합니다.
- 복원이 끝나면 프로그램을 종료 후 다시 실행하고 인터넷 연결과 휴대폰 접속을 확인합니다.
- 이미 운영 자료가 있는 PC에서는 이 명령으로 빈 자료를 덮어쓰지 않습니다.
- 실제 회사 백업으로 새 PC 복원을 이 개발 환경에서 실행 검증한 것은 아닙니다. 포맷 전에 별도 PC/폴더에서 복원 결과를 확인하는 것이 좋습니다.

## 7. 앞으로 업데이트/테스트할 때

- 업데이트는 운영판을 트레이에서 종료 → 새 ZIP을 다른 폴더에 해제 → 새 `start-production.cmd`. 운영 자료는 AppData에 있어 이어서 사용합니다.
- `start-test.cmd`/`continue-test.cmd`는 격리 테스트입니다. `copy-existing-data.cmd`는 운영 전환 후에는 최신 운영 자료를, 운영 전환 전에는 WanryoTalk 원본을 테스트 폴더로 복사합니다. 운영 서비스·키 게시·푸시 전송은 테스트 모드에서 계속 차단합니다.
- 잘못된 수주 처리나 연결 오류가 나오면 운영 폴더를 임의로 지우지 말고 화면의 오류와 버전을 알려 주세요. 예전 프로그램으로 돌아가려면 새 운영 이후 기록의 처리도 함께 정해야 합니다.

## 8. 엑셀 연결 순서

1. 관리 창 → **수주 · 메시지 관리** → 관리자 로그인 → **설정 → 엑셀 저장 설정**.
2. 암호 없는 기존 `.xlsx` 선택 → **복사본 연결 · 기록 합치기** (최대 5MB).
3. 연결된 파일명과 완료/일치 기록 수 확인. 파일 선택 칸이 비어도 위 파일명이 남아 있으면 연결은 저장된 상태입니다.
4. **병합된 엑셀 받기**로 결과를 확인합니다.
5. 이후 완료·수정·취소는 운영 폴더의 `검사완료기록-복구서버.xlsx`에 자동 반영됩니다. PC 관리 창의 **엑셀 폴더**로 위치를 엽니다. Excel이 파일을 잠그면 닫은 뒤 저장 오류가 해소되는지 확인합니다.
6. 처음 선택한 원본은 그대로입니다. 원본을 Excel에서 수정했다면 다시 선택해 연결해야 합니다. 원본 경로와 자동 양방향 동기화하지 않습니다.
7. v1.4에서 이미 연결했다면 업데이트 때 다시 연결하지 않아도 됩니다.

로컬 서버는 실행과 함께 시작합니다. 휴대폰 외부 접속에는 터널이 필요하며 저장된 Pages/Cloudflare 설정으로 자동 연결을 시도합니다. **외부 접속 연결됨**이면 버튼을 다시 누를 필요가 없습니다. 끊기면 **인터넷 연결**로 재시도합니다. 인터넷 끊기는 외부 접속만 끄며 로컬 서버 종료와 다릅니다.

연결 상태는 PC 창 우측 상단의 작은 표시로 확인합니다. 녹색 ‘연결됨’은 터널 확인/주소 게시가 성공한 상태이며, 빨간색 ‘연결 안 됨’은 준비 중/실패/종료 상태입니다. 아래 상세 상태도 함께 확인하세요. 인터넷 도구는 별도 콘솔 창 없이 실행하도록 구성했습니다.

중복 수주 찾기: 이미 등록된 번호는 완료/숨김 상태라도 재사용을 막습니다. 등록 시 중복이면 기존 수주 이름·상태·화면 열기/수정/삭제 확인 버튼을 표시합니다. PC 관리자 로그인 후 http://127.0.0.1:18791/projects/find?number=test 로 test 번호를 직접 찾을 수도 있습니다. 영문 대소문자는 구분하지 않습니다. 삭제는 자동으로 하지 않습니다.

PC 알림: 세팅 신청은 파란색, 출하 신청은 주황색, 통합 신청은 보라색이며 수주번호/프로젝트/신청자를 나눠 표시합니다. 비고가 있으면 별도 행에 표시하고 긴 문구는 공간에 맞춰 줄임표로 표시합니다. ‘검사 신청 확인’으로 원래 검사 화면을 엽니다. 닫기/시간 만료만으로 읽음 처리하지 않으며 안 읽은 알림 숫자로 다시 확인합니다. 검사 완료는 알림을 보내지 않고 기록/엑셀만 보관합니다. 기존 비고 메시지 알림은 노란색으로 유지합니다. PC 창의 ‘알림 미리보기’로 새 레이아웃을 확인하세요.
일반 수주 목록의 전체/세팅/출하는 완료 수주를 제외합니다. 금일 검사 완료는 오늘 출하까지 완료된 수주만 표시하며, 오늘 납기·다음 출고·캘린더에서도 완료 수주는 제외합니다. 날짜별/월간/필터 건수도 미완료 수주 기준입니다. 과거 완료 수주는 중복 안내 또는 수주 번호 직접 조회로 찾습니다. 시험 수주를 삭제하면 같은 번호로 다시 등록할 수 있으며 이전 완료 기록은 보존합니다.

엑셀 폴더 버튼: Windows 탐색기로 현재 선택된 운영 폴더를 엽니다. 검사 기록은 그 안의 `검사완료기록-복구서버.xlsx`입니다. 실패하면 표시되는 오류와 저장 경로를 확인하세요. Windows 키+R에 그 경로를 입력해 열 수도 있습니다. 원본 WanryoTalk 폴더를 여는 버튼이 아닙니다.

작업자 전체 특이사항: 작업자 화면의 수주 검색창 바로 위 ‘업체별 특이사항 전체 보기 → 전체 보기’를 누릅니다. 수주와 연결되지 않은 업체도 표시됩니다. 업체명/내용으로 검색하고 업체 이름을 누르면 글/사진이 펼쳐집니다. 사진을 누르면 크게 열립니다. 관리자 수정 내용은 약3초 간격으로 자동 갱신하며 검색어와 펼친 업체는 유지합니다. 작업자에게는 수정/삭제 권한을 제공하지 않습니다. 관리자 메뉴의 업체 특이사항 관리에 등록된 원본을 조회합니다.

납기표/시장 확인(v1.4.8): 저장된 OneDrive 주소는 다시 입력할 필요 없이 납기표 연결 메뉴의 ‘지금 갱신’을 눌러 확인합니다. 직접 다운로드 → 원본 공유 링크 → API 재시도로 처리하며, 실패 시 어떤 방식이 HTTP 오류/안내 페이지였는지 표시합니다. 다운로드 실패해도 기존 납기와 마지막 성공 시각은 보존합니다. 실제 공유 파일이 서버 다운로드를 허용하는지는 회사 PC에서 확인해야 합니다. 시장 설정의 연결 확인은 같은 캐시 시세를 표시합니다. 정상은 초록색, 일부 실패/이전 값 유지는 주황색, 조회 실패는 빨간색이며 마지막 확인 시각과 항목별 상태를 표시합니다. 새 외부 조회를 강제로 늘리는 버튼은 아닙니다. v1.4.7의 작업자 업체 전체 조회 버튼도 포함됩니다.

사급품(v1.4.9): ‘조립일정’ 시트 N열의 ‘사급 관련’ 내용을 수주번호로 연결합니다. 기존 납기표 연결 설정 그대로 ‘지금 갱신’ 또는 자동 갱신을 사용합니다. 관리자·작업자 수주 카드에서 특이사항 앞에 사급품 내용이 표시되며, 길면 누르면 전체를 봅니다. 검사 화면·특이사항 상세·금일 완료·미완료 출고 캘린더에도 표시됩니다. N열이 빈 칸이면 표시를 없애고, N열 헤더를 못 찾거나 해당 번호가 원본에 없거나 다운로드가 실패하면 기존 사급품 내용을 보존합니다. 같은 수주번호가 여러 행이면 처음 나오는 행의 N셀만 사용합니다. 셀 안에 줄바꿈이 있어도 첫 줄만 표시하며 첫 행/첫 줄이 빈칸이면 나중 내용은 가져오지 않습니다. 버튼 배경색은 해당 셀의 채우기 색과 현재 문구별 조건부 서식을 반영합니다. 글자색은 대비에 맞춰 자동 조정합니다. N열의 병합 셀은 실제 병합 범위만 적용합니다. 기존 수주별 특이사항·업체 원본 내용은 덮어쓰지 않습니다. 납기표 원본에 값을 쓰는 기능이 아닙니다.

소스 보관과 업무 자료는 별개입니다. 버전별 소스 ZIP/실행 ZIP/커밋을 GitHub 복구 브랜치에 보존합니다. 별도 데이터 백업 성공과 복구키 보관도 확인하세요. 소스 ZIP에는 회사 수주·사진·API 키가 포함되지 않습니다.

v1.4.10 업데이트 후 납기표 ‘지금 갱신’을 누르면 첫 행/첫 줄과 색상을 다시 읽습니다. 조회에 실패하면 기존 저장 값을 유지하되 화면에서는 첫 줄만 표시합니다. 직접 지정한 단색/테마 색(tint 포함)과 현재 시트의 문자열 일치 조건부 채우기 색을 지원합니다. 임의의 Excel 수식 조건부 서식 전체를 계산하는 기능은 아닙니다. 추가 파일 다운로드는 하지 않습니다.

v1.4.11: 사급품 버튼 앞의 고정 ‘사급품’ 제목을 제거했습니다. 원본 셀 첫 줄만 그대로 표시하며 셀 내용 자체의 ‘사급품’ 단어는 삭제하지 않습니다. 색상과 전체 내용 열기는 유지합니다. 관리자/작업자 화면을 새로고침해 주세요.

v1.4.12 반려: PC 알림은 그대로입니다. 휴대폰 검사 신청 알림의 확인은 관리자 검사 화면으로 이동하는 용도이며, 로그인이 필요할 수 있습니다. 실제 승인은 그 화면의 ‘세팅검사 완료/출하검사 완료/세팅·출하 모두 완료’로 처리합니다. 새 반려 버튼을 누르면 작업자가 다시 신청해야 합니다. 출하만 반려하면 이미 승인한 세팅은 유지합니다. 통합 반려는 두 단계 모두 다시 신청합니다. 반려 이력은 남지만 완료 엑셀/완료 건수에는 포함하지 않습니다. 기존 특이사항/사급품/납기/사진은 보존합니다. 반려 후 작업자 카드와 신청창에 안내가 표시되고 새 신청 시 사라집니다. 이전 화면의 승인/반려/신청을 다시 보내도 현재 신청을 잘못 처리하지 않도록 요청 ID와 새 신청 토큰을 검증합니다. PC 알림에 반려 버튼을 추가한 버전은 아닙니다.


## Windows 기본 음성 알림 (v1.4.13에서 추가, 웹 음성 선택은 아래 v1.4.14 참고)

운영 PC에서 프로그램을 켜 두면 새 검사 신청에 띵똥 소리 후 “홍길동님이 알파 작업 확인의 세팅 및 출하 통합검사를 신청했습니다.”처럼 읽습니다. 비고 알림은 작성자와 메시지를 읽고 수주번호/완료 알림은 읽지 않습니다. 휴대폰 알림에는 음성 기능을 추가하지 않았습니다.

1. 기존 프로그램을 트레이에서 완전히 종료한 뒤 새 EXE를 실행합니다. 기존 운영 자료를 계속 사용합니다.
2. 프로그램 창에서 ‘음성 미리듣기’를 누르고 PC 스피커 볼륨/출력 장치를 확인합니다. 기본 음성 알림은 켜짐입니다.
3. ‘음성 알림 켜짐’을 누르면 꺼지고, 다시 누르면 켜집니다. 이 설정은 재시작 후에도 유지합니다. 끄면 현재 음성과 대기를 취소하며 그동안의 신청을 나중에 몰아서 읽지 않습니다.
4. Windows에 한국어 음성이 없으면 ‘설정 → 시간 및 언어 → 음성’에서 한국어 음성을 추가한 뒤 다시 미리듣기를 누르세요. 기본 한국어 여성 음성을 우선 사용하며 유튜브 채널의 특정 상용 목소리와 같지는 않습니다. 회사 보안 정책에서 PowerShell/음성 기능을 제한하면 음성 실패가 표시될 수 있습니다.

여러 신청은 순서대로 읽고 중복 조회/알림 다시 보기/프로그램 재실행 때 기존 신청을 반복해서 읽지 않습니다. 처음 실행 시 남아 있던 미확인 신청은 기존처럼 팝업으로 확인합니다. 격리 테스트 모드에서는 실제 신청 자동 음성은 끄며 미리듣기만 수동으로 사용할 수 있습니다. 음성 처리는 별도 작업에서 수행해 서버/창 처리를 막지 않습니다. 외부 TTS 서버로 프로젝트명/신청자를 전송하지 않습니다. 한국어 음성이 없거나 재생에 실패해도 검사 신청/알림 화면은 그대로 유지됩니다.

실제 Windows PC의 목소리/스피커 출력과 회사 보안 정책은 개발 환경에서 확인하지 못했습니다.


## 전자녀 스타일 웹 음성 (v1.4.14, 현재 권장)

1. 기존 프로그램을 트레이에서 완전히 종료하고 새 EXE를 실행합니다. 자료 폴더나 QR을 다시 만들 필요는 없습니다.
2. Windows 창의 ‘수주 · 메시지 관리’로 관리자 웹 화면을 엽니다. Chrome 또는 Edge에서 사용하세요.
3. 상단 ‘🔊 전자녀 알람 켜기’를 직접 누르면 음성 안내가 나오고 브라우저 오디오를 활성화합니다. 페이지를 새로 열거나 이동하면 다시 눌러 주세요. 브라우저 정책/장치 설정에 따라 재생이 제한될 수 있습니다.
4. 옆의 미리듣기로 “홍길동님이 알파 작업 확인의 세팅 및 출하 통합검사를 신청했습니다.”를 확인합니다. 실제 신규 검사 신청·비고는 띵똥 후 순서대로 읽습니다. 켜기 전 미확인 신청은 몰아서 읽지 않습니다. 검사 완료 알림은 추가하지 않습니다.
5. 끄기를 누르면 현재 음성과 대기를 취소합니다. 회사 PC의 로컬 관리자 화면에서 웹 음성을 처음 켜면 기존 기본 음성은 꺼짐으로 저장됩니다. 웹 음성을 끄거나 페이지를 닫아도 기본 음성을 자동으로 켜지 않습니다. 기본 음성으로 돌아가려면 웹 음성을 끈 뒤 Windows 창의 음성 알림 버튼을 직접 켜세요. 휴대폰/외부 주소에서 웹 음성을 켜는 것은 회사 PC 기본 음성 설정에 영향을 주지 않습니다.

음성 우선순위는 Google 한국의, Microsoft SunHi Online (Natural), Microsoft Heami, 그 외 한국어입니다. 브라우저/Windows에 등록된 음성만 선택할 수 있고 매번 문장을 읽을 때 최신 음성 목록을 확인합니다. rate=1.1, pitch=1.0, lang=ko-KR을 고정합니다. 선택된 목소리는 버튼 옆에 표시합니다. 위플랩 자체 음성을 가져오거나 동일한 음질을 보장하는 기능은 아닙니다. 서버가 유료 TTS API를 호출하지 않으며 Python/edge-tts 설치도 필요하지 않습니다. 온라인 음성은 브라우저가 제공사에 텍스트를 전달해 합성할 수 있으므로 오프라인 재생을 보장하지 않습니다.

같은 PC의 로컬 관리자 창은 한 창만 읽으며 다른 창에는 대기 안내가 뜹니다. 이전 창에서 끄거나 닫으면 다른 활성 창이 약 3~9초 안에 연결을 이어받습니다. 신청/비고의 읽음·승인·반려·완료 기록은 음성 재생만으로 바뀌지 않습니다. 매우 긴 비고는 음성만 300자까지 읽고 나머지는 화면 확인을 안내합니다. 브라우저가 백그라운드에서 중지되거나 휴대폰 화면이 잠기면 음성이 멈출 수 있습니다. 창의 상태가 오류로 바뀌면 알림 목록을 직접 확인해 주세요.

자동 검증은 합성 알림/모의 음성 엔진으로 속도·음높이·음성 선택·순서·취소·중복 방지와 서버 접근 권한을 확인합니다. 실제 회사 PC의 Google/SunHi/Heami 설치 여부와 들리는 목소리는 미리듣기로 확인해야 합니다.


## 회사 공용 컴퓨터에서 신청 음성 듣기 (v1.4.15)

1. 서버가 실행되는 회사 PC에서 기존 프로그램을 트레이까지 완전히 종료하고 새 EXE를 실행합니다.
2. 공용 컴퓨터/노트북에서는 기존 작업자 접속 주소를 열고 새로고침합니다. 이 컴퓨터에 EXE 설치나 관리자 로그인은 필요 없습니다.
3. 화면 상단의 ‘🔊 공용 PC 신청 알림 켜기’를 누르고 옆의 미리듣기로 스피커를 확인합니다. 페이지를 열어 둔 상태로 사용하세요. 새로 열거나 페이지를 이동한 뒤에는 다시 눌러야 합니다.
4. 다른 작업자가 휴대폰으로 검사 신청하면 공용 컴퓨터에서 띵똥 후 “홍길동님이 프로젝트의 세팅검사를 신청했습니다.”처럼 읽습니다. 통합검사는 한 번만 읽으며 여러 신청은 순서대로 읽습니다.
5. 중단하려면 ‘끄기’를 누릅니다. 기본 상태는 꺼짐이어서 작업자들의 휴대폰에서 저절로 소리가 나지는 않습니다. 원하는 장치에서만 켜세요.

공용 화면은 새 검사 신청만 읽습니다. 작업자가 ‘관리자에게 보내기’로 보낸 비고는 공용 화면에 전달하지 않으며 기존 관리자 음성에서만 읽습니다. 완료/반려 알림은 추가하지 않습니다. 숨김/삭제된 수주는 공용 음성에서 제외합니다. 켜기 이전 신청은 몰아서 읽지 않으며 관리자가 먼저 알림을 읽어도 새 신청이 여전히 검사 대기 중이면 공용 화면에서 받을 수 있습니다.

관리자 PC와 별도 공용 컴퓨터의 음성은 각각 켤 수 있습니다. 공용 화면은 관리자 기본 음성 켜짐 설정이나 검사·읽음 기록을 바꾸지 않습니다. 서버 PC 자체의 로컬 작업자 창에서 음성을 켜면 같은 PC의 다른 음성과 중복되지 않게 그 창이 활성인 동안 재생을 조정합니다. 같은 브라우저 여러 창에서는 한 창만 읽습니다.

음성 우선순위와 속도/음높이는 v1.4.14와 동일합니다. 실제 목소리는 공용 컴퓨터 브라우저에 따라 다릅니다. PC 절전/브라우저 중지/화면 잠금으로 음성이 멈출 수 있으니 현장 공용 PC를 사용 중에는 절전되지 않게 설정하세요. 테스트는 모의 음성 엔진으로 검증했고 실제 스피커 출력은 미리듣기로 확인해야 합니다.


## gTTS 음성으로 통일 (v1.4.16)

- 서버 PC에 포함된 Python 3.12.10, gTTS 2.5.4, pygame 2.6.1을 사용합니다. 별도로 Python/pip을 설치할 필요가 없습니다. 런타임은 %LocalAppData%\AlphaWorkCompleteRecovered\gtts-runtime에 체크섬을 확인해 준비합니다. 회사 수주 자료 폴더를 변경하지 않습니다.
- Google에서 만든 MP3를 관리자 PC/휴대폰/공용 작업자 화면에 전달합니다. 특정 장치의 Windows/브라우저 목소리로 대체하지 않습니다. 관리자 음성은 기존 신청·비고, 공용 화면은 신청만 읽습니다. 완료 알림은 추가하지 않습니다.
- 브라우저 재생은 실제 playbackRate=1.1이며 음높이 보존을 켭니다. Windows 직접 재생은 pygame.mixer.init(frequency=26400, size=-16, channels=1)에서 디코딩한 뒤 별도 시간 조정으로 1.1배속을 만듭니다. 26400Hz 설정만으로 배속이 생기는 것이 아니며, 크롬 내장 음성과 완전히 동일한 톤/운율이라고 보장하지 않습니다.
- 임시 MP3는 재생/전달 후 삭제하며 오류 때도 정리합니다. 끄면 대기와 현재 음성을 중단하고 생성 요청/자식 프로세스도 취소합니다. 네트워크/스피커 오류는 화면에 표시하고 다음 신청 처리는 계속합니다. 생성 중에도 검사 신청/수주 화면은 사용할 수 있습니다.
- Google 음성 합성 시 메시지 내용이 Google로 전송됩니다. 인터넷이 끊기면 음성은 실패할 수 있지만 검사 신청·관리자 승인·화면 알림은 계속 동작합니다. 오프라인 대체 목소리는 사용하지 않습니다. 온라인 미리듣기가 실패하면 서버 PC의 인터넷/보안 정책/Google 접속과 스피커를 확인하세요.
- 테스트는 모의 합성 응답, 실제 pygame MP3 디코딩/더미 오디오, 1.1배 길이·음높이 보존, 큐/오류/임시 파일 정리, 서버/브라우저 계약과 Windows 교차 빌드로 검증합니다. 개발 환경에서 Google 접속이 403으로 차단되어 실제 gTTS 합성 음색과 Windows 스피커 출력은 확인하지 못했습니다.

실행 파일이 이전보다 커진 이유는 Python/음성 라이브러리를 포함했기 때문입니다. 기존 실행 ZIP/소스는 삭제하지 않고 새 버전을 함께 보관합니다.


## v1.4.17 설정 사용 순서

1. 기존 프로그램을 트레이에서 완전히 종료하고 새 EXE를 실행합니다.
2. Windows 프로그램 창의 ‘음성 설정·테스트’를 누릅니다. 관리자 설정 메뉴의 같은 항목으로도 열 수 있습니다. 회사 서버 PC에서 변경하는 설정입니다.
3. 체크박스는 PC 직접 알림의 ON/OFF입니다. 브라우저 관리자/공용 화면의 재생은 각 화면에서 별도로 켭니다. 설정이 처음이면 ON이며 이전 OFF 선호는 유지합니다.
4. 목소리와 슬라이더를 변경하면 자동 저장합니다. 배속 숫자가 즉시 바뀌며 tts_config.json과 암호화 백업의 설정 사본에 보관합니다.
5. ‘🔊 테스트 재생’을 누르면 현재 선택을 저장한 뒤 PC의 같은 FIFO 대기열에서 “아리아니 공구14님이 테스트 완료”를 읽습니다. 알림이 OFF여도 수동 테스트는 가능하며, 여러 번 클릭한 테스트는 각각 클릭 당시 목소리·배속을 기억합니다. 이 PC의 다른 웹 화면에서 음성을 읽고 있으면 그 화면의 음성을 끈 뒤 테스트합니다.
6. 실패 시 엔진명과 오류 원인을 확인하세요. 다른 목소리로 자동 변경하지 않습니다. 구글·선희·인준은 인터넷이 필요하고 SAPI는 서버 PC에 설치된 기본 목소리를 사용합니다.

선희는 ko-KR-SunHiNeural, 인준은 ko-KR-InJoonNeural입니다. 배속 1.10은 +10%, 0.90은 -10%로 합성에 전달하고 이후 pygame/브라우저에서 다시 가속하지 않습니다. gTTS는 출력 주파수뿐 아니라 별도 PCM 시간 조정으로 실제 배속을 만듭니다. SAPI는 오프라인 PCM WAV로 생성해 같은 속도 조정을 합니다.

직접 Python 소스를 실행하는 개발자만 아래 설치가 필요합니다. Windows 배포 EXE 사용자는 설치하지 않습니다.

```sh
pip install gTTS pygame edge-tts comtypes
# 고정 버전은 tts_assets/requirements.txt 참고
```

Google/Microsoft 실제 합성 및 Windows COM·스피커 출력은 개발 환경에서 확인하지 못했습니다. 회사 PC에서 테스트 재생으로 확인하세요. 설정/대기열/실패·백업 복원·모의 브라우저·pygame 더미 출력을 검증했습니다.


## 반복 말하기 (v1.4.18)

1. 프로그램 창의 ‘음성 설정·테스트’를 엽니다.
2. ‘반복 말하기’에서 ‘1회 말하기’ 또는 ‘2회 반복’을 고릅니다. 변경 즉시 tts_config.json에 repeat=1 또는 2로 저장됩니다.
3. 테스트 재생으로 확인합니다. 선택한 목소리·배속은 유지하며 테스트 문장도 같은 횟수로 읽습니다.
4. 실제 신청/비고 음성에도 적용됩니다. 공용 화면은 계속 신청만 읽습니다. 두 번 읽기를 마쳐야 다음 음성으로 넘어가며 OFF로 중단할 수 있습니다.

기존 설정에 repeat가 없으면 1회입니다. 2회 선택 때문에 Google/Microsoft 음성 생성을 두 번 호출하지 않습니다. 효과음은 알림 도착 때 한 번 내고 안내만 반복합니다. 같은 순간 여러 신청의 효과음은 한 번으로 합칠 수 있습니다. 음성 합성·스피커 장치의 실제 준비 시간은 남을 수 있지만 생성이 끝날 때까지 효과음을 보류하지 않습니다. 추가 pip 설치는 없습니다.

**중요:** 디자인만 선택해서 미리보는 기능입니다. 별도 시험용 자료가 생기는 것은 아니며, 실제 검사 신청·완료·반려·수주 수정은 기존 업무 자료에 그대로 반영됩니다. 화면 선택을 되돌려도 이미 처리한 업무가 취소되지는 않습니다.
