# PC 프로그램 자동 업데이트 · v1.4.86부터

## 사용하는 방법

v1.4.85 이하에는 이 기능이 없으므로 v1.4.86을 처음 한 번 ZIP으로 내려받아 압축 해제하고 기존 프로그램을 완전히 종료한 뒤 실행합니다. 이후에는 ZIP을 찾거나 이전 EXE를 직접 삭제할 필요가 없습니다.

실행할 때와 5분마다 인터넷으로 최신 PC 버전을 확인합니다. PC 창 아래와 트레이 메뉴의 **PC 업데이트 확인**은 수동 확인이며 새 버전이 있으면 **v버전 업데이트**가 표시됩니다. 누른 뒤 재시작 안내에 동의하면 다운로드·검증·정상 종료·교체·재실행합니다. 창이 트레이에 숨겨져 있어도 확인은 계속하며 무단으로 재시작하지 않습니다. 다운로드 중에는 업무를 계속하고 실제 재시작 동안만 작업자 접속과 알림이 잠시 중단됩니다. 관리자 APK는 별도 버전입니다.

## 자료와 실패 처리

현재 운영 자료 폴더의 절대 경로와 로컬 포트를 새 프로세스에 전달합니다. D드라이브 자료·사진·첨부·기존 설정을 삭제하거나 새 자료로 초기화하지 않습니다. 실행 파일의 경로는 그대로 유지하므로 바로가기도 계속 사용합니다. 설치 폴더는 쓰기 가능해야 합니다. 압축 파일 안에서 바로 실행하거나 읽기 전용 폴더에 설치하지 마세요.

다운로드/검증/도우미 준비에 실패하면 기존 프로그램을 유지하고 상태에 이유를 표시합니다. 부모 프로세스가 정상 종료되어 파일/자료 잠금이 해제된 후 실행 파일을 교체합니다. 새 프로세스가 시작 확인 전에 종료되면 이전 실행 파일로 되돌려 시작합니다. 2분 후에도 새 프로세스가 살아 있지만 시작 확인이 없으면 업무 자료 보호를 위해 강제 종료하지 않고 창 확인 안내를 표시합니다.

실행 폴더의 `.alpha-pc-update-*`는 도우미와 이전 실행 파일을 보관하는 내부 폴더입니다. 성공한 이전 EXE는 최근 두 개까지 유지하고, 다음 시작 시 오래된 성공 업데이트의 알려진 파일만 정리합니다. 미완료 업데이트나 알 수 없는 파일은 자동 삭제하지 않습니다. 문제 시 `error.txt`와 `previous.exe` 위치를 확인할 수 있습니다. 이는 운영 자료 전체 백업을 대체하지 않습니다. Windows의 보안 확인이나 백신 정책은 그대로 적용됩니다.

## 배포 유지 절차

`recovery/server-builds/pc-update.json`이 최신 PC 버전·Windows ZIP 고정 HTTPS URL·크기·ZIP SHA256·EXE SHA256을 제공합니다. 다른 호스트/저장소, 다른 버전 파일명, 낮거나 같은 버전은 설치하지 않습니다. 정상적인 GitHub/TLS 신뢰와 저장소 관리 권한을 사용하며 SHA256은 다운로드 손상 및 패키지 불일치를 검사합니다.

새 배포마다 버전이 다른 ZIP/전체 소스를 보존해 올리고 패키징 스크립트에서 이 최신 메타데이터도 함께 갱신해야 합니다. 최신 `audit/package-pc-v1.4.90.py`가 ZIP 생성 후 JSON을 자동 생성합니다. 향후 버전에서도 이 단계를 유지해야 사용자의 PC에서 새 버전을 찾습니다. 현재 릴리스와 같은 버전을 설치한 PC는 최신 버전이라고 표시하는 것이 정상입니다.

## 검증 범위

모의 HTTPS 응답 및 유효한 합성 Windows PE/ZIP을 사용해 새 버전 판정, 배포 경로 제한, ZIP/EXE 해시·크기, 중복/경로 조작 ZIP 거부, 다운로드 취소, 기존 파일 불변, 실패 복원, 저장 경로/시작 옵션 유지, 이전 파일 정리를 검사합니다. 전체 Go 회귀·race·Linux/Windows vet·Windows GUI 교차 빌드를 수행합니다. 실제 Windows GUI·백신 환경에서 실행 파일 교체와 재실행은 이 작업환경에서 실행하지 않았습니다.
