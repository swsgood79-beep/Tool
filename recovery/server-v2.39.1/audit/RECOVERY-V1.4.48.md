# v1.4.48 작업자 전송 전반의 나가기 경고 수정

이전 v46의 정상 제출 예외는 토크 글쓰기/수정에만 적용되어 비고 메시지·댓글 등 정상 POST의 화면 이동에 beforeunload 경고가 남아 있었습니다. 해당 원인을 실제 브라우저에서 재현하고 작업자 전송 경로 전체를 공통 처리했습니다. 수주 사진·보관함 기능 작업은 보류하고 이 수정에 포함하지 않았습니다.

## 동작

- 현재 작업장 /complete/{board}, /combined/{board}, /note/{board}와 /community/{board}/save, comment, like, delete, delete-comment에 보내는 동일 원점·현재 창 POST만 정상 제출 예외로 취급합니다.
- submit 이벤트의 defaultPrevented를 beforeunload 시점에 확인하므로 사진 검증·삭제 취소로 제출이 막히거나 검사 신청이 화면 내 fetch로 처리되는 경우에는 정상 탐색 예외를 임의 적용하지 않습니다. 기존 검사 AJAX 처리와 기본 POST 방식 모두 확인했습니다.
- 토크의 정상 공유·사진 첨부·수정·댓글·삭제 및 비고 전송에는 불필요한 나가기 경고가 없습니다. 글 삭제의 기존 ‘삭제할까요?’ 확인창은 유지합니다.
- GET 검색/필터 폼의 입력은 미저장 글로 표시하지 않습니다. 검색 제출과 입력 후 분류 이동에서 나가기 경고가 발생하지 않습니다.
- POST 작성 중 실제 다른 화면으로 이동하는 경우의 미저장 경고, 검사창 보호, 전송 중 자동 재접속 보호 및 POST 비재전송은 유지합니다. dirty 상태 자체를 지우지 않고 정상 제출 탐색 1회만 예외 처리합니다.
- 수주·검사·비고·토크의 저장/검증 API, 승인·반려·완료 및 기존 화면 이동 절차와 데이터 구조, 음성·납기·사급품·저장 위치를 변경하지 않았습니다.

## 실제 서버·브라우저 결과

임시 Go App 서버와 실제 Chromium의 네이티브/form fetch 전송을 사용했습니다. 모바일/PC × 밝은/어두운 테마 4개 조합 및 기본 전송 대체 경로를 확인했습니다.

| 동작 | 결과 |
|---|---|
| 기존 v46 비고 전송 | beforeunload 경고 재현, 취소 시 POST 0회 |
| 세팅검사·출하검사·함께 신청 | 화면 내 전송 후 신청 상태 확인, 나가기 경고 0회 |
| 비고 메시지 | 정상 POST 후 복귀, 중복 없이 1회 접수, 나가기 경고 0회 |
| 토크 글 등록 | 정상 등록, 나가기 경고 0회 |
| 사진 첨부·글 수정 | 실제 사진 저장/로딩 확인, 나가기 경고 0회 |
| 댓글 등록/삭제·좋아요/취소 | 실제 저장 상태 확인, 나가기 경고 0회 |
| 글 삭제 | 기존 삭제 확인 1회, 추가 나가기 경고 0회, 사진 파일 정리 확인 |
| 검색 제출·분류 이동 | 나가기 경고 0회 |
| 필수 항목 누락·8MB 초과 사진 | POST 없음, 일반 이탈 경고로 입력 보호 유지 |
| 세팅·출하·함께 신청의 기본 POST 대체 경로 | 나가기 경고 0회, 실제 요청 저장 |

총 52개 검증 항목을 통과했습니다. Go 측에서 정확히 24개의 검사/비고 이벤트, 중복 없는 비고 접수, 테스트 글·댓글 삭제 및 사진 파일 정리를 확인했습니다. 회사 운영 자료에는 쓰지 않았고 삼성 인터넷 실기기에서는 실행하지 않았습니다.

기존 실제 Service Worker 재접속 회귀 시험 18개와 전체 Go race, Linux/Windows vet를 통과했습니다. Windows GUI 교차 빌드이며 Windows 실기기 실행은 하지 않았습니다. 소스 ZIP 재빌드와 실행파일 일치를 확인하고 이전 버전은 보존합니다. 고정 읽음 연결 페이지는 기존 v47를 그대로 사용하며 새 Pages 배포는 필요하지 않습니다.
