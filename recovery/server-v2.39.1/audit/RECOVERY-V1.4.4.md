# v1.4.4 PC 인터페이스와 신청 알림

요청 최종 반영: 검사자명 별도 항목은 없고 신청자 이름은 표시한다. 검사 종류/수주번호/프로젝트/신청자를 각각 그린다. 세팅 파랑, 출하 주황, 통합 보라, 비고 노랑. 비고는 추가 영역이다. 창은 둥근 패널과 간결한 헤더로 정돈하고 최근 기록은 라벨로 구분한다. 12초/호버 정지/닫기와 읽음 분리/안읽음 숫자 재열기/검사 화면 이동 동작은 유지한다. 팝업 높이는 비고 유무에 따라278/330px, 작업 영역에 맞게 쌓는다. 긴 문자열은 줄바꿈/줄임표를 사용한다. OS 기본 창에는 실제 Windows 확인이 필요하다.

PC 이벤트는 본문 문자열 분해 대신 원본 Event 필드를 사용한다. push pump 경로와 PC snapshot 경로에서 동일한 필터/구조를 사용한다. 검사 완료 이벤트는 PC/휴대폰으로 보내지 않으며 전달 커서는 진행한다. 관리자 승인 시 해당 신청을 읽음 처리한다. 과거 완료는 UI unread에서 제외한다. 기록/엑셀은 유지한다. 비고 알림은 기존대로 유지한다. 사용자의 ‘신청자 이름 필요’ 정정을 반영했다.

관리자 일반 전체 목록에 금일 완료가 섞이던 조건을 수정했다. 완료는 금일완료 필터에만, 납기/캘린더 예외는 기존 요청대로 유지한다. 원본 admin.js는 보존하고 버전별 extras 자산을 사용한다.

TEST 중복: 기존 자료는 운영 copies 아래 projects-v2.dat에 있다. 삭제 확인 링크를 빨간 버튼으로 강화하고 삭제 후 번호 재사용/이전 완료 기록 보존을 테스트했다. 실제 회사 데이터를 도구로 읽거나 삭제하지 않았다.

검증: desktop_notice_test.go 구조/통합검사/시각/최신 프로젝트 정보/완료 알림 제외/웹 badge; integration_test.go 암호화 push mock으로 완료 후 재전송 없음/커서 진행; duplicate_order_test.go 삭제 후 재등록; browser-order-filters-v1.4.4.json 관리자·작업자 일반목록/금일완료/납기/캘린더. Windows GUI 교차 빌드와 vet를 수행하며 실제 Windows 렌더/통화/계정 연결은 여기서 실행하지 않았다. 과거 브라우저 보고서는 당시 검증으로 보존한다.
