# v1.4.47 토크 읽음 기록의 접속 주소 변경 대응

기존 읽음 기록은 public tunnel 원점별 localStorage에만 보관되어 업데이트로 주소가 바뀌면 모두 새 글로 계산되는 문제가 있었습니다. 새 버전은 읽음 기록을 기존 운영 저장 파일의 선택적 TalkReaders 필드에 기기별로 보관하고 고정 GitHub Pages 원점에서 같은 브라우저의 식별값을 다시 연결합니다.

## 연결과 보관

- 게시글 ID만 저장하며 본문·사진 복사본을 추가하지 않습니다. 식별값은 무작위 256비트이고 서버는 작업장 키와 함께 해시한 값만 저장합니다. 작성자 이름·IP·기기 지문으로 사용자를 추정하지 않으며 다른 브라우저의 기록을 합치지 않습니다.
- 식별값은 읽음 기록에만 쓰며 기존 토크 작성·수정·삭제 권한의 소유자 쿠키와 별개입니다. 작성자 권한을 다른 원점으로 옮기지 않습니다.
- public Pages 모드의 유효한 HTTPS trycloudflare 작업자 화면에서 아직 연결되지 않았으면 로컬 기록을 먼저 서버에 보관한 뒤 고정 talk-reader.html 페이지를 거쳐 연결합니다. 제3자 iframe 저장소를 사용하지 않아 모바일 저장소 분리의 영향을 피합니다. 로컬/LAN 및 Pages 이외 모드는 현재 주소에서만 동기화하며 외부로 자동 이동하지 않습니다.
- 최초 연결 후 같은 원점에서는 반복 이동하지 않습니다. 새 공개 원점에서만 다시 연결합니다. 글쓰기·사진 업로드·사용자 입력이 시작됐거나 검사창이 열렸으면 자동 이동하지 않습니다. 기존 사진 공유 경고 수정도 유지합니다.
- 고정 페이지는 기존 식별값을 우선하고 공개 포인터의 application/version/online 및 엄격한 trycloudflare HTTPS 원점을 확인합니다. 같은 작업장의 허용된 작업자 경로와 필터만 복귀 대상으로 사용하며 관리자·외부 임의 URL로 식별값을 보내지 않습니다. 식별값은 URL fragment로 전달하고 앱에서 즉시 지웁니다.
- 기존 주소의 남아 있는 로컬 읽음 기록은 서버 기록과 합칩니다. 본인 글도 읽음으로 보관해 원점 변경 후 새 글로 세지 않습니다. 상세 열람은 keepalive POST로 반영하고 기존 15초 새 글 조회 때도 동기화합니다. 추가 읽음이 없으면 저장 파일을 다시 쓰지 않습니다. 검사 엑셀을 다시 쓰지 않는 기존 공지 저장 경로를 사용합니다.
- 이미 접근 불가능한 옛 주소에만 남았거나 초기화된 기록은 소급 복구할 수 없습니다. 서버에 이번 버전으로 기록된 것부터 유지합니다. 브라우저 저장 공간을 지우거나 시크릿 모드를 종료하면 별도 브라우저로 취급됩니다.
- 게시글 삭제 시 사진 정리 방식은 기존과 같습니다. 읽음 기록의 삭제된 글 ID는 해당 기기의 다음 동기화 때 제거합니다.

## 배포

고정 페이지 https://swsgood79-beep.github.io/Tool/talk-reader.html 와 talk-reader-v1.4.47.js 두 파일만 기존 gh-pages 브랜치에 추가했습니다(724c4ac). 기존 QR index·relay·관리자·휴대폰 페이지는 수정하지 않았습니다. 두 파일의 원본은 이 소스 ZIP의 extras/talk-reader-bridge-v1.4.47.html/js입니다. 서버 실행파일 외에 이 정적 페이지도 유지해야 합니다.

gh-pages 공개 raw 스크립트와 소스 해시 일치를 확인했습니다. 이 실행 환경에서는 기존 Pages 루트와 신규 Pages URL 모두 HTTP 403으로 막혀 실제 Pages 호스트 응답은 직접 확인하지 못했습니다. 실제 회사 휴대폰 접속 및 Pages 호스트 점검은 별도 확인 범위입니다.

## 검증

- 실제 임시 Go 서버 + Chromium에서 두 HTTPS 터널 원점과 고정 Pages 원점 사이를 이동했습니다. Pages 파일과 공개 포인터만 모의했으며 읽음 API는 실제 서버·저장 파일을 사용했습니다. 기존 로컬 기록 이전·상세 열람·주소 변경 후 읽음 유지·새 글은 미읽음·다른 PC 기록 분리·위험한 복귀 URL/포인터 차단을 확인했습니다.
- Go에서 기기 분리·기록 합치기·재실행 보존·삭제 ID 정리·변경 없는 조회의 파일 미갱신·읽음 저장이 검사 엑셀을 수정하지 않는 것을 검증했습니다.
- 실제 임시 서버에서 모바일/PC × 밝은/어두운 테마 4개 조합의 토크 사진 공유·수정 저장·잘못된 사진/필수항목 검사·일반 이탈 보호 회귀 시험을 통과했습니다.
- 전체 Go race 및 Linux/Windows vet 통과. Windows GUI 교차 빌드이며 Windows 실기기 실행은 하지 않았습니다. 소스 ZIP 재빌드 일치를 확인하고 이전 배포본과 증거 자료는 보존합니다.
