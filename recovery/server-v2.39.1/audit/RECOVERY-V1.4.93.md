# PC v1.4.93 · 출하 고객사 표시 누락 수정

출하 기록의 고객사 표시를 화면·목록·고객사 검색·출하 엑셀에서 통일했습니다. 수주명에서 띄어쓰기 뒤 숫자+축 앞부분을 고객사로 사용합니다. **은일 12축 → 은일**, **쿼드메디슨 3축, 긴급건 → 쿼드메디슨**입니다. 업체 특이사항 연결 여부와 관계없이 적용하며 고객사가 비어 있는 기존 보관 건도 다시 열면 표시합니다. 숫자+축 형식이 없으면 저장된 고객사, 명시적으로 연결된 업체 이름을 사용하고 확인할 수 없으면 항목을 숨기지 않고 미등록으로 표시합니다. 신규 검사/사진 보관 때도 같은 기준으로 고객사를 저장합니다. 기존 특이사항 연결·사진·검사일·보관일은 유지합니다. PC v1.4.86 이상은 PC 업데이트 확인으로 v1.4.93을 설치하고 APK 1.0.11은 그대로 사용합니다.

이전 captureShippingRecord는 고객사 이름을 연결된 ClientNote가 있을 때만 저장하고 상세 템플릿은 빈 이름이면 고객사 span을 생략했습니다. v1.4.85의 수주명 고객사 추출은 Excel job에만 있었으므로 화면과 Excel이 서로 다른 기준을 사용했습니다. shippingCustomerName은 기존 축 수량 패턴 함수를 공통으로 사용하고, 명시적 ClientSourceID 또는 정확한 수주 ID/번호/출하 이벤트/완료시각 일치로 확인된 업체 연결만 보조 정보로 사용합니다. 고객사 이름에서 ClientID를 추정하거나 원본 특이사항 연결을 변경하지 않습니다.

App.shippingCurrentNotes·shippingListView·export job·승인 캡처·최종 사진 보관에 같은 함수를 사용합니다. 조회와 내보내기 사본만 기존 빈 이름을 보완하고 이전 State를 일괄 다시 쓰지 않습니다. 템플릿은 빈 이름이면 미등록을 명시합니다. 출고일자 문구·보관일·사급품·사진 중복 제거·검사자 기록은 유지합니다.

단위 시험은 고객사 누락/기존 값/축 패턴 우선/공백이 있는 고객사/형식 없는 수주의 저장된 이름/원본 연결 없는 신규 캡처/사진 보관·재실행/수주 제거 후 과거 조회/명시적 원본 fallback/알 수 없는 이름·다른 원본 추정 금지를 검사합니다. 관리자·작업자 HTTP 상세/목록 검색·실제 출하 XLSX C8 고객사 셀과 조회 시 State 불변을 검사합니다. Chromium PC/모바일 APK agent 밝게·어둡게에서 은일·쿼드메디슨 16뷰와 검색을 확인했습니다. 전체 Go/race/vet·Windows GUI 교차 빌드·소스 재빌드 일치/원본 web57개·APK1.0.11 체크섬을 확인합니다. 실제 회사 자료나 Windows/Android/Microsoft Excel 기기는 실행하지 않았습니다.
