# v1.4.9 조립일정 N열 사급품 연결

사용자 첨부 일정표를 읽기 전용 확인했으며 N7 제목 ‘사급 관련’을 확인했다. 실제 데이터/사진/키를 소스나 ZIP에 넣지 않는다. 별도 parseScheduleMaterials로 같은 받은 XLSX에서 N열 텍스트를 읽는다. 추가 다운로드는 없다. 수주NO/발송예정일 헤더 행을 찾아 N열에 사급 헤더가 있는 경우만 적용한다. 실제 병합 범위만 적용하고 같은 번호 여러 행의 내용은 중복 없이 합친다. N열 빈 값은 명시 삭제, N열 없음/원본 번호 없음/실패는 기존 값 보존이다. 날짜 충돌과 사급품 텍스트 동기화는 독립이며 날짜가 안 바뀌어도 Project.Revision을 올린다.

Project/LegacyOrder/direct projection에 SuppliedMaterials/SuppliedMaterialsManaged를 보존하고 직접 저장 확장·정상 필드·휴대용 백업 경로와 호환한다. 수동 특이사항이나 업체 원본을 덮어쓰지 않는다. 날짜 변경과 별도 사급품 변경 건수를 상태에 제공한다.

카드·검사 화면·특이사항 상세·금일 완료에 특이사항 앞에 금색 사급품 표시를 넣고 클릭 시 안전한 textContent로 전체 내용을 표시한다. 관리자/작업자 캘린더는 이전 완료 제외 정책을 유지한다. 초기 렌더와 상태 JSON/패널 갱신/금일 완료 DOM 갱신에 필드를 포함한다. 원본 web57개는 변경하지 않고 템플릿 파싱 시 보강한다.

검증: schedule_materials_test.go(병합/빈칸/같은 번호 다중 행/열 없음/날짜 불변 갱신/수동내용 보존/저장 재실행/원본 필드 읽기/완료 polling), 기존 첨부파일 파싱 시험에 N열 식별 확인 추가. browser-supplied-materials-v1.4.9.json 관리자/작업자×1100/390px에서 특이사항 앞 배치, 전체 내용, 독립 클릭, 중첩 캘린더, 실시간 표시 갱신, 가로 넘침/JS 오류를 합성 내용으로 확인했다. 실제 회사 OneDrive 다운로드/Windows GUI 실행은 이 환경에서 확인하지 않았다.

소스 소실 대응을 위해 소스 ZIP/실행 ZIP/커밋/해시를 버전별 보존한다. 배포 소스 ZIP을 별도 경로에 풀어 재빌드한 검증 결과는 server-builds의 해당 버전 source-rebuild.json에 별도 보관한다. 이 사실은 실제 업무 DB 백업이나 어떤 상황에서도 복구 가능하다는 보장이 아니다.
