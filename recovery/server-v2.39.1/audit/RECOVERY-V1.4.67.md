# v1.4.67 · 선택형 관리자 앱 로그인

관리자 APK 1.0.3은 시작/일반 백그라운드 복귀 시 아이디·비밀번호 입력 화면을 먼저 표시합니다. 그 아래 ‘지문으로 로그인하기’를 직접 눌렀을 때만 Android 인증을 시작합니다. 자동 인증창 호출은 onCreate/onResume/알림 클릭/앱 메뉴에서 제거했습니다. 지문 로그인 정보가 있어도 자동으로 세션을 복원하거나 업무 화면을 표시하지 않습니다. 로그인 화면에서 앱 업데이트 확인도 사용할 수 있습니다. 사진/파일 선택 복귀는 진행 중인 업무를 유지합니다.

비밀번호 로그인은 현재 서버 /login의 CSRF nonce와 /login 경로 쿠키를 사용합니다. 비밀번호를 저장하지 않으며, 성공한 응답의 세션 쿠키로 계정·권한을 확인한 뒤 기존 지속 로그인 연결을 등록합니다. 동일 계정의 중단된 업무 화면은 가능한 경우 기존 CSRF와 화면을 유지합니다. 다른 계정으로 로그인하면 이전 계정 화면을 보여주지 않고 새 업무 화면을 연 뒤 이전 내비게이션 기록을 지웁니다. 다른 아이디가 입력된 상태에서 저장 계정의 지문을 사용하는 것을 방지합니다. 지문 복원 후에도 서버가 반환한 실제 account_key가 저장된 계정과 같은지 확인합니다.

지문은 휴대폰 설정에 등록된 생체인증이며, 지문 데이터는 앱이나 서버가 저장하지 않습니다. 각 관리자는 자기 휴대폰에서 본인 관리자 계정으로 최초 1회 비밀번호 로그인한 뒤 지문을 사용할 수 있습니다. 한 휴대폰은 마지막으로 연결한 계정 하나를 사용하며 지문별 계정 구분은 하지 않습니다. 계정 중지·비밀번호 변경·명시적 로그아웃에 따른 기존 서버 검증을 유지합니다.

서버 bootstrap에 본인 account_username을 추가합니다. 그 외 PC 메뉴·디자인·권한·수주·Firebase 설정은 유지합니다. APK의 로그인 프로토콜은 서버 v1.4.66에서도 사용할 수 있으며 새 필드는 표시 개선용입니다. 앱 업데이트 manifest를 1.0.3/versionCode 4로 갱신하고 기존 서명키로 APK를 서명합니다. 앱 안의 업데이트 확인은 foreground에서 수행하며 잠금화면/다른 앱 사용 중 새 버전 안내를 보내는 기능은 없습니다. 검사 알림의 기존 FCM 수신과는 별개입니다.

검증: Go 전체 테스트, 임시 TLS 서버에서 실제 비밀번호 로그인·CSRF·쿠키 경로·대표/개인 계정 권한·username 계약, 관련 race, Linux/Windows vet, Windows GUI 교차 빌드/전체 소스 동일 재빌드. Android release 빌드, JUnit 16개, Lint/서명 검사. 실제 Android 지문 센서·native 입력 화면·OS 설치창은 이 환경에서 실행하지 않았습니다. 기존 업무 웹 화면은 v1.4.66의 브라우저 검증 자료를 이력으로 유지합니다. 회사 자료와 Firebase 비밀키에는 접속하거나 변경하지 않았습니다.
