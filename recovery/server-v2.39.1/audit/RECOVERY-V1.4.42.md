# v1.4.42 업데이트 후 작업자 자동 재접속

열린 작업자 탭이 10초 간격으로 준비 상태·버전을 확인합니다. 연속 두 번 연결에 실패하면 다시 연결하며, 동일 주소의 새 버전도 갱신합니다. 이전 주소가 끊긴 상태에서 새로고침하면 Service Worker가 공개된 고정 QR 포인터의 최신 서버로 연결합니다. 연결이 아직 준비되지 않았으면 대기 화면에서 20초마다 재시도합니다.

## 설치와 범위

- Windows 프로그램을 종료하고 새 실행파일로 교체·실행합니다. 공용 PC마다 저장된 고정 북마크로 한 번 접속해야 v42의 복구 코드가 등록됩니다. 이미 열린 이전 버전 탭에는 소급 설치할 수 없습니다.
- Pages 방식 + 유효한 trycloudflare 공개 주소의 작업자 화면에서만 설치합니다. 로컬/LAN 및 관리자 흐름은 그대로입니다.
- Service Worker 범위는 해당 출처의 루트지만 가로채는 요청은 명시된 작업·출고 탭·토크·공지·업체·특이사항 화면의 GET 탐색뿐입니다. 관리자·로그인·API·사진·POST는 처리하지 않습니다.
- 네트워크 우선이며 Cache API로 업무 페이지를 저장하지 않습니다. 게이트웨이 장애·네트워크 오류만 복구하고 정상 응답 및 업무 오류는 유지합니다.
- 공개 GitHub 포인터만 읽으며 비공개 토큰은 전달하지 않습니다. application/version/online 및 엄격한 HTTPS trycloudflare 원점을 검사합니다. 기존 작업자 경로와 허용된 화면 필터만 전달합니다.
- 검사창·전송 중 폼·보이는 수정 폼이 있으면 현재 입력을 유지하고 새 탭 연결을 안내합니다. 나가기에는 브라우저의 입력 경고를 사용합니다. 신청·게시·댓글을 자동 재전송하지 않습니다.
- 회사 PC와 프로그램이 꺼져 있으면 접근할 수 없습니다. 이 변경은 클라우드 서버 이전이 아닙니다. 브라우저가 Service Worker를 차단하면 열린 탭의 고정 주소 이동은 가능하지만 끊긴 원점에서의 새로고침 복구는 제한됩니다.
- 원점 변경 시 브라우저별 설정·글 소유권·읽음 정보는 기존 동작을 따릅니다. 자료 위치·D 경로·운영 데이터 구조·업무 처리는 변경하지 않았습니다.

## 검증

- go test -race ./... 통과, Linux 및 Windows 대상 go vet 통과.
- 실제 Chromium Service Worker와 Go 렌더링 HTML로 모바일 390px/PC 1100px 각 9개, 총 18개 시나리오 통과. 이전 주소 장애의 새로고침·열린 탭 자동 복구·입력 보호·POST 비재전송·캐시 미저장·대기 후 복구·타 작업자 경로/필터·관리자/인증 비간섭·동일 원점 버전 갱신·잘못된 포인터 거부를 확인했습니다.
- 공개 GitHub/Cloudflare 응답은 브라우저 시험에서 모의하고 실제 회사 서버 통신은 하지 않았습니다. Windows 실행은 하지 않았으며 windows/amd64 GUI 교차 빌드입니다.
- 원본 web 자산 57개 해시 및 소스 재빌드 실행파일 일치를 패키징 과정에서 검증합니다. 이전 배포 ZIP은 보존합니다.
