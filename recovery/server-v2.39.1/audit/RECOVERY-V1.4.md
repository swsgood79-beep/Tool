# v1.4 운영 전환 배포본

v1.3.1까지는 의도적으로 외부 연동을 차단한 격리 시험판이었다. 사용자의 운영 전환 요청에 따라 v1.4에서는 운영을 기본 모드로 두고 -test를 별도 제공한다. 원본과 100% 동일성을 인증하거나 회사 계정/Windows 실기기 검증을 마쳤다는 의미는 아니다.

## 운영 데이터

- 기본 루트 UserConfigDir/AlphaWorkCompleteRecovered, active-production-copy.json이 선택한 copies/copy-{UTC}-{token} 폴더.
- 최초 실행에 원본 WanryoTalk의 기존 6개 파일/사진을 읽기 전용 복사. 이후에는 선택된 운영 데이터 재사용. 원본 재복사나 덮어쓰기 없음.
- 별도 production marker 사용. 원본/테스트 폴더를 운영 저장 폴더로 직접 지정하는 것을 거부. 선택 정보 경로 탈출/표시 없는 폴더 거부.
- 운영 루트/선택 데이터 잠금과 Windows 원본 뮤텍스 Local\WanryoTalkNotifier-v1으로 이중 운영 방지. 테스트는 기존 별도 뮤텍스·클래스·쿠키를 유지.
- -promote-test는 최초 운영 시작 전에만 가능. 테스트 업무 자료와 원본 연결/인증 설정을 조합한다. QR 키/비밀번호/패스키/연동 설정은 원본에서 복구한다. 푸시 전송 기준을 현재 데이터의 NextID로 잡아 테스트 과거 알림 재전송을 피한다. 원본/테스트 자료는 수정하지 않는다.
- -empty는 새 PC 복원용으로 비어 있는 운영 데이터를 생성한다. 이미 선택한 운영 데이터가 있으면 교체를 거부한다.
- 운영 시작 후 새 테스트 복사본 생성은 오래된 원본보다 최신 운영 폴더를 우선한다.

## 운영과 시험의 구분

운영에서는 Integration 설정을 비우거나 외부 transport를 차단하지 않는다. 시세/일정/백업 pump는 설정대로 작동한다. 설정된 quick 또는 Pages+GitHub 키가 있으면 서버 준비 후 터널 연결을 시도한다. 실제 준비 endpoint 검증 뒤에만 포인터 게시를 수행한다. 수동 연결도 유지한다. 테스트 모드는 설정 초기화와 외부 HTTP 차단을 계속 적용한다.

테스트의 모바일 경로 차단에서 PC 네이티브 일회용 티켓의 로컬 finish만 예외로 했다. Native 티켓은 UI 내부에서만 생성하며 토큰/만료/일회용 검증을 통과해야 한다. 외부 패스키 등록/로그인 경로는 여전히 테스트에서 차단한다.

## 확인

production_test.go: 원본 불변 복사와 설정/QR 키 보존, 운영 재실행, 원본/테스트 폴더 거부, 잘못된 선택 경로, 테스트 업무 자료 전환과 원본 인증 설정 복구, 재전환 차단, 새 PC 빈 복원 시작, 운영 메뉴 개방/시험 메뉴 차단, 별도 UI 식별자, 시험의 안전한 네이티브 티켓, 최신 운영 자료로 테스트 복사.

browser-production-v1.4.json: 생성한 원본 스키마 시험 파일만 사용. Linux에서 운영 첫 실행/자료 복사, 운영 설정 메뉴, 신청/승인, 테스트 별도 자료/쿠키/차단, 운영 재시작 시 완료 상태 유지, 원본 파일 해시 불변을 확인했다. 실제 회사 자료/계정/Cloudflare/푸시 제공자/Windows 실행을 사용하지 않았다.

go-test-race-v1.4.txt와 build-manifest-v1.4.json에 테스트/빌드 결과를 기록한다. 제공된 실제 엑셀과 회사 데이터는 소스나 ZIP에 포함하지 않는다. 과거 보고서와 배포 ZIP은 보존한다.

## 운영자 확인 필요

START-HERE.md 순서대로 원본 폴더/엑셀 보관, 하나의 초기 데이터 선택, 수주/사진/기록 확인, 휴대폰 실제 알림/수주 이동/지문 로그인, 시세·OneDrive·백업 상태, 복구키 PC 밖 보관을 확인한다. 백업 상한 256MB와 원본과 다른 UI/일부 미복원 항목은 계속 공개한다. 원본을 보존해도 운영 전환 이후의 기록이 원본 폴더로 자동 돌아가는 것은 아니다.
