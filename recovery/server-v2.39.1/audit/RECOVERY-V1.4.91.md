# PC v1.4.91 · 검사자 표시 정리 / 완료 시각 검증 / PC 접속 세션

업체 특이사항의 내용·사진 수정은 이미 보관 완료된 출하 기록과 새로 저장하는 출하 엑셀에도 반영합니다. 수주별 추가 메모·사진은 별도로 유지하고 명시적으로 수주 특이사항을 수정하면 동일 검사 건의 출하 상세도 갱신합니다. 출하사진·첨부·사급품·담당자·검사 완료일·보관일은 변경하지 않습니다. 업체 원본을 삭제하면 마지막 내용을 보관합니다.

검사 완료 화면과 출하 상세에는 검사자 이름·실제 완료 일시만 표시합니다. 하단의 자동/과거 보완 방식·보완 처리 시각/계정 표시는 빼고 출하 상세 엑셀도 같은 방식으로 정리했습니다. 내부 보완 이력은 유지합니다. 신규 검사는 관리자 완료 버튼을 서버가 처리한 시각을 저장하며 신청 시각과 구분합니다. 기존 완료 시각은 바꾸지 않습니다. PC에서 관리자 화면을 다시 열 때 유효한 로컬 대표 관리자 세션을 재사용해 기존 탭의 CSRF가 바뀌지 않도록 했습니다. 일회용 접속 티켓·계정 권한·CSRF 검증은 유지합니다. APK 1.0.11은 그대로 사용합니다.

동일 로컬 대표 세션 재사용은 /mobile-admin/passkey/finish의 유효하고 소비된 PC 티켓(Owner 없음)에만 적용합니다. 이름 있는 계정·원격 WebAuthn 흐름은 기존 새 세션 발급 경로를 따릅니다. 만료/로그아웃 세션은 재사용하지 않습니다. 접속 쿠키를 다시 만들며 다른 탭에 남은 폼 토큰과 불일치하는 경로를 재현해 회귀 시험을 추가했습니다. 사용자 스크린샷만으로 당시 원인을 확정할 수는 없습니다.

이미 승인 함수는 time.Now()로 단계/Event/출하 스냅샷/검사자 recordedAt을 기록하고 있었습니다. 이번 시험은 신청 시각을 이틀 전으로 둔 별도/통합 승인이 현재 서버 시각을 쓰고, 요청 시각과 기존 완료 재제출 시각은 바꾸지 않음을 검증합니다. 화면과 XLSX만 표시를 줄이고 저장 구조와 내부 감사 이력/검사자 원장은 유지합니다. 기존 web 57개 및 APK 1.0.11 그대로. 회사 실자료, Windows GUI·Android 기기·Microsoft Excel은 실행하지 않았습니다.

새 보관 기록은 업체 원본 ID/revision과 공통 사진 ID 목록을 별도로 저장합니다. 구형 기록은 현재 수주 ID·번호·출하 EventID·완료 시각이 모두 같은 경우에만 업체 연결을 복구합니다. 원본 연결을 확인할 수 없는 과거 기록은 이름만 추정해 바꾸지 않고 기존 복사본을 유지합니다. 내용·사진 읽기와 엑셀 내보내기 스냅샷/파일 보존 핀이 같은 최신 프로젝션을 사용합니다. 원본 저장 및 수주 특이사항 수정 transaction에서 변경을 영속화합니다. 원본 삭제 후에도 보관 사진 참조는 남아 파일 정리에서 제외합니다. 테스트는 구형/신규 보관·실제 multipart 사진 추가/제거·순서/고유 메모 보존·수주 삭제 이후 원본 수정·재시작·원본 삭제 보존·출하 엑셀 실생성·다른 검사 주기 연결 금지를 확인합니다.
