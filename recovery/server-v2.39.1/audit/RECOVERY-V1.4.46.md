# v1.4.46 토크 공유하기 정상 제출 경고 수정

외부 작업자 화면에서 자동 재접속 도우미의 beforeunload 보호가 정상적인 토크 multipart POST까지 미저장 이탈로 판단하여 휴대폰에 ‘사이트에서 나가시겠습니까?’를 띄우던 문제를 수정합니다. 정상 공유하기 및 수정 저장은 경고 없이 기존 업로드·검증·저장·목록 복귀를 수행합니다.

## 변경 범위

- 재접속 도우미 JS만 v1.4.46으로 갱신합니다. Service Worker는 기존 v42를 유지합니다.
- #community-form의 현재 작업장 /community/{board}/save로 보내는 동일 원점·현재 창 POST submit 이벤트를 추적합니다. submitter의 method/action/target 재정의를 검사하고 다른 창/다른 목적지 제출에는 예외를 적용하지 않습니다.
- beforeunload 시점에 submit 이벤트의 defaultPrevented를 확인합니다. 필수 항목이 없어 submit 자체가 발생하지 않거나 기존 사진 검증기가 제출을 막은 경우에는 예외를 적용하지 않습니다.
- id라는 숨김 입력이 form.id 속성을 가리는 실제 폼 구조를 고려하여 getAttribute로 식별합니다.
- 정상 제출의 beforeunload 1회에만 예외를 사용합니다. 후속 사용자 입력·클릭·키 입력과 페이지 재표시 시 예외를 지웁니다. dirty 상태 자체를 삭제하지 않으므로 업로드 중 자동 재접속은 여전히 입력을 보호합니다.
- 다른 화면 이동의 미저장 경고·검사창 보호·자동 재접속·POST 비재전송을 유지합니다. 토크 저장 API, 사진 압축·권한·목록 이동, 기존 검사·납기·사급품·공지·음성과 자료 위치는 변경하지 않았습니다.

## 검증

- 실제 임시 Go App HTTP 서버와 Chromium에서 모바일/PC × 밝은/어두운 테마 4개 조합을 실행했습니다. 합성 PNG를 브라우저 파일 입력에 넣고 실제 multipart POST로 저장한 뒤 목록→상세에서 사진 로딩을 확인했습니다. Enter 키 수정 저장도 확인했습니다. 정상 공유/수정에서는 beforeunload 대화상자가 0건이었습니다.
- 각 조합에서 필수 제목 누락과 8MB 초과 사진을 시험해 POST가 발생하지 않는지 확인하고, 이후 다른 화면으로 나가려 할 때 경고를 취소하면 글이 유지되는 것을 확인했습니다.
- 임시 앱에 총 4개 글과 각 1장의 사진이 남고 수정된 제목이 저장되는 것을 Go 측에서 확인했습니다. 회사 운영 자료나 회사 서버에는 쓰지 않았습니다. 실제 삼성 인터넷 실기기는 시험하지 않았습니다.
- 기존 실제 Chromium Service Worker 회귀 시험 18개를 통과했습니다. 열린 탭/죽은 주소 새로고침 복구·다른 작업자 메뉴·버전 변경·미작성 내용 보호·POST 1회·캐시 미저장·잘못된 포인터/관리자 인증 비간섭을 확인했습니다.
- 전체 Go race 및 Linux/Windows vet 통과. Windows GUI 교차 빌드이며 실제 Windows 런타임 실행은 하지 않았습니다. 소스 ZIP 재빌드의 실행파일 일치를 확인하고 이전 배포본을 보존합니다.
