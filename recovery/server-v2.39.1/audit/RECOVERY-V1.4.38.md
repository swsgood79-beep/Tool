# v1.4.38 — 작업 공유와 D드라이브 자료 경로

작업자 하단은 작업 / 출고 일정 / 업체 특이사항 / 작업 공유 / 전체의 5개 메뉴입니다. 관리자 하단 4개 메뉴는 유지합니다. 작업 공유는 전체·작업안내·건의사항·일상생활 분류, 글/작성자 검색, 최신 순 20건 페이지, 글과 사진 등록/수정/삭제, 댓글 등록/삭제, 브라우저별 좋아요를 지원합니다. 일상생활은 일반 SNS처럼 자유로운 내용과 사진을 올리는 분류입니다. 관리자는 전체 → 작업 공유 관리에서 모든 게시글과 댓글을 삭제할 수 있습니다.

## 사진과 작성 권한

사진은 최대 5장·각 8MB의 JPG/PNG/GIF를 받아 긴 변 1,600px 이내 JPEG(품질82)로 저장합니다. GIF는 첫 프레임이며 휴대폰 JPEG EXIF 회전은 반영하고 나머지 메타데이터는 제거합니다. 원본 프로젝트·공지 사진 처리에는 영향을 주지 않습니다. 글/첨부 삭제를 저장한 후 다른 자료에서 참조하지 않는 해당 게시판 사진을 photos 폴더에서 정리합니다.

이름은 직접 입력하는 표시명이며 새 로그인 계정을 만들지 않습니다. 수정/삭제 소유권과 좋아요는 HttpOnly/SameSite 쿠키의 난수 해시 기준입니다. 같은 공용 브라우저 사용자는 작성 권한을 공유합니다. 접속 도메인이 바뀌거나 쿠키를 지운 경우 이전 글은 관리자가 정리할 수 있습니다. 작업자 쓰기는 board 검증과 쿠키, 관리자 관리는 기존 로그인/CSRF를 사용합니다. 텍스트는 이스케이프하고 글 수정 충돌은 revision으로 검출합니다.

글·댓글·사진 정보는 기존 projects-v2.dat의 _RecoveredV1 상태에 선택적 Community 필드로 보관합니다. 공지와 같은 저널 저장을 사용하며 수주/검사 이벤트나 엑셀 기록을 만들지 않습니다. 기존 암호화 백업에도 게시판 사진을 포함합니다.

## 자료 경로 변경

회사 PC의 관리자 전체 → 자료 저장 위치에서 현재 폴더와 사용 용량을 확인하고 D:\AlphaWorkCompleteData 같은 새 전용 폴더를 예약하세요. 프로그램을 트레이에서 종료 후 다시 실행하면 현재 활성 운영 폴더의 수주·사진·공지·작업 공유·엑셀·설정·백업본 등 일반 파일 전체를 복사합니다. 원본 잠금, 기존 저널 복구, 모든 파일 SHA-256/복사 중 원본 변화 검사, 복사본 상태 읽기를 거쳐 새 폴더로 전환합니다. 임시 복사 폴더는 대상 드라이브에 만들며 최종 이름으로 원자적 변경합니다. 기존 자료/QR/설정은 유지됩니다.

예약/사용 경로의 작은 JSON 파일은 기존 AppData 운영 루트에 둡니다. 이후 업데이트도 이 설정을 읽습니다. 자료는 D에 저장되지만 Windows/브라우저/음성 런타임 임시 캐시와 실행 파일 다운로드는 별도 위치에 남을 수 있습니다. 연동 중인 회사 OneDrive 원본 파일 경로는 자동으로 옮기지 않습니다.

기존 운영 폴더는 지우지 않습니다. D에서 정상 사용 및 백업을 확인한 뒤 이전 운영 복사본을 별도로 정리해야 C 공간이 확보됩니다. 새 경로는 비어 있거나 존재하지 않는 전용 폴더여야 하며 현재 폴더/상하위·연결 폴더·원본 프로그램 폴더는 거부합니다. 복사 실패 시 기존 경로로 실행하고 저장 위치 화면에 원인을 표시합니다. 이미 선택한 드라이브가 사라지면 빈 자료를 새로 시작하지 않고 오류로 중단합니다. 명시적 -data 옵션은 사용자 지정 경로를 우선합니다. D로 변경 후에는 v1.4.38 이상 EXE를 사용하세요(구버전은 새 경로 선택 파일을 모릅니다).

## 검증

- Go 실제 HTTP: 작성 쿠키/board/CSRF, 다른 브라우저 수정·삭제 거부, 글/댓글 이스케이프, 좋아요 토글, 수정 충돌, 사진 축소/JPEG 변환, EXIF 방향, 재실행 보존, 암호화 백업 사진 복원, 관리자 삭제와 미참조 사진 정리, 수주/이벤트/엑셀 불변 검증.
- 경로 이전: 운영 폴더 전체 해시 일치, 원본 보존, QR/게시판 읽기, 다음 실행 경로 유지, 사용 중인 폴더 덮어쓰기 거부, 상하위/상대 경로 거부, 실패 시 기존 경로, 드라이브 부재 시 빈 시작 방지.
- 전체 Go race, Linux/Windows go vet, Windows amd64 GUI 빌드. 원본 web 자산57개 해시, ZIP 무결성, 소스 ZIP에서 동일 실행 파일 재빌드.
- Chromium 48조합: 새 게시판/저장 위치 12 + 기존 카드 12 + 오늘 납기 12 + 공지 12. 새/기존 화면·밝게/어둡게·320/390/1100px·관리자/작업자 조합에서 확인했습니다.
- 실제 회사 PC의 D드라이브·Windows GUI/DPAPI·외부 계정은 이 Linux 환경에서 실행하지 않았습니다. 경로 복사는 Linux 임시 폴더에서, Windows는 교차 빌드로 확인했습니다. 회사 실자료는 사용하지 않았습니다.

## 사용 순서

1. 기존 프로그램을 트레이에서 종료하고 새 ZIP을 풀어 실행합니다. ZIP/EXE는 D:\AlphaProgram 등 별도 프로그램 폴더에 두어도 됩니다.
2. 관리자와 휴대폰 화면을 새로고침합니다. 작업 공유에서 이름·분류·글·사진을 입력해 공유합니다.
3. 회사 PC 관리자 전체 → 자료 저장 위치에서 D:\AlphaWorkCompleteData를 지정하고 ‘다음 실행부터 이 위치 사용’을 누릅니다.
4. 트레이에서 종료하고 재실행합니다. 첫 복사는 사진 용량에 따라 시간이 걸릴 수 있습니다.
5. 자료 저장 위치의 현재 폴더가 D로 표시되는지 확인하고 수주/사진/게시판/백업을 확인합니다. C 복사본 정리는 그 다음에 합니다.

전체 소스·실행 ZIP·소스 ZIP·검증 기록을 recovery-v2.39.1 브랜치에 추가하며 이전 버전은 보존합니다.
