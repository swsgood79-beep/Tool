# v1.4.18 알림 효과음 지연과 반복 말하기

사용자는 최종 메시지에서 현재 목소리/읽는 방식이 좋으니 지연만 줄이고 반복 1회/2회를 추가하라고 정정했다. 문장 조합·선택 엔진/배속은 변경하지 않는다. 기존 관리자 신청·비고/공용 신청 경계도 유지한다.

원인: 기존 Windows 경로는 Python이 음성을 생성한 뒤 pygame에서 효과음→디코딩/시간조정→음성을 재생했다. 브라우저도 MP3 응답 후 850ms 효과음을 기다렸다. 이를 알림 수락 시점의 효과음과 음성 준비의 병행으로 바꾼다. Native inspectionAnnouncer는 중복/꺼짐/대기 초과를 통과한 새 job에 대해 notice callback을 먼저 호출하고 음성 작업자를 깨운다. callback은 전역에 보존한 WAV 메모리를 WinMM PlaySoundW ASYNC|MEMORY|NODEFAULT로 즉시 전달한다. 같은 순간 여러 알림은 1초 간격으로 효과음을 합친다. 큐/꺼짐/종료의 stopNotice로 효과음을 중단한다. 예전 미확인 재표시나 중복 ID는 다시 울리지 않는다.

Python에 뒤늦은 chime 파일을 전달하지 않는다. not_before 절대시각을 전달하고 음성 디코딩/시간조정이 완료된 뒤 필요할 때만 기존 효과음의 끝까지 짧게 기다린다. 따라서 첫 효과음은 인터넷·라이브러리 준비를 기다리지 않고, 음성도 효과음을 합성 후 추가로 기다리는 1.1초를 줄인다. GUI가 표시된 뒤 background에서 포함된 runtime을 준비해 첫 재생의 준비 작업도 앞당긴다. 프로그램 창/수주 HTTP 요청을 기다리게 하지 않는다.

브라우저는 새 job을 받는 즉시 WebAudio 효과음을 낸다. 합성 요청을 병행하고 준비가 느리면 효과음을 다시 기다리지 않는다. 빠른 합성이면 효과음 종료 시점까지만 기다린다. 여러 건의 효과음은 1초간 합치고 음성 큐는 그대로 유지한다. 음성 ON 화면의 내부 알림 확인은 3초→0.5초로 단축해 PC 팝업과의 시간차를 줄인다. 새 ID가 없으면 전체 이벤트 복사/정렬을 생략한다. 외부 시장/납기/API 조회 간격이나 Google/Microsoft 합성 요청 수를 늘리는 변경이 아니다. 인터넷/음성 제공사 및 오디오 장치의 실제 지연까지 없애는 것은 아니다.

TTSConfig.repeat 정수는 기본1, 허용1/2이며 설정 GUI의 ‘반복 말하기’ select로 바꾼다. JSON 자동 저장/기존 mirror/백업·복원/테스트 job snapshot에 포함한다. 기존 v17 JSON이나 백업에 repeat가 없으면 1로 이관해 현재 동작을 유지한다. 이전 GUI가 repeat를 보내지 않으면 현재 값을 유지한다. 0/3/음수/문자열은 거부한다. 기존 목소리/배속/ON·OFF를 초기화하지 않는다.

Python은 음성을 한 번만 생성·디코딩하고 pygame Sound.play(loops=repeat-1)로 같은 채널에서 이어 읽는다. 두 번 읽는 동안 다음 알림이 끼어들지 않고 임시 파일은 끝난 뒤 정리한다. 브라우저는 X-TTS-Repeat를 받아 같은 blob URL/media element를 한 번 더 재생하며 합성 API를 다시 호출하지 않는다. 큐의 다음 메시지는 반복이 끝난 후 진행한다. OFF는 두 번째 재생도 중단하고 생성 요청/효과음/URL을 정리한다. 반복에 맞춰 작업 제한 시간을 확장해 두 번 읽기를 첫 회 제한으로 끊지 않는다.

검증: 기존 전체 Go race 시험과 반복 이관·저장·재시작·백업/응답 헤더/한 번 합성, 느린 합성보다 먼저 notice callback 발생·중복/꺼짐 무음 시험을 수행한다. 빠른 빈 조회 경로는 기존 관리자/작업자/커서/대량 알림 시험으로 추가 검증했다. Python9개 시험에는 2회 선택 시 생성1번·loops1·파일 정리가 포함된다. 브라우저는 설정2크기, 기존4엔진×관리자/공용×2크기16조합, 관리자/공용2회 반복, 합성 응답을 보류한 동안 효과음이 먼저 시작함, 생성1회/첫 반복 뒤 다음 job 대기, 중간 OFF를 검증한다. 실제 Google/Microsoft 합성이나 Windows 스피커의 물리적 타이밍을 재현한 시험은 아니다. Windows GUI 교차 빌드/vet 및 소스 ZIP 동일 EXE 재빌드로 배포를 확인한다.

과거 소스/버전 ZIP/web57개와 회사 자료는 보존한다. 전체 소스/Windows ZIP/체크섬/재빌드 증거를 기존 복구 브랜치에 보관한다. 실제 회사 설정·자료/사진/키는 업로드하지 않는다.
