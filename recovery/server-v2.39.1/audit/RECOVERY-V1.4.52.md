# v1.4.52 보관 삭제 후 사진 필요 복귀

문제: 관리자가 보관 기록을 삭제하면 현재 수주에 세팅·출하 완료 상태가 남아 있어도 사진 대기 기록이 함께 사라졌습니다.

- 현재 수주가 보이고 세팅·출하가 완료되었으며 같은 출하 검사 EventID인 경우, 삭제는 출하사진·메모·보관 완료 상태를 비우고 사진 필요 상태로 되돌립니다. 검사 상태, 작업자, 수주 스냅샷, 사급품 수령내역, 특이사항 사진은 유지합니다.
- 새 사진 대기 기록 ID를 발급해 삭제 전의 오래된 업로드 화면으로 재등록되는 것을 막습니다. 정상 등록은 새 사진 필요 목록에서 진행합니다.
- 해당 검사 완료 수주에 대한 사진 필요 기록 자체를 관리자 삭제로 없애지 못하도록 합니다.
- 현재 완료 수주가 없거나 다른 검사 주기의 옛 보관 자료는 기존의 완전 삭제 동작을 유지합니다.
- 이전 버전에서 이미 삭제한 기록은 관리자 출하 기록의 ‘사진 필요 목록 복구’ 목록에서 선택하거나, 해당 수주카드의 ‘출하사진 필요 복구’로 복구합니다. 기존 수주의 현재 정보로 사진 필요 기록만 생성하며 검사 완료 상태를 바꾸지 않습니다. 삭제된 사진이나 삭제 시점의 세부 자료를 복원한다고 주장하지 않습니다.
- 과거 완료 수주 전체를 자동으로 사진 대기로 바꾸지 않습니다. 복구는 관리자 명시 선택으로만 진행합니다.
- 저장 실패 시 상태와 사진을 유지하고, 저장 성공 후 더 이상 참조되지 않는 출하사진만 정리합니다. 특이사항 사진과 다른 자료의 참조는 유지합니다.

검증: 삭제→사진 필요→재등록·재시작, 실제 수주/검사 상태 불변, 특이사항 사진 보존, 이전 주기/원본 없는 자료 완전 삭제, 저장 실패 롤백, 관리자 인증/CSRF와 복구 중복 방지. 실제 임시 Go 서버와 Chromium PC/휴대폰 밝게·어둡게에서 관리자 삭제·작업자 조회·사진 재등록·누락 기록 복구12개를 확인합니다. 기존 기능의 변경하지 않은 목록/추가 사진/전송/재연결 검증은 v1.4.51 결과를 명확히 참조합니다.

Windows GUI 교차 빌드와 소스 ZIP 재빌드 일치를 확인합니다. 실제 회사 자료와 Windows GUI/DPAPI, 실물 휴대폰 실행은 확인하지 않았습니다. 기존 자료 저장 경로는 유지합니다. 전체 소스·Windows ZIP·소스 ZIP·검증 자료를 recovery-v2.39.1에 배포합니다.
