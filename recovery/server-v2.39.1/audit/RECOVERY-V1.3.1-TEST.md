# v1.3.1 엑셀 연결 검사 개선

신고 화면은 파일명이 저장됐지만 기존 기록 0건으로 보였다. 실제 XLSX와 PC 데이터는 제공받지 않았으므로 해당 파일의 원인은 확정하지 않았다. 코드에서 두 사실을 확인했다.

1. report-settings는 프로그램 완료 기록과 엑셀의 행을 연결하는 출력 병합 기능이다. 엑셀 행을 프로그램 수주/완료 상태로 가져오는 기능이 아니다. 프로그램 완료 기록이 없으면 0건이 정상적으로 나올 수 있으나 기존 UI가 이를 구분해 설명하지 않았다.
2. 기존 매칭은 수주번호/검사구분/완료일자/완료시간 문자열의 완전 일치를 요구했다. 날짜 서식이나 시각의 표시 정밀도가 다르면 같은 기록도 누락됐다.

workbook_match.go를 추가해 날짜/Excel 일련번호/시간/검사구분을 해석한다. 분까지만 주어진 시간은 프로그램에서 그 분에 해당 수주/검사 기록이 한 건일 때만 연결한다. 정확한 초가 다르면 연결하지 않는다. 같은 행에 둘 이상의 기록을 연결하거나 중복 행 중 하나를 추측하지 않는다. 1904 날짜 체계와 시간 셀에 전체 날짜/시각이 들어있는 경우도 처리하며 날짜/시간 날짜가 다르면 오류로 분류한다.

report-settings에 엑셀 행/프로그램 완료 기록/현재 일치/읽지 못한 행을 표시한다. 저장된 연결이 이미 있다면 수주 이름 등의 변경 때문에 현재 문자열 일치 수가 달라져도 기존 연결이 실패했다고 표시하지 않는다. 재검사 POST는 기존 Baseline을 유지하면서 새로 찾은 연결만 추가한다. 이미 취소된 기록의 행에 다른 ID를 재연결하지 않는다. 원본 업로드 bytes와 원본 회사 데이터는 수정하지 않는다.

workbook_match_test.go에서 날짜·시간·검사구분 표시, Excel 숫자·1904 날짜, 초 정밀도와 분 정밀도 충돌, 프로그램 기록 0건 안내/역방향 가져오기 없음, 재검사 후 수정 기준 유지와 CSRF를 검증한다. 브라우저에서는 v1.3으로 생성한 시험 파일을 서식 변경해 0건 연결을 재현한 뒤 같은 데이터 폴더를 v1.3.1로 열어 재업로드 없이 2건 연결/행 중복 없음/메모 보존을 확인했다. 실제 회사 자료/Windows 실행으로 확인한 것은 아니다.
