# v1.4.61 알파 설치형 웹앱(PWA)

고정 주소 /Tool/app/에 standalone manifest·192/512/maskable 아이콘·서비스워커·연결용 앱 화면을 추가합니다. 앱 시작 URL에는 작업장 키가 없으며 설치 전 해당 장치의 고정 출처 localStorage에 저장합니다. 최초 설치는 작업자 전체 메뉴의 ‘알파 앱 설치’로 연결합니다. 자동 설치 요청은 브라우저가 지원할 때만 표시하고 Chrome/삼성 인터넷/Safari 수동 홈 화면 추가 안내도 제공합니다. 사용자가 처음 한 번 설치해야 하며 OS가 닫힌 앱을 강제 실행하거나 APK를 자동 설치하지 않습니다.

고정 출처 안에서 유효 HTTPS trycloudflare 작업자 화면만 iframe으로 표시해 접속 주소 변경에도 설치 앱 범위를 유지합니다. 공개 작업장 경로에만 frame-ancestors를 고정 Pages origin으로 제한해 허용하고 관리자/로그인은 계속 차단합니다. 관리자 전환은 별도 창으로 엽니다. cross-origin postMessage는 부모 출처·창·작업장·nonce를 검증하며 임의 메시지로 갱신하지 않습니다.

앱의 작업장 키·토크 reader·작성자용 무작위 capability는 고정 출처에 저장됩니다. bootstrap의 URL fragment로만 전달하고 서버 쿼리/로그에 넣지 않습니다. HTTPS의 작업장/CSRF 검증 후 HttpOnly Secure SameSite=None Partitioned 쿠키를 설정해 Android Chrome의 제3자 쿠키 차단 환경에서도 앱 내 토크 작성/수정 권한이 유지되도록 합니다. 기존 일반 브라우저 Strict 쿠키는 유지합니다. 설치 앱은 별도 브라우저 저장 맥락으로 기존 일반 브라우저의 작성자 소유권을 자동 이관하지 않습니다. 서버 수주·사진·사급품·검사 데이터 저장 경로는 변경하지 않습니다.

작성/사진 선택/전송 및 검사 창 상태를 자식 화면이 알리고, 부모는 갱신 직전에 nonce 확인으로 안전 여부를 다시 확인합니다. 작업 중이면 그대로 유지하며 저장 후 새 문서에서 안전 응답을 받으면 최신 주소/버전을 적용합니다. iframe 안에서는 기존 전체 페이지용 주소 복구 서비스워커와 타이머를 새로 시작하지 않고 앱 부모가 연결을 관리합니다. 독립 브라우저의 기존 복구·저장 시 나가기 경고 생략 동작은 유지합니다.

앱 서비스워커는 자체9개 정적 자산만 캐시하고 서버 수주·게시글·사진 응답을 캐시하지 않습니다. 오프라인에서는 연결 안내 앱 화면을 열며 업무 데이터의 오프라인 작성/저장을 지원하지 않습니다. 대기 중 서비스워커 활성화와 화면 재시작도 자식의 안전 응답 후 진행합니다. 사진/작성 폼에는 변경을 강제 저장하거나 자동 제출하지 않습니다.

검증: 전체 Go 시험과 권한/쿠키/CSRF/프레임 범위 검증, 임시 실제 서버와 Chromium의 모바일/PC 앱 화면에서 토크 사진 작성 및 출하사진 저장, 미저장 상태의 주소 변경/서버 버전 변경 보류, 저장 후 전환, 주소 변경 후 작성자 유지, QR 없는 재실행, 설치 안내와 manifest, 실제 서비스워커 설치·자산 캐시·오프라인 앱 시작. HTTPS Pages/터널 네트워크는 시험에서 모의 프록시를 사용하며 실제 Android 시스템 설치 대화상자 및 Windows GUI를 실행하지는 않았습니다. 변경된 일반 브라우저 회귀(검사/비고/토크/사진 업로드 및 나가기 경고)를 재검증합니다. Linux/Windows vet·Windows 교차 빌드 및 소스 ZIP 동일 실행 파일 재빌드 증명을 포함합니다. 고정 앱 파일은 gh-pages의 app/에만 추가해 기존 QR·관리자·휴대폰 페이지를 보존합니다.

최종 검증 결과: 설치형 앱 흐름12개, 실제 서비스워커3개, 기존 작업자 전송52개, 전체 Go 시험 및 앱/작업장 권한 race 시험 통과. HTTPS 프록시의 리다이렉트는 시험 경계에서 HTML refresh로 모의 처리했고, 일반 브라우저 전송 시험은 실제303 응답을 사용했습니다. PWA 앱 자체의 waiting/activation 신호는 시험에서 모의하고 캐시/설치/claim은 별도 실제 서비스워커로 확인했습니다. 공용 작업자 페이지에서 파일 미리보기를 위해 blob: 이미지를 허용하며 관리자 페이지 CSP는 유지합니다. 실제 GitHub Pages 호스트는 실행 환경 프록시가403 CONNECT로 차단하여 기존 관리자 주소도 직접 접속하지 못합니다. Pages 브랜치와 공개 raw 자산 해시로 게시 파일을 확인합니다.
