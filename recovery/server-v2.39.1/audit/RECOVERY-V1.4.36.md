# v1.4.36 — 관리자 공지사항과 사진 첨부

관리자 전체 → 공지사항 관리에서 일반/긴급 공지를 등록·수정하거나 게시 종료할 수 있습니다. 제목 120자·본문 10,000자·사진 최대 5장(각 8MB, JPG/PNG/GIF/WebP)을 지원합니다. 기존 사진은 선택 삭제하고 새 사진을 추가할 수 있습니다. 게시 전 미리보기는 저장 요청 없이 브라우저에서 보여 줍니다.

작업자는 시장정보 아래·수주 검색 위에서 상단 공지를 확인하고, 전체 목록·내용·첨부 사진 확대를 볼 수 있습니다. 긴급 공지를 우선 정렬하고 상단에는 최신 순으로 최대 3건을 표시합니다. 상단 표시를 끈 게시물도 전체 공지 목록에는 남습니다. 게시 종료한 자료는 관리자에게만 남고 작업자 상세/사진 주소도 차단합니다. 공지가 없으면 작업 화면의 공지 영역은 숨깁니다. 15초 간격으로 변경을 확인하며 일시 네트워크 오류에는 기존 표시를 유지합니다. 검사 전 강제 확인이나 공지용 TTS/검사 이벤트는 추가하지 않았습니다.

## 저장과 호환성

기존 projects-v2.dat의 _RecoveredV1 상태에 선택적 Announcements 필드로 저장합니다. 공지가 없는 기존 상태는 자동으로 호환되며 원본 읽기 필드를 변경하지 않습니다. 첨부는 기존 protect/unprotect를 사용하는 photos 폴더에 저장합니다(Windows 현재 계정 보호). 공지 전용 저장은 기존 저널 저장·외부 변경 검증을 사용하면서 검사 엑셀을 다시 쓰거나 수주/검사 이벤트를 만들지 않습니다. 기존 암호화 백업의 파일 목록에 공지 첨부 사진을 포함하고, 공지만 있는 저장소에도 복원이 덮어쓰지 않도록 합니다. 공지 종료 시 기존 파일을 물리 삭제하지 않습니다.

관리자 쓰기는 기존 로그인·CSRF 검증을 통과해야 합니다. 작업자 조회는 기존 QR의 board capability로 제한하고 게시 중인 공지/사진만 제공합니다. 본문은 텍스트로 이스케이프해 표시하며 같은 공지의 충돌 편집은 revision으로 검출합니다. 수주 목록 필터·검사 승인/반려·엑셀/납기 동기화·음성·캘린더 집계와 기존 카드 CSS/JS는 그대로 유지합니다. 공지 메뉴 링크를 추가한 모바일 컨트롤러는 v1.4.36을 사용합니다.

## 검증

- 실제 HTTP 등록/수정/종료·이미지 업로드/다운로드, 관리자 미로그인/CSRF/작업자 쓰기 거부, 잘못된 board 차단, 제목/본문 이스케이프, stale revision 거부, 기존+추가 사진 5장 제한, 첨부 삭제를 검사했습니다.
- 공지 저장 전후 수주·검사 이벤트 및 엑셀 파일이 동일함을 확인했습니다. 재실행 후 보존과 암호화 백업 복원 후 사진 일치도 확인했습니다.
- 전체 Go race 테스트 및 Linux/Windows go vet, Windows amd64 GUI 교차 빌드, ZIP 무결성·원본 web 자산 57개 SHA-256, 소스 ZIP에서 동일 Windows 실행 파일 재빌드 검증.
- Chromium 36조합: 공지 12, 기존 카드 12, 오늘 납기 12. 밝게/어둡게·320/390/1100px·역할/기존 화면 조합으로 배치, 메뉴 진입, 상세, 사진 확대, 사진 폼/저장 없는 미리보기, 자동 갱신/게시 종료, 기존 디자인과 업무 액션/오늘 납기 완료 포함을 확인했습니다. 브라우저 사진은 합성 테스트 이미지입니다.
- Windows 실제 GUI·휴대폰 OS·회사 실자료/외부 백업 계정은 이 Linux 환경에서 실행하지 않았습니다. 저장/백업 검증에는 임시 합성 데이터와 테스트 복구키를 사용했습니다.

## 업데이트와 사용

회사 PC 프로그램을 트레이에서 완전히 종료한 뒤 새 ZIP의 AlphaWorkComplete-Recovered.exe를 실행하고 관리자/작업자 브라우저를 새로고침하세요. 기존 운영 자료/설정은 그대로 사용합니다. 일반 버전 업데이트에 테스트 승격 스크립트는 필요 없습니다.

관리자 전체 → 공지사항 관리 → 공지 등록에서 글과 사진을 입력하고 ‘작업자 화면 상단에 표시’ 및 ‘작업자에게 게시’를 선택해 등록하세요. 미리보기 후 등록할 수 있습니다. 작업자는 상단 카드 또는 전체 → 공지사항에서 봅니다. 전달이 끝나면 관리 목록에서 게시 종료하고, 필요하면 수정 화면에서 다시 게시할 수 있습니다.

전체 소스·실행 ZIP·소스 ZIP·검증 기록을 recovery-v2.39.1 브랜치에 추가하고 이전 버전은 보존합니다.
