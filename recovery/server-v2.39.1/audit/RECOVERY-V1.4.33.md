# v1.4.33 — 출고일정에서 연 검사창의 원래 위치 복귀

원인은 출고일정 버튼이 달력을 닫고 작업 메뉴로 전환한 뒤 검사창을 열지만 닫은 후의 출처를 보존하지 않았기 때문입니다. 이제 출고일정에서 열 때만 출처 URL·검색/필터·스크롤을 임시로 기억합니다. 검사창/특이사항 확인창이 모두 닫히면 기존 달력 인스턴스를 다시 열어 선택한 달·날짜·미정 보기와 스크롤로 돌아갑니다. 작업 메뉴에서 직접 연 검사창은 기존대로 작업 메뉴에 남습니다.

특이사항 취소·ESC, 검사창 닫기·ESC, 확인 후 검사창으로 이어지는 과정, 특이사항 없는 직접 검사, 날짜 미정 수주, 승인 후 폴링으로 검사창이 사라지는 경우를 지원합니다. 열기/복귀 때문에 방문기록을 추가하지 않으며 명시적 뒤로가기는 복귀 출처를 해제해 사용자의 이동을 방해하지 않습니다. 출고일정의 ‘목록으로’와 작업 메뉴 직접 진입은 기존 동작을 유지합니다.

출고일정에서 검사창을 연 뒤 작업 카드로 강제 스크롤하던 동작은 제거하고 실제 열린 검사창 입력에만 preventScroll로 초점을 줍니다. 기존 팝업 모드에서는 달력을 다시 열기 전에 원래 문서 위치로 이동하고, 다음 프레임에 내부 스크롤도 복원합니다. 특이사항 확인창이 검사창으로 이어지는 동안에는 복귀하지 않습니다. 원래 검색/필터도 복원합니다. 비고의 별도 페이지 접수, 검사 신청/승인/반려·녹색 완료·날짜/건수/연동 정책·음성·디자인·자료 형식은 변경하지 않습니다.

Go 실제 합성 수주(다음 달 5일의 특이사항 있는/없는 수주, 미정 수주)와 실제 승인 후 폴링 응답으로 Chromium 새/기존 디자인 × 밝게/어둡게 × 320/390/1100px 12조합을 검증했습니다. 모든 닫기 경로의 달/날짜/미정/URL/방문기록 길이/검색/필터/스크롤, 일반 작업창의 기존 닫기 동작, 승인 갱신 후 녹색/건수 유지를 확인합니다. 새 디자인에서는 뒤로가기를 선택한 뒤 닫아도 강제 복귀하지 않음을 확인합니다. 자동화 클릭 전 자체 스크롤과 구분하기 위해 원래 위치는 실제 DOM 클릭 캡처 시점에서 비교했습니다.

전체 Go race·Linux/Windows vet·Windows GUI 교차 빌드·전달 소스 ZIP 동일 실행파일 재빌드로 검증합니다. 별도 납기 파일 경로가 필요한 선택 시험은 미지정으로 건너뜁니다. 실제 회사 Windows·모바일 브라우저/하드웨어 뒤로가기·외부 서비스는 여기서 실행하지 않았습니다. 화면 캡처는 합성 자료입니다. 원본 57개 web 파일과 이전 버전 에셋/ZIP은 보존합니다.

기존 프로그램을 트레이에서 종료하고 새 EXE를 실행한 뒤 PC·휴대폰 화면을 새로고침하세요. 전체 소스·실행파일·검증 자료는 GitHub 복구 브랜치에 저장합니다. ERP 첨부파일·접속정보는 포함하지 않습니다.
