# v1.4.12 관리자 검사 화면 반려

최종 범위: 사용자는 PC 알림에는 반려가 필요 없다고 정정했다. desktop_windows.go의 버튼/클릭은 변경하지 않는다. 휴대폰 알림은 기존 고정 관리자/검사 경로를 연다. 관리자 검사 화면에만 단독/통합 반려 POST 폼을 추가한다. 기존 검사 완료 버튼은 기존 승인/저장/다음 단계 동작을 유지한다.

rejectInspection은 원자적 transaction에서 프로젝트/단계/pending/요청 ID와 실제 이벤트를 검증한다. 통합은 두 pending을 함께 반려하며 개별 반려를 막는다. 출하 반려는 세팅 완료 유지, 세팅/통합 반려는 세팅부터 재신청한다. 토큰/generation을 갱신해 오래된 신청을 재사용하지 못하게 한다. 새 신청은 새 EventID를 만들고 반려 안내를 지운다. 승인/반려가 동시에 들어오면 하나만 성공한다. 관리자 인증/CSRF는 기존 경계에서 유지하며 GET이나 알림 클릭만으로 처리하지 않는다.

Project.RejectedInspection, Event.Rejected/RejectedAt을 기존 파일의 정상 필드와 확장에 보존한다. 반려 Event는 pending/unread/완료 시각을 지우고 완료 엑셀/CSV/푸시에서 제외한다. 반려 시각/신청자/원래 메모는 이력으로 남기고 별도 이력 확인 화면을 제공한다. 이력 삭제가 다음 신청을 취소하지 않게 검증했다. 반려 후 작업자 카드와 열리는 신청창에 안내를 표시한다. 납기/특이사항/사급품/사진은 건드리지 않는다.

inspection_reject_test.go: 세팅/출하/통합, 재신청, 이전 토큰·요청 재사용 거부, 승인 기록 보존, 원본 필드/재실행, 인증/CSRF, 동시 승인·반려, 통합의 개별 반려 금지, 세팅만 승인한 통합의 출하 반려, 반려 이력 삭제와 새 신청 분리. browser-inspection-reject-v1.4.12.json은 Go handler가 만든 합성 화면과 모의 POST 응답으로 PC1100/휴대폰390px 폼/반려 안내/신청 가능 UI를 검증한다. HTTP 303 및 상태/인증은 서버 시험에서 별도로 검증한다.

첫 브라우저 모의 리디렉션은 검증용 reject.test의 실제 네트워크 이동이 개발 프록시에서 Domain forbidden으로 차단돼 실패했다. 모의 제출 결과를 Go 생성 화면으로 반환하도록 검증 도구만 고쳤다. 회사 프로그램이나 회사 자료 실패/변경을 의미하지 않는다. 실제 회사 계정/Windows/휴대폰 장비에는 도구로 접속·승인·반려하지 않았다.

기존 파일/버전 ZIP/원본 web57개는 보존하고 새 전체 소스/실행 ZIP과 재빌드 해시 기록을 함께 업로드한다. 소스 보관과 실제 회사 데이터 백업은 별개다.
