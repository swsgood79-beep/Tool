# v1.4.49 출하사진·수주 보관함

관리자 출하검사 완료 → 출하사진 필요 → 작업자 사진 1~20장 등록 → 완료·보관. 검사 요청·반려와 납기표의 수주 표시 기준은 유지합니다. 출하검사를 새로 승인하는 수주부터 적용하며 과거 완료 수주의 상태를 바꾸지 않습니다.

- 검사 완료 거래와 독립적인 수주 정보·특이사항 사진 복사본·사급품 수령내역을 같은 저장 작업에서 보관합니다. 저장 실패 시 새 사진을 정리하고 완료 처리하지 않습니다.
- 작업 메뉴에 사진 필요 수량과 목록, 출고 일정 상단에 보관함 탭을 추가합니다. 간결한 청록색 테두리 목록에서 검색 후 상세 내용을 볼 수 있습니다.
- 폰 촬영·앨범 선택을 합산해 최대 20장. 1장 이상 필수. 8MB/장 제한, 서버에서 1600px JPEG로 축소하고 기존 사진 보호 방식으로 저장합니다. D 드라이브로 자료 위치를 설정했다면 해당 경로를 그대로 사용합니다.
- 납기표 삭제 후에도 사진 대기·보관 자료를 유지하며, 세팅/출하 작업자와 날짜·설계담당자/전화·사급품 색상·수령내역·특이사항을 당시 내용으로 조회합니다.
- 관리자에게만 보관 자료 삭제를 허용합니다. 원본 수주를 삭제하지 않으며 참조되지 않는 첨부파일만 정리합니다. 암호화 백업에 새 기록과 사진을 포함합니다. 기존 백업 용량 상한은 256MB입니다.
- 정상 사진 등록 POST에는 나가기 경고를 띄우지 않으며, 실제 미저장 입력 이탈 보호와 기존 검사·비고·토크 동작을 유지합니다. 자동 재연결은 새 보관함의 조회 경로도 지원하고 쓰기 요청을 재시도하지 않습니다.

검증: 임시 Go 서버·Chromium 휴대폰/PC 및 밝게/어둡게 UI, 저장/검색/사진 검증, 원본 수주 제거 후 보관, 재시작과 백업 복원, 잘못된 사진·0/20/21장·중복 제출·저장 실패·접근 권한 검증. 정확한 결과는 같은 버전의 JSON 및 테스트 로그에 기록합니다.

실제 회사 자료와 Windows GUI/DPAPI·실물 휴대폰은 실행 검증하지 않았습니다. GitHub의 recovery-v2.39.1 브랜치에 전체 소스와 Windows·소스 ZIP을 함께 배포합니다.
