# v1.4.79 / APK 1.0.11 · 앱 업데이트 다운로드

사용자는 업데이트 동의 후 다운로드가 시작되지 않고 앱을 여러 번 다시 열어야 진행된다고 보고했습니다. 실제 휴대폰 로그는 확보하지 못했습니다. 기존 코드를 확인한 결과 다운로드 시작 자체가 safeUpdate gate 뒤에 있어 로그인·입력/저장 중이면 요청을 버렸고, 전송 실패는 한 번의 Toast 외에 재시도/진행 상태/요청 복구가 없었습니다. 이 코드 경로가 관찰 증상을 만들 수 있음을 원인 후보로 확인했습니다.

동의 직후 다운로드는 독립 스레드에서 즉시 시작하고, 설치만 UpdateInstallQueue에 보존해 foreground·로그인·작업 상태를 확인한 후 실행합니다. 진행률과 실패/재시도 버튼, 최대3회 전송 재시도, 닫아도 계속되는 진행창을 추가했습니다. 전체 앱 로그인 capability, Role, FCM 채널/토큰과 알림 설정은 변경하지 않습니다. 같은 com.alpharobotics.admin 패키지/기존 서명을 유지합니다.

개별 임시 파일과 프로세스 공통 전송 플래그를 사용하고 동의한 요청/완료 파일을 private cache에 보관합니다. Activity 재생성·재실행 시 metadata를 확인하고 완료 파일은 SHA-256/package/version/현재 설치 서명으로 재검증합니다. OS가 프로세스를 죽인 미완료 작업은 다음 실행에 다시 다운로드합니다. Android가 캐시를 제거하면 다시 받습니다. 설치 취소/‘나중에’ 후에는 수동 앱 업데이트 확인으로 재개합니다. 설치 허용 설정 복귀를 처리하며, 자동 무인 설치나 Android 설치 확인 우회는 하지 않습니다.

검증: 기존30개 + 전송8개/설치대기3개 = Android JUnit41개, release/lint 오류0·경고4(기존 JS 활성화/문자열 경고와 진행 문구 번역 경고), 동일 APK 서명. 전송 시험은 503·타임아웃·잘린 응답·해시 불일치·404·32MiB 초과·부분 파일 정리와 정상 재시도/진행 상태를 모의 HttpURLConnection으로 실행합니다. 설치대기 시험은 로그인/작업 busy·background 상태에서 동작을 잃지 않고 idle에 한 번 실행하는 것을 확인합니다. 전체 Go, Linux/Windows vet·Windows GUI 빌드, 원본 web57개 해시·소스 ZIP 동일 EXE 재빌드·공개 파일 SHA-256 확인. PC 서버 변경은 버전/현재 APK 링크만이며 업무/구매팀/인증 서버는 v1.4.78 참조 시험을 유지합니다.

제한: 실제 Android Activity·시스템 설치기·권한 설정·백그라운드/프로세스 종료·삼성폰 네트워크는 이 환경에서 실행하지 않았습니다. 실제 사용자 증상의 단일 원인을 확정하지 않습니다. 회사 운영자료/개인키는 패키지에서 제외합니다. PC v1.4.78을 쓰는 사용자는 앱 수정만을 위해 PC를 교체할 필요가 없습니다.
