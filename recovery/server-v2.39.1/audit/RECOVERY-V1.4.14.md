# v1.4.14 전자녀 스타일 브라우저 음성

사용자는 최종 확인에서 ‘기존 검사 신청·비고 알림만 읽기’를 선택했다. 검사 완료 알림은 추가하지 않는다. Go/Win32 서버와 JS 관리자 화면이므로 Python/edge-tts를 설치하지 않는다. 원본 web 57개는 그대로 두고 런타임 HTML 주입과 extras JS/CSS로 관리자 홈·검사 대기·검사 화면·미확인/기록 편집에 음성 도구를 제공한다. 작업자 화면에는 관리자 음성 도구나 CSRF를 노출하지 않는다.

JS 음성 선택은 Google 한국의 → Microsoft SunHi Online (Natural) → Microsoft Heami 이름 우선이며 지역 접미사가 있는 이름도 인식한다. 다음으로 lang=ko 계열을 사용하며, 목록이 아직 비어 있으면 utterance.lang=ko-KR로 브라우저 기본 선택에 맡긴다. 각 문장을 읽을 때 최신 getVoices()를 조회해 뒤늦게 등록된 음성도 반영한다. rate=1.1/pitch=1.0/volume=1을 모든 발화에 적용한다. 브라우저에 없는 음성을 설치/생성하거나 위플랩 ‘전자녀’와 동일한 목소리를 보장하지 않는다. 온라인 음성은 브라우저의 제공사 연결을 사용할 수 있으며 서버에서 TTS API 키나 유료 호출을 추가하지 않았다.

신청/비고는 공통 inspectionSpeech 포맷을 사용해 ‘홍길동님이 프로젝트의 세팅 및 출하 통합검사를 신청했습니다.’, ‘김작업님이 프로젝트 비고 메시지를 남겼습니다. 내용’으로 읽는다. 기존 PC 기본 음성도 동일한 문장과 비고 읽기를 지원한다. 이름/프로젝트/긴 비고의 음성 길이 제한만 적용하고 업무 내용은 수정하지 않는다. 긴 비고는 300자와 화면 확인 안내를 읽는다. SSML/HTML/실행 코드로 해석하지 않는다.

버튼 클릭 안에서 AudioContext.resume(), speechSynthesis.resume()/speak()를 호출한다. 실제 알림에는 WebAudio 두 음 효과음 후 단일 FIFO로 발화하며, onend/onerror와 제한 시간으로 진행한다. OFF/pagehide는 현재 발화, 효과음, 대기, 폴링을 취소한다. 같은 event ID는 한 번만 읽는다. 켜기 전 미확인 신청은 기준 커서로 제외하고 새 신청부터 읽는다. 같은 회사 PC 로컬 관리자 창은 서버의 9초 임대(3초 갱신)로 한 창만 읽고, 외부 장치는 장치별 한 창을 선택한다. 네트워크/인증 실패는 발화를 취소하고 상태로 안내하며 재연결 시 과거 알림을 몰아서 읽지 않는다. 브라우저 종료/정지/잠금에서 항상 배경 음성을 보장하지 않는다.

POST /admin-speech/poll은 기존 관리자 인증·CSRF·Origin/Host 경계를 그대로 따른다. 정렬된 기존 unread/pending-or-note 이벤트만 반환하고 통합 Batch의 대표 한 건만 반환한다. 완료/반려는 제외한다. 256개 초과는 커서를 나누어 다음 요청에서 계속 가져오며 수주/검사/읽음 상태는 변경하지 않는다. 잘못된 소유자/장치 ID를 거절한다. 임대는 런타임에만 보관하고 만료 항목을 정리한다. 같은 PC의 명시적 ‘웹 음성 켜기’ 요청(select_browser=1)은 기존 DesktopSpeechMuted=true를 저장한다. 따라서 웹 OFF 뒤 옛 Windows 목소리가 다시 나오는 일이 없으며, 사용자가 Windows 기본 음성을 명시적으로 다시 켤 수 있다. 일반 갱신은 음성 설정을 다시 쓰지 않는다. 외부/휴대폰은 회사 PC 기본 음성을 끄지 않는다. 로컬 임대가 활성인 동안 Native enqueue/refresh에서도 음성을 멈추고 중복 ID를 기록한다.

검증: browser_speech_test.go는 관리자 인증/CSRF, 단독·통합/비고 포맷, 최신 프로젝트명, 완료/반려 제외, 커서·대량 알림, 사업 데이터 불변, 화면 노출 범위, 임대 단일 소유/해제/만료, 원격-PC 분리, 명시적 웹 선택/끄기/재시작 음성 설정 보존을 검증한다. desktop_speech_test.go의 기존 순차 처리/취소/재시작 시험도 새 문장과 비고에 맞춰 유지한다. 전체 go test -race, Linux/Windows vet, Windows GUI 교차 빌드를 수행한다.

browser-electron-speech-v1.4.14.cjs/json은 Go handler가 만든 합성 관리자 화면에 모의 인증 API·SpeechSynthesis·AudioContext를 연결해 네 음성 우선순위 × PC1100/휴대폰390px 총 8개 조합을 검증한다. rate/pitch/lang, 실제 클릭의 userActivation 안에서 시작한 호출, 띵똥 주파수/발화 순서, 비고/신청 FIFO, 중복 제거, 중도 끄기, 화면 넘침, 지연 등록 음성, 다른 창 대기/인수, 인증 실패 중단을 확인한다. 첫 샌드박스 Chromium 실행은 시스템 socket 제한으로 실패했고, 허용된 외부 실행에서 검증했다. 실제 사이트/회사 계정으로 업무 처리를 하지 않았다.

실제 Google/SunHi/Heami 음성의 가용성·음색·속도 체감, Windows 스피커/브라우저 음성 서비스, 회사 보안 정책 및 삼성 인터넷 잠금 화면은 이 환경에서 검증하지 못했다. 모의 음성 검증은 소리를 들었다는 의미가 아니다. 설치 후 해당 브라우저의 미리듣기로 확인해야 한다.

완성된 전체 소스/Windows ZIP/체크섬과 소스 ZIP에서 동일 EXE 재빌드 기록을 복구 브랜치에 보관한다. 기존 자료/버전 ZIP은 삭제하지 않는다. 실제 회사 데이터/비밀키/사진은 업로드하지 않으며 소스 보관과 업무 데이터 백업은 별개다.
