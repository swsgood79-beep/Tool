# v1.4.20 — PC 음성 테스트 충돌 및 오류 표시 수정

## 재현 및 수정

회사 PC의 음성 ON 설정이 저장되어 있어도 같은 PC 브라우저에 활성 음성 lease가 있으면 Win32 음성 큐는 꺼지고 `/tts-settings/test`는 HTTP409를 반환했습니다. 설정 페이지는 POST 오류를 표시한 뒤 1초 상태 폴링으로 `음성 알림 꺼짐`을 덮어써, 사용자가 원인을 볼 수 없었습니다. 해당 조건을 서버 시험으로 재현했습니다. 실제 사용자 PC의 lease와 음성 엔진 실패 여부를 원격으로 확인한 것은 아닙니다.

이제 PC 음성 ON의 성공적인 저장은 로컬 브라우저 lease를 해제하고 PC 프로그램 재생을 선택합니다. 기존 탭·대기 탭의 단순 갱신은 다시 가져갈 수 없습니다. 브라우저의 명시적인 ON 클릭은 다시 브라우저를 선택할 수 있고, 공용 화면의 해당 클릭은 관리자 설정 파일을 바꾸지 않습니다. 다른 PC/휴대폰의 음성은 유지됩니다. Windows 시작 시 저장된 PC ON 설정에 따라 PC 재생을 선택합니다.

브라우저는 PC 선택 응답을 받으면 해당 PC의 재생을 멈추고 위치를 안내합니다. 설정의 요청 오류는 다음 테스트 시도까지 유지되고, 서버 ON/OFF 상태를 동기화하며 요청/상태 확인에 제한 시간을 둡니다. 음성 엔진·읽는 문장·속도·1/2회 반복 및 v1.4.19 특이사항 확인은 유지합니다. 다른 목소리로 몰래 대체하지 않습니다.

## 검증

- 전체 Go race 검사 통과. 별도 업로드 납기표 경로가 필요한 선택 검사 1건은 경로 미지정으로 건너뛰었습니다.
- 로컬 브라우저 충돌 재현, PC ON 후 선택된 선희/1.05배속 미리듣기가 네이티브 큐까지 도달, 이전/대기 탭의 재탈취 방지, 잘못된 설정의 전환 방지 확인.
- Chromium PC/모바일 설정에서 POST 오류가 OFF 폴링 후에도 표시되고 재시도로 해제됨, 서버 상태 동기화 확인.
- 4개 엔진 × 관리자/공용 × PC/모바일 16가지 음성 UI, 대기열·취소·반복·즉시 알림음, PC 전환 시 브라우저 정지, 대기 탭의 자동 재선택 방지를 가짜 오디오/합성 응답으로 확인.
- Linux/Windows vet 및 Windows GUI 교차 빌드. 실제 회사 PC 스피커, Windows 런타임 실행, 라이브 Google/Microsoft 응답은 여기서 확인하지 못했습니다.

## 업데이트

기존 프로그램을 트레이의 종료로 완전히 종료하고 새 EXE를 실행합니다. 회사 PC에서 열려 있던 관리자/작업자 브라우저를 새로고침합니다. ‘음성 설정·테스트’에서 ON을 체크하고 기존 선택 목소리로 테스트합니다. 인터넷/엔진 오류가 있으면 이제 상태에 표시되는 원인을 확인합니다. 데이터 폴더나 tts_config.json을 삭제할 필요가 없습니다.
