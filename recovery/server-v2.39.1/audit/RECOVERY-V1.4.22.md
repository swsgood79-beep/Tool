# v1.4.22 — 브라우저 음성 알림 기본 ON

관리자·작업자 브라우저의 음성 기본 상태를 ON으로 변경합니다. 먼저 자동 재생을 시도하고, 브라우저 정책으로 막히면 ‘음성 알림 켜짐 · 화면을 한 번 눌러 주세요’로 대기합니다. 별도 켜기 버튼을 다시 누르지 않아도 일반적인 화면 터치/키 입력에서 같은 오디오 요소와 WebAudio를 활성화합니다. 소리가 실제로 허용되기 전에는 서버 음성 lease를 받지 않아 PC 프로그램 재생을 중단하지 않습니다.

브라우저의 명시적 OFF는 localStorage `alpha-speech-browser-enabled-v1=off`에 저장하고, 다음 접속에도 유지합니다. 명시적 ON은 `on`으로 저장합니다. 페이지 종료·새로고침·PC 음성으로 양보하는 내부 정리는 OFF 선택으로 저장하지 않습니다. 관리자/작업자 탭 사이의 설정 변경을 동기화합니다. 과거 알림이나 테스트 문장을 자동 시작 시 읽지 않으며 새 신청부터 읽습니다. 사용자가 켜기/미리듣기를 직접 누르는 기존 테스트 동작은 유지합니다.

PC 프로그램의 기존 기본 ON 및 사용자가 저장한 OFF 설정, 목소리·속도·반복 값은 그대로 유지합니다. 자동 브라우저 시작은 `select_browser=0`으로 PC 설정 파일을 끄거나 기존 PC 재생 권한을 빼앗지 않습니다. PC가 이미 맡고 있으면 ‘음성 알림 켜짐 · PC 프로그램에서 재생’과 명시적 브라우저 전환 버튼을 표시합니다. 수주·검사·반려·비고·권한·새 디자인 미리보기 기능에는 변경이 없습니다.

검증: 전체 Go race 검사, Linux/Windows vet, Windows GUI 교차 빌드. 합성 HTML과 미디어 모의로 관리자/공용 화면 기본 ON·신규 알림·OFF 기억·새로고침 유지·첫 터치 활성화·권한 획득 전 lease 미발급·기존 PC 우선순위 및 4엔진/2역할/2화면폭의 기존 대기열·취소·반복 검증. 실제 Chromium HTMLAudioElement/WebAudio에 `document-user-activation-required` 정책을 적용하여 최초 차단과 일반 입력창 터치 후 활성화를 별도로 확인했습니다. 실제 Windows/삼성 인터넷의 스피커 출력이나 잠금/백그라운드 상태를 검증하거나 보장하는 것은 아닙니다. 별도 납기표 입력 경로가 필요한 선택 검사 1건은 경로 미지정으로 건너뛰었습니다.

업데이트: 기존 프로그램을 트레이에서 완전히 종료한 뒤 새 EXE를 실행하고 열려 있는 웹 화면을 새로고침합니다. 브라우저가 소리를 막으면 화면을 한 번 터치합니다. 새 디자인에서는 음성 도구가 하단 ‘전체’ 메뉴에 있습니다. 데이터 폴더·설정 파일을 삭제할 필요가 없습니다.
