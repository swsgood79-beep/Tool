# v1.4.54 검사자별 개별 로그인

승인한 로그인/계정 관리 시안에 맞춰 동료 계정을 추가합니다. 기존 관리자는 기존 비밀번호·패스키·네이티브 일회용 티켓 로그인을 유지하며, 기존 자료에 새 아이디를 강제로 지정하지 않습니다. 계정이 생기면 일반 로그인은 아이디·비밀번호를 표시하고 ‘기존 관리자 로그인’ 링크로 종전 비밀번호 로그인을 선택할 수 있습니다. 최초 설정과 기존 비밀번호만 보내는 호환 요청도 유지합니다.

- State.AdminAccounts 선택 확장 필드에 이름·소문자 아이디·활성 상태·리비전·bcrypt12 해시를 저장합니다. 비밀번호 원문을 저장/표시하지 않고 별도 자료 폴더나 C드라이브 데이터베이스를 만들지 않습니다. 기존 직접 저장 확장과 age 암호화 백업/복원에 포함합니다.
- 기존 관리자만 계정 생성·재설정·중지/재개를 관리합니다. 동료는 자기 비밀번호를 변경할 수 있습니다. 계정별 해시가 기존 관리자 PasswordHash를 덮어쓰지 않도록 이전 PBKDF2 관리자 마이그레이션과 분리합니다.
- 세션은 계정 ID와 리비전을 보유하고 모든 관리자 인증에서 활성 상태와 리비전을 검증합니다. 비밀번호 변경/중지는 대상 계정의 모든 세션을 종료하며 다른 계정과 기존 관리자의 세션은 유지합니다. 자기 비밀번호 변경 시 현재 브라우저에는 새 세션을 발급합니다. 전역 원격접속 설정 저장·기존 관리자의 전체 로그아웃은 기존 동작을 유지합니다.
- 동료도 수주/검사/게시판/출하 기록 등 기존 업무를 사용합니다. 계정·원격접속·패스키 등록·연결/백업/자료 위치 등 시스템 설정은 기존 관리자만 사용할 수 있습니다. 개인 계정에는 패스키 등록을 추가하지 않으며 기존 관리자 패스키는 유지합니다. 세션을 참조하는 패스키 흐름도 유효 세션과 기존 관리자 여부를 검증해 개인 계정이 기존 관리자로 승격되지 못하게 합니다.
- 계정 관리 화면에는 비밀번호 해시를 전달하지 않고 안전한 계정 표시 정보만 사용합니다. CSRF, 로그인 nonce, 기존 로그인 횟수 제한과8시간 세션, 외부 관리자 접속 허용 스위치를 유지합니다.
- 검사 과정과 기존 수주/사진/보관/완료 취소 기능은 변경하지 않습니다. 개인별 검사 승인자 이력 기록은 추가하지 않습니다. 회사 PC가 꺼져도 접속하는 별도 호스팅 기능은 추가하지 않습니다.

검증: 기존 관리자·개인 계정 로그인, 잘못된/중지된 계정, 계정별 세션 분리와 중지/재설정/본인 비밀번호 변경, 기존 관리자 비밀번호 및 이전 해시 마이그레이션 보존, CSRF·예약/중복 아이디·오래된 수정/저장 실패, 비밀번호 원문/해시 UI 노출 방지, 재시작과 암호화 백업 복원, 외부 접속 허용 스위치. 실제 임시 Go 서버와 별도 Chromium 컨텍스트로 두 PC 역할을 만들어 계정 생성→동료 로그인→같은 검사 완료→비밀번호 변경/재설정/중지/재개를 PC·휴대폰 밝게/어둡게 및320px 화면에서 확인합니다. 기존 검사·비고·토크 전송52개도 현재 버전 화면에서 검증합니다. 변경하지 않은 출하 기록/재연결은 기존 버전의 검증을 명확히 참조합니다.

전체 Go race, Linux/Windows vet, Windows GUI 교차 빌드와 소스 ZIP 동일 EXE 재빌드 증명을 포함합니다. 실제 회사 자료·Windows GUI/DPAPI·실물 패스키 기기의 실행 검증은 하지 않았습니다. 전체 소스·Windows ZIP·소스 ZIP·검증 자료를 recovery-v2.39.1에 배포합니다.
