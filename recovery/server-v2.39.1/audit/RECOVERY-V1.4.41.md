# v1.4.41 — 검사 화면 명시적 버튼 진입·단계 표시 한 줄

카드 전체/제목의 클릭 및 제목의 버튼 역할·키보드 진입을 제거했습니다. 작업자 작업 메뉴와 출고일정의 카드에서는 기존 ‘검사 화면 열기’ 액션만 검사 화면/특이사항 확인을 엽니다. 기존 화면에서도 summary의 일반 클릭은 열지 않고 그 안의 기존 열기 문구만 작동합니다. 해당 문구에 role/button/tabindex와 Enter/Space 처리를 연결해 키보드 진입을 유지합니다. 창을 닫을 때 열기 액션으로 포커스를 돌립니다. 자동 갱신으로 교체된 카드에도 같은 규칙을 적용합니다.

새 디자인의 검사 단계 배지는 최대 폭을 제거하고 본문에 필요한 폭과 nowrap을 사용하여 ‘02 출하검사 확인 대기’, 세팅/통합 대기도 한 줄로 표시합니다. 담당자·사급품·특이사항·완료 녹색, 관리자 수정/펼침/숨김/삭제, 달력 검사창 복귀를 유지합니다. 서버 API·데이터 스키마·신청/승인/반려 처리에는 변경이 없습니다. 원본 web/57개도 그대로입니다.

자산은 mobile-design-v1.4.41.js, order-card-v1.4.41.css/js, worker-dialog-v1.4.41.js를 사용합니다. 토크 댓글 한 줄/삭제 오른쪽/둥근 아이콘과 브라우저 읽음 기록, D드라이브 경로 선택은 기존 버전을 유지합니다.

## 검증

- 실제 Go에서 출하검사 요청을 만든 pending 상태로 초기 화면 및 자동 갱신 fixture를 생성했습니다. 전체 Go race와 Linux/Windows go vet, Windows amd64 GUI 교차 빌드 통과.
- 명시적 진입 Chromium 12조합: 새/기존 화면 × 밝게/어둡게 ×320/390/1100px. 카드 배경/제목/상태/제목 키보드 진입은 무반응, 명시적 마우스/키보드 버튼은 특이사항/검사 창 진입, 긴 pending 배지 한 줄, 원래 일정 복귀, 갱신 후 동일 규칙을 확인했습니다. 카드 클릭/창 열기 자체에는 신청 POST가 발생하지 않음을 확인했습니다.
- 기존 카드 Chromium 12조합: 관리자·작업자 전화 링크/사급품 원본 색상/특이사항/수정·숨김·삭제/완료 녹색/갱신 검증.
- 달력 복귀 Chromium 12조합: 명시적 열기 버튼을 사용해 월/날짜/스크롤/검색/필터/히스토리 복원, 닫기/ESC/특이사항 취소·진행과 승인 갱신을 확인했습니다.
- 원본 자산 57개 SHA-256, ZIP 무결성, 소스 ZIP에서 동일 실행 파일 재빌드 확인.
- Windows 실제 실행·회사 실자료/휴대폰은 이 Linux 환경에서 확인하지 않았으며 합성 자료·Chromium 및 Windows 교차 빌드로 검증했습니다.
