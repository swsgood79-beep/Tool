# v1.4.15 회사 공용 작업자 화면의 신청 음성

공용 컴퓨터/노트북에서 작업자 화면을 열어 다른 휴대폰 작업자의 새 검사 신청을 듣게 한다. 별도 EXE 설치나 관리자 로그인은 필요 없다. 버튼 기본값은 꺼짐이며 공용 PC에서 직접 켜야 한다. 기존 QR/Pages/작업자 주소 체계는 변경하지 않고 서버 EXE 업데이트 후 화면 새로고침으로 적용한다.

원본 web57개는 그대로 보존한다. work.html 렌더 결과에 ‘🔊 공용 PC 신청 알림 켜기/끄기’, 미리듣기, 상태를 삽입한다. data-mode=shared, data-endpoint=/worker-speech/{board}, data-csrf={board}만 넘기며 관리자 CSRF/세션/연결 키를 전달하지 않는다. 공통 electron-speech-v1.4.15.js는 v1.4.14의 음성 우선순위/rate1.1/pitch1.0/직접 클릭 해제/띵똥/FIFO/취소/3초 폴링을 유지하고 모드별 URL/문구를 선택한다. 관리자 화면도 같은 새 버전 JS/CSS를 사용하며 기존 관리자 신청·비고 음성 동작을 유지한다.

worker()에서 board URL을 검증한 뒤 /worker-speech/{board}를 처리한다. POST만 허용하고 기존 작업장 토큰과 같은 csrf 본문을 요구한다. 기존 Origin/Host 검증, 요청 길이 제한은 그대로 따른다. 관리자 /admin-speech/poll은 계속 관리자 세션과 별도 CSRF가 필요하다. 공용 응답에는 새 pending 검사 신청의 이벤트 ID/작성자/음성 문장만 담고, 통합 대표 한 건만 반환한다. 관리자에게 보낸 IsNote 비고, 완료, 반려, 숨김/삭제 수주는 제외한다. 관리자가 알림을 읽어도 여전히 대기 중인 새 신청은 공용 화면에서 받을 수 있도록 이 경로에서는 Unread를 요구하지 않는다. 켜기 이전 기록은 기준 커서로 제외한다.

기존 speechPollReply에서 관리자/공용 정책을 구분하며 공통 임대/커서/순서/대량 처리 코드를 재사용한다. 주체는 관리자 CSRF 또는 작업장 토큰과 owner로 해시하며 다른 주체의 임대를 해제할 수 없다. 같은 브라우저의 여러 외부 창은 device별 한 창만 읽고, 관리자 PC 로컬과 별도 공용 컴퓨터는 각각 연결된다. 로컬 서버 PC에서 공용 작업자 창을 켜면 기존 local 임대로 음성 중복을 조정하지만, 공용 endpoint는 select_browser=1을 보내더라도 DesktopSpeechMuted 같은 관리자 설정을 저장하지 않는다. 수주/검사/읽음/비고/사진/납기 상태를 쓰지 않는다.

worker_speech_test.go는 관리자 없이 기준 연결, 휴대폰 신청 후 통합 한 건 전달, 관리자 선읽음 후 전달, 사적 비고/완료/반려/숨김/없는 수주 제외, 상태 불변, 잘못된 board/본문/방식/추가 경로 거절, 관리자 권한 획득 불가, 관리자 PC와 공용 PC 동시 수신, 같은 브라우저 중복 방지, 다른 주체의 임대 해제 불가를 합성/임시 자료로 검증한다. 기존 browser_speech_test.go는 새 공용 버튼이 관리자 CSRF를 노출하지 않음을 확인한다.

browser-electron-speech-v1.4.15.cjs/json은 Go 생성 합성 화면과 모의 API/음성 엔진으로 관리자 8조합(4음성 × 2크기), 공용 2조합(1100/390px)을 검증한다. 공용 버튼/별도 board endpoint/관리자 설정 요청 없음/다른 작업자 신청 문장/음성·속도·음높이/끄기/넘침을 확인한다. 관리자 기존 선택·대기열·늦은 음성 등록·오류 중단도 재검증한다. 전체 race 시험과 Linux/Windows vet/Windows GUI 교차 빌드를 수행한다. 실제 회사 컴퓨터의 스피커/설치된 목소리/브라우저 배경 재생을 확인한 것은 아니며 미리듣기가 필요하다.

공용 PC의 브라우저/화면을 열어두고 절전을 피해야 한다. 새 페이지를 열면 다시 켜기를 눌러야 하며 모바일 잠금 상태 음성이나 브라우저 자동 시작을 보장하지 않는다. 위플랩 음성의 동일성은 검증하지 않는다. 온라인 음성은 브라우저가 제공사에 합성 텍스트를 전달할 수 있다.

기존 소스/ZIP은 삭제하지 않는다. 전체 소스/실행 ZIP/체크섬/소스 ZIP에서 동일 EXE 재빌드 결과를 GitHub 복구 브랜치에 보관한다. 회사 실제 데이터/사진/키는 업로드하지 않으며 소스 보관과 업무 데이터 백업은 별개다.
