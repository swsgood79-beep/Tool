# v1.4.66 · 통합 로그인·앱 지문 잠금·즉시 작업자 진입

관리자 로그인은 아이디·비밀번호 입력 화면 하나로 통일합니다. 대표 관리자 아이디는 wssong이며 기존 State.PasswordHash와 권한을 그대로 사용합니다. 계정을 새로 추가하거나 저장된 비밀번호를 교체하지 않습니다. 추가된 개인 관리자 계정과 권한도 유지합니다. 관리 화면의 ‘기존 관리자/기존 로그인’ 표시는 관리자/wssong으로 바꿉니다. 신규 개인 계정에는 wssong을 예약하며, 이미 동일 이름 개인 계정이 있으면 각각의 비밀번호로 기존 권한만 사용합니다. 양쪽 비밀번호까지 같아 권한이 모호하면 로그인은 거절합니다. 기존 브라우저 패스키 API는 호환 목적으로 남지만 통합 로그인에는 웹 지문 링크를 표시하지 않습니다.

관리자 APK 1.0.2는 첫 비밀번호 로그인 후 저장된 앱 로그인 연결을 유지하며, 지문이 등록된 기기에서는 다음 앱 실행/백그라운드 복귀 시 Android 인증 창으로 앱을 엽니다. Android 28 이상은 시스템 BiometricPrompt, 26~27은 FingerprintManager를 사용합니다. 인증 성공 전에 업무 WebView와 세션 복원 호출을 차단하고 잠금 중 화면 캡처를 제한합니다. 취소·실패·알림 클릭은 잠금을 해제하지 않습니다. 사진/파일 선택에서 복귀할 때는 현재 작업을 유지합니다. 인증 정보는 앱 프로세스 메모리에만 유지하고 백그라운드 진입 시 다시 잠급니다. 기기 생체인증이 없거나 실패하면 비밀번호 로그인으로 전환할 수 있습니다. 이 전환은 기존 앱 연결을 해제하고 정상 서버 로그인을 다시 요구합니다. 지문 데이터와 비밀번호를 앱이나 회사 PC에 저장하지 않습니다. 이미 보관된 앱 로그인 비밀값은 기존 Android Keystore AES-GCM으로 보호합니다.

지문은 휴대폰의 등록된 생체인증을 통한 앱 잠금 해제이며, 계정 중지·비밀번호 변경 등 서버 검증을 대신하지 않습니다. 앱 ⋮에서 지문 잠금을 끄거나 다시 켤 수 있습니다. 앱 알림 서비스는 화면 잠금과 독립적으로 기존 Firebase 연결을 사용합니다. APK는 기존과 같은 서명키로 서명하며 덮어 설치 시 기존 앱 자료를 유지합니다. 앱은 웹 패스키 인증 경로가 브라우저로 나가지 않도록 차단합니다.

작업자 사이트는 EntryGate=false로 문 열림 화면과 entry-gate/entry-motion 스크립트를 응답에서 제거합니다. 기존 QR·북마크·PWA 진입으로도 즉시 수주목록이 표시되며 달력 최초 진입·검사·공지·토크 기능은 유지합니다. 원본 web 자산 57개는 수정하지 않았습니다.

검증: Go 전체 시험, 인증/역할/지속 로그인/푸시/작업자 진입 race, Linux/Windows vet, Windows GUI 교차 빌드 및 source ZIP 동일 재빌드. Chromium에서 통합 wssong/개인 계정 로그인과 권한, 직접 작업자 진입·밝게/어둡게 8항목, 기존 앱 업무 흐름 28항목 통과. Android release 빌드·JUnit 11개·Lint 오류 0개와 기존 서명 인증서 일치 확인. 실제 Android 지문 센서·시스템 대화상자·Firebase 실수신은 이 환경에서 시험하지 않았습니다. 사용자 Firebase 및 회사 자료에는 접속하거나 변경하지 않았습니다.

앱 내부 APK 업데이트: 고정 GitHub manifest를 앱 시작 및 사용 중 5분 간격으로 확인하고, 새 버전에서 사용자가 업데이트를 선택하면 다운로드합니다. 패키지·버전·SHA-256·설치된 앱과 동일 서명 인증서를 검사한 뒤 FileProvider URI로 Android 설치 확인 창을 엽니다. REQUEST_INSTALL_PACKAGES와 최초 사용자 출처 허용이 필요합니다. 자동 무인 설치는 하지 않습니다. 지문 잠금 중 또는 입력·저장 중 설치를 진행하지 않습니다. 실제 Android 설치 허용/설치 대화상자는 실기기에서 확인해야 합니다.
