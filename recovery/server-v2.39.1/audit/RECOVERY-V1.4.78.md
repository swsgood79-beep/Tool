# v1.4.78 / 공용 APK 1.0.10 · 구매팀 호출

사용자의 최종 지시에 따라 별도 구매팀 앱/패키지/업데이트 경로를 만들지 않았습니다. 기존 com.alpharobotics.admin 앱에 구매팀 역할을 추가하고 기존 Firebase/서비스 계정/서명을 재사용합니다. 계정 권한에 따라 관리자 화면과 구매팀 호출 전용 화면을 나눕니다. 새로운 구매팀 역할의 계정과 수신 담당자는 회사 대표 관리자가 설정해야 하며 회사 운영자료에 임의 계정을 만들지 않았습니다.

작업자 수주카드에 구매팀 호출 버튼을 추가했습니다. 이름 입력과 전송만 제공하고 종류/메모/작업자 내역은 만들지 않았습니다. 호출 당시 수주번호·제품명·접수시간·담당자 계정은 독립 스냅샷에 저장합니다. 전송 실패는 이름과 키를 유지합니다. 같은 작업자·수주·담당자의 미완료 중복 호출은 기존 건에 합치며, 별도 전송 키도 기록해 완료 직후의 응답 유실 재시도가 새 호출을 만들지 않도록 합니다.

구매팀은 본인에게 온 미완료 목록을 접수 순서대로 보고 ‘완료하고 다음 호출 보기’로 가장 오래된 미완료 건을 엽니다. 완료는 멱등이며 다른 기기의 중복 완료로 이력이 늘어나지 않습니다. 완료 내역은 접수 역순, 페이지당20건입니다. 원본 수주가 삭제되어도 호출 스냅샷은 유지합니다. 새 상태는 기존 자료의 _RecoveredV1에 함께 저장·백업합니다. 사진·검사·주문 상태를 변경하지 않습니다.

서버는 구매팀 세션을 전역 허용 경로로 제한하고 관리자 인증 함수에서도 다시 확인합니다. 메뉴 숨김/UA만으로 권한을 판단하지 않습니다. 구매팀의 검사/수주/업체/백업/계정 관리/작업자 보기 등 직접 GET/POST는 차단합니다. 본인 호출만 조회·완료할 수 있고 POST는 기존 CSRF·출처 검사 대상입니다. 계정 생성의 기본 권한과 기존 빈 Role은 관리자 의미를 유지합니다.

기존 관리자 FCM 루프는 구매팀 역할 기기를 제외하고 구매팀 루프가 지정 RecipientID·활성 계정·미완료·전송 위치를 검사합니다. 검사 이벤트 스트림에 구매 호출을 넣지 않아 관리자 PC/공용 PC/관리자 휴대폰에 구매 알림을 퍼뜨리지 않습니다. 실패 시 전송 위치를 넘기지 않고 재시도합니다. 앱은 purchasing_calls_v1 채널과 call_id 클릭 경로를 사용하며 기존 inspection_requests_v1 채널은 유지합니다. 지연 도착한 다른 계정/역할의 푸시는 RecipientPolicy로 걸러냅니다. 기존 앱의 기기별 로그인 grant·Keystore·복구·로그아웃 코드를 재사용합니다.
