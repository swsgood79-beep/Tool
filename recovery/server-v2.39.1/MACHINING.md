# 가공팀 · ERP 엑셀 작업목록 (PC 1.4.104)

## 처음 사용

1. 회사 PC를 1.4.104로 업데이트합니다. 관리자 Android APK 1.0.11은 유지합니다.
2. 대표 관리자 계정에서 **관리자 계정 관리 → 동료 계정 추가 → 가공팀 · 가공 전용**을 선택합니다. 실제 작업자별 이름과 아이디를 등록합니다. 여러 명이 같은 계정을 쓰면 기록에서 구분되지 않습니다.
3. 관리자 전체 메뉴의 **가공 작업 · 완료/입고 확인**을 엽니다. 직접 주소는 `/machining-admin`입니다.
4. **ERP 엑셀 가져오기**에서 구매관리 → 발주대비미입고현황 → 거래처 가공사업부를 조회해 내보낸 XLSX를 선택합니다. 이미 시험 도구가 저장한 XLSX도 사용할 수 있습니다.
5. 미리보기의 원본 행·작업 건수·수량을 확인하고 **확인 · 가공 작업목록에 반영**을 누릅니다.
6. 가공팀 직원이 기존 앱 또는 관리자 로그인 주소에서 자신의 계정으로 로그인합니다. 가공 전용 화면으로 연결됩니다. 기존 관리자·구매팀 화면 권한은 주어지지 않습니다. 기존 앱의 공통 메뉴 항목을 눌러도 다른 업무 자료에는 접근하지 못합니다.

이 버전은 **목록 가져오기와 작업 기록을 제공하는 첫 단계**입니다. ERP 화면의 거래처/날짜 조회 조건 설정, 주기적인 Excel 버튼 실행, 파일 자동 수집은 아직 연결하지 않습니다. 새 ERP 목록은 XLSX로 가져옵니다. ERP에 수주를 다시 타이핑하지 않아도 됩니다.

## 합산 규칙

- 필수 열: 입고예정일, 발주번호, 거래처, 수주번호, 프로젝트, 로봇품번, 품번, 품명, 수량, 입고수.
- 품명이 공백 제거·대소문자 비교 후 정확히 BASE인 행만 읽습니다. BASE FRAME/BASE JOINT BLOCK은 제외합니다. BASE 행의 거래처가 가공사업부가 아니면 전체 반영을 중단합니다.
- 발주번호 + 수주번호 + 가공품번별 합산입니다. 원본 중복 행도 실제 배분 수량으로 모두 더합니다. 원본 행번호·로봇품번·발주수량·입고수·납기를 별도로 보관합니다.
- 최초 작업 수량은 발주 수량 - ERP 입고수의 합계입니다. 수량은 음수가 아닌 정수여야 하며 발주 수량보다 큰 입고수는 거부합니다.
- 같은 파일을 다시 가져와도 추가하지 않습니다. 이후 보고서에서도 같은 작업의 시작/완료/입고 확인 기록을 초기화하지 않습니다.
- 시작 전 항목은 ERP 미입고 수량에 맞춰 갱신합니다. 시작 후 변경은 계획 수량을 덮어쓰지 않고 확인 표시를 띄웁니다. 이 프로그램에서 이미 확인한 ERP 입고 수량은 비교 시 차감합니다. 관리자가 수량을 수정하면 이전/변경 수량·작업자·시간을 이력에 남기며 시작·완료된 절단 수량 미만으로 줄이지 못합니다.
- 보고서에서 빠진 항목도 삭제하지 않습니다. 조회 기간/필터/입고 처리 등 원인을 구분할 수 없어 ‘최근 ERP 목록에서 제외됨 · 기록 유지’만 표시합니다. 누락만으로 입고 완료로 판정하지 않습니다.

## 휴대폰 작업

수주 카드를 누르면 표가 열립니다. 첫 칸에 로봇품번과 가공품번, 나머지 칸에 수량·절단·가공을 표시합니다.

각 공정에서 **시작 → 작업 수량 확인 → 완료** 순서입니다. 시작 때 일부 수량을 선택할 수 있습니다. 절단을 완료한 수량부터 가공을 시작할 수 있습니다. 공정별 한 번에 하나의 작업을 진행하며 해당 작업을 시작한 계정에서 완료합니다. 중복 터치/오래된 화면은 서버의 변경번호로 거부합니다. 입력한 작업자 이름이나 휴대폰 시간은 신뢰하지 않고 서버의 로그인 계정과 실제 저장 시간을 기록합니다.

오늘 시작하고 내일 완료하면 시작은 어제, 완료는 오늘로 각각 남습니다. 진행 중에는 시작 작업자·수량·날짜/시간이 표시됩니다. 두 날짜 사이를 실제 가동시간으로 계산하지 않습니다.

작업 기록은 프로그램 재시작과 기존 백업의 확장 상태에 포함됩니다. 작업자 이름을 이후 바꿔도 이미 남은 기록의 이름은 유지됩니다.

## 완료 전달 및 ERP 입고

관리자 가공 화면의 **입고 확인** 분류에 가공 완료된 미확인 수량을 표시합니다. 관리자 전체 메뉴에서도 미확인 수량을 30초마다 갱신합니다. 가공 작업목록은 열린 상태에서 15초마다 갱신합니다. 이 버전의 알림은 화면 내 표시이며 별도의 휴대폰 잠금화면/PC 소리 푸시 알림은 추가하지 않았습니다.

관리자가 ERP에서 직접 입고를 처리한 다음 **ERP 입고 처리 확인**을 누릅니다. 누른 관리자와 시간이 기록됩니다. 버튼 자체가 ERP 입고 자료를 변경하지는 않습니다. 부분 가공 완료마다 각각 확인합니다.

**작업 기록 엑셀용 CSV 받기**로 공정별 수량, 시작/완료 작업자와 시각, ERP 입고 확인자/시각을 내려받습니다. 시각은 한국 시간이며 초까지 내보냅니다. 가공 기록 화면은 ISO 관련 추적 자료를 제공하며 현장의 실제 공정·검사·문서 관리 절차도 함께 운영해야 합니다.

## 검증 범위

합산/중복/입고수 차감/오류 파일 거부, 공정 순서·일부 수량·타 작업자 완료 차단·실제 완료 시각, 보고서 누락 보존·재시작, 계정 권한·CSRF·기존 앱 영구 로그인 복원을 검증합니다. 실제 업로드된 보고서는 로컬에서 88 BASE행 → 54작업·155개를 확인했으며 회사 엑셀/개인 데이터는 공개 소스에 포함하지 않습니다.

Chromium에서 360/390/430px 밝게·어둡게 6개 화면, 절단/가공 부분 완료, 관리자 미리보기·중복 가져오기·입고 확인을 시험합니다. 실물 Windows GUI/Android/ERP 자동 수집 운영은 별도 확인이 필요합니다.

## 대표 관리자 가공팀 화면 보기

대표 관리자(wssong)는 `/machining-admin`의 **가공팀 화면 보기**를 누르면 `/machining?preview=1`에서 작업자와 같은 수주 카드·품목 표·진행 내역을 확인합니다. 이 화면의 시작 버튼은 비활성화되며 서버도 관리자 계정의 가공 시작/완료 요청을 거부합니다. 작업자 기록을 덮어쓰지 않습니다. 상단 **가공 관리로 돌아가기**로 기존 관리자 기능으로 복귀합니다. 가공팀 계정의 권한·로그인 동작은 유지합니다.
