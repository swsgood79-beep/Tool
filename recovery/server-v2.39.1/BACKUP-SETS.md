# 분할 백업과 새 PC 복원 · PC v1.4.88

## 저장 위치와 복구키

운영 수주·사진·동영상·첨부는 회사 PC의 지정된 자료 폴더에 그대로 있습니다. 백업은 설정된 GitHub Tool 저장소의 Releases → 암호화 복구 서버 백업(`alpha-recovered-backup-<BoxID>`)에 별도로 올립니다. 개발 소스 ZIP/PC 프로그램 배포와는 다른 Release입니다. 키는 올리지 않으며 기존 age X25519 복구키로 암호화합니다. **복구키 파일 만들기/다시 받기는 이미 있는 같은 키를 내려줍니다.** USB 등 다른 기기에 보관하고 실제 다른 키를 생성한 경우 예전 백업용 키도 보관해야 합니다.

## 백업 실행

기존 설정을 유지하며 자동 백업을 임의로 켜지 않습니다. 관리자 백업 화면에서 복구키 보관과 GitHub 연결을 확인하고 자동 백업 켜기 또는 지금 전체 백업을 사용합니다. 변경이 있으면 기존 자동 주기에 따라 실행합니다. 마지막 성공/자료 기준/시도, 전체 암호화 용량, 조각 수, 최근 실패 이유를 확인하세요. 화면의 전송 완료와 개발 소스 업로드는 회사 자료 백업 성공을 대신하지 않습니다.

전체 자료를 디스크 기반 ZIP→age 암호화 스트림으로 만들고 검증합니다. 200MiB(화면 안내 200MB) 단위로 암호문을 나누어 업로드하며 각 조각을 원격에서 다시 읽어 크기와 SHA256을 확인합니다. 완료 정보도 암호화해 임시 라벨로 올리고 다시 읽어 확인한 뒤에만 완료 라벨로 바꿉니다. 복원 목록에는 완료 백업 세트와 이전 단일 백업만 표시합니다. 조각을 사용자가 직접 합칠 필요가 없습니다.

실패 시 직전 정상 백업을 유지하고 새 미완료 파일만 가능한 범위에서 정리합니다. 정리 연결까지 실패한 미완료 파일은 정상 세트로 표시하지 않습니다. 모든 검증과 성공 정보 저장이 끝난 뒤 최근 정상 3세트를 남깁니다. 원래 프로그램의 백업 Release/alpha-verified-v1 사본은 삭제하지 않습니다. 새 백업은 초기 설정·백업 용량과 인터넷 속도에 따라 시간이 걸립니다. 개별 요청은 20분, 전체 작업은 2시간의 응답 보호 기한을 두며 중단하면 다시 전체 백업합니다. 증분/중단 재개 기능은 이번 범위에 없습니다.

## 새 PC 복원

PC v1.4.88 이상에서 수주·검사·사진·계정/등록 기기가 없는 새 운영 자료로 시작합니다. 기존 회사 PC 프로그램을 종료하고 새 PC에서 인터넷 연결을 켜기 전, 백업 메뉴에 복구키와 필요시 GitHub 연결키를 입력하고 세대를 선택합니다. 분할 백업 또는 예전 단일 파일 백업을 받습니다. 옛 PC 버전은 새 분할 세트를 인식하지 못하므로 최신 PC 프로그램을 사용하세요.

필요한 모든 조각 존재·순서·길이·해시와 합친 암호문 해시를 검사하고, age/ZIP를 풀어 업무 메타데이터·사진·영상/파일 조각을 검증합니다. 하나라도 누락/손상되면 업무 자료를 적용하지 않습니다. 검증 후 새 Windows 계정에 맞게 보호해 저장합니다. 기존 업무가 있는 PC에 덮어쓰지 않습니다. 복원 완료 후 프로그램을 재시작하고 관리자 로그인·기존 QR·사진/파일 조회와 연결 상태를 확인하세요.

## 용량과 임시 공간

운영 백업의 전체 256MB 제한을 없애고 큰 데이터는 파일 스트림으로 처리합니다. RAM에는 전체 자료를 한꺼번에 올리지 않습니다. 임시 파일은 운영 자료 폴더에 만들고 작업 종료 시 정리하며 복호화·내부 검사 때문에 자료 크기의 여러 배에 해당하는 여유 디스크가 필요할 수 있습니다. 공간 부족·권한·연결 실패는 오류로 알리고 최신 성공 시각을 갱신하지 않습니다. 강제 종료/전원 장애가 있으면 임시 폴더가 남을 수 있습니다.

조각 200MiB, 누적 검증 1TiB, 항목 100만 개, 메타데이터 128MiB 및 기존 파일별 제한은 손상/압축 폭탄을 막는 안전 상한입니다. GitHub 서비스 정책과 실제 디스크/통신 환경 제약도 있습니다. 사진/첨부를 임의로 빼서 성공으로 표시하지 않습니다. 복원은 별도 검증용 디스크를 사용합니다. Windows DPAPI 보호 파일을 다른 계정에 직접 복사해 사용하는 것 대신 이 복원 절차를 사용합니다.

## 검증 범위

260MiB 무작위 합성 첨부를 실제 디스크 파일로 만들어 암호화한 260MiB 이상 백업을 두 조각+완료 인덱스로 전송 모의 서버에 저장하고 새 자료 폴더에서 복원해 원본 해시를 비교했습니다. 실패·손상·누락·완료 등록 실패·원본/이전 3세트 보존·API 페이지 조회·업무 화면 응답·기존 키 재다운로드·기존 단일 백업·race·PC/휴대폰 크기 Chromium 밝게/어둡게·전체 Go 검사 및 Windows 교차 빌드를 확인합니다. 실제 회사 운영 자료를 GitHub에 올리거나 새 Windows 계정 DPAPI 복원을 수행한 것은 아닙니다.
