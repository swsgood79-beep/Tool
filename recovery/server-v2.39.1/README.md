# 알파 검사 복구 서버 · 부분 구현

**원래 서버의 100% 복원본이 아닙니다.** 바이너리의 구조체·함수 정보와 추출 화면의 API 계약을 참고해 핵심 업무 흐름을 새로 구현했습니다. 운영 프로그램을 대체할 준비가 끝났다고 주장하지 않습니다.

이전 검증·내보내기 도구와 달리, 이 폴더는 실제 HTTP 서버이며 수주·신청·승인·기록을 파일에 저장합니다. 원본 v2.39.1의 실행파일과 자료는 보존했습니다.

## 실행

Windows 실행용 ZIP에서 `AlphaWorkRecoveredServer.exe`를 실행하세요. 브라우저가 자동으로 열리며 처음에는 **12~72자의 새 관리자 비밀번호**를 설정합니다.

- 관리자: `http://127.0.0.1:18791/`
- 작업자: 로그인한 관리자 화면 상단 **작업자 화면** 버튼. 같은 PC의 다른 브라우저에서도 이용할 수 있습니다.
- 서버 종료: 실행 창에서 `Ctrl+C`.
- 기본 자료 폴더: Windows의 `%AppData%\AlphaWorkRecoveredServer`.
- 자동 엑셀: 위 자료 폴더의 `검사완료기록-복구서버.xlsx`.
- 기존 프로그램의 자료를 자동으로 읽거나 덮어쓰지 않습니다. 이 복구판에서 새로 등록한 자료만 표시합니다.

이 버전은 같은 PC에서 기능을 비교하는 용도이며 로컬 주소만 허용합니다. 휴대폰·다른 노트북의 접속, 기존 QR, 외부 터널은 아직 지원하지 않습니다. Windows 파일 암호화(DPAPI)는 현재 Windows 계정에 종속되므로 다른 PC/계정에 파일만 복사하는 복원은 지원하지 않습니다. 원본 포맷·암호화 키와의 호환성은 구현되지 않았습니다. Linux 빌드는 검증용이며 파일 암호화가 적용되지 않습니다.

다른 자료 폴더나 포트를 쓰려면:

```powershell
.\AlphaWorkRecoveredServer.exe -data "D:\AlphaRecoveredTest" -listen 127.0.0.1:18793
```

**아직 구현하지 않은 기능:** 원본 자료 이관/포맷 호환, 지문·패스키, Windows 관리 창·트레이·네이티브 알림, 휴대폰 웹 푸시, Cloudflare/ngrok·고정 QR·Pages 중계, 토스/코인/환율, OneDrive 납기 동기화, 수주 엑셀 일괄등록, GitHub 암호화 백업·복원, 복원 저널·원본과 동일한 장애 복구 동작. 해당 설정 메뉴/API에는 미복원 안내를 표시합니다. 시세 값을 임의로 생성하지 않습니다.

삭제된 사진의 암호화 파일을 자동 청소하는 기능, 원본의 이미지 리사이즈·정지 이미지 변환도 아직 없습니다. 등록 정보에서 사진을 제거해도 파일이 보관될 수 있습니다. 자료를 많이 등록할 때의 부하·장애 동작은 원본과 동일하다고 검증되지 않았습니다.

## 원본 근거와 구현의 구분

- `web/` 57개 파일은 앞서 추출한 바이트 그대로입니다. 렌더링 시 비교판 안내·시장 API 미연동 문구 및 수동 납기 입력란만 추가합니다.
- `audit/main-functions.json`: `main.` 함수 711개. 표준·외부 패키지 함수 본문은 분석 목록에서 제외했습니다.
- `audit/main-struct-layouts.json`: Go 1.27 RTTI에서 확인한 사용자 정의 구조체 99개, 필드 611개. 타입·필드 태그·오프셋 보관.
- `audit/recovered-struct-declarations.go.txt`: 위 메타데이터의 선언 형식 출력. 메서드·임포트·전체 별칭이 없으므로 빌드 대상 소스가 아닙니다.
- `audit/frontend-contracts.json`: 57개 자산 전체를 순회한 폼 43개, URL 참조 198곳, 통신 호출 18곳의 위치와 코드 문맥. 동적 변수·템플릿 경로는 그대로 보관했습니다.
- `audit/API-CONTRACTS.md`: 확인된 프론트엔드 요청·응답과 실제 구현 범위.
- `audit/inspection-core-annotated.asm`: 원본의 단독·통합 승인 및 통합 신청 핸들러 어셈블리. 직접 호출을 심볼과 대조했습니다. 원본이 `commit`을 호출하는 흐름을 참고했으며, 모든 분기·상수·암호화 프로토콜의 동등성까지 증명한 것은 아닙니다.
- 실제 빌드 대상 `.go` 파일들은 **새 구현**입니다. 원본의 구조체 이름·바이너리 포맷 전체를 그대로 사용하지 않습니다.

## 빌드 및 시험

Go 1.27.3 이상, 외부 모듈 없음:

```sh
go test -race ./...
go vet ./...
go build -o recovered-server .
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o AlphaWorkRecoveredServer.exe .
```

PowerShell에서는 마지막 줄의 환경변수를 `$env:GOOS="windows"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"`으로 설정한 뒤 `go build`를 실행합니다.

시험 내용: 신청/승인 분리, 통합·부분 승인, 중복·오래된 요청 차단, 완료 취소, 재시작 유지, 로그인/로그아웃, 권한·CSRF·출처 검사, 저장 실패 롤백, 연결 원본 수정·삭제, 사진 업로드/조회, HTML 이스케이프, 엑셀 XML·열·완료 기록 포함 여부. 브라우저 시험은 초기 비밀번호 설정→수주 등록→로그인하지 않은 작업자의 통합 신청→관리자 승인→완료 작업자·캘린더 확인입니다.

Linux 서버와 Chromium에서 시험했습니다. Windows 실행파일은 교차 빌드했으며 **Windows에서 직접 실행하거나 DPAPI·브라우저 자동 열기를 실제 확인한 것은 아닙니다.** 빌드 성공과 원본의 기능 동등성은 별개입니다.
