# 알파 복구 서버 v1.0 · 직접 저장·Windows UI 구현판

원본 바이너리의 함수·RTTI·어셈블리와 57개 웹 자산을 근거로 다시 작성한 서버입니다. **원본 소스가 되살아난 것은 아니며, 원본과 100% 동일하다고 검증한 완성본도 아닙니다.** 이번 v1.0에서는 v0.2의 원본 직접 저장과 네이티브 Windows UI 미구현 부분을 추가했습니다.

## 실행

Windows ZIP을 풀고 `AlphaWorkRecoveredServer.exe`를 실행합니다. 이제 콘솔 대신 관리 창이 열립니다. ‘수주 · 메시지 관리’에서 관리자 웹 화면을 엽니다. 처음 실행 시 비밀번호를 설정하고, 기존 자료가 있으면 저장된 비밀번호를 사용합니다.

- 창의 X: 트레이에 숨깁니다. 프로그램과 휴대폰 접속은 유지됩니다.
- 트레이: 프로그램 열기, 안 읽은 알림 다시 보기, 관리자 화면, 프로그램 종료.
- 팝업: 최대 3개, 약 12초 후 사라집니다. 마우스를 올리면 타이머가 멈춥니다.
- 미확인 숫자: 메시지가 읽힐 때까지 남습니다. 누르면 팝업을 다시 보여주며, 오른쪽 클릭하면 전체 미확인 목록을 엽니다. 팝업 닫기·시간 만료만으로 읽음 처리하지 않습니다.
- 세팅·출하 통합 신청은 한 팝업으로 묶습니다. 팝업 본문을 누르면 해당 수주 검사 화면으로 연결합니다.
- 관리 창의 ‘인터넷 연결’, ‘고정 QR 설정’, ‘엑셀 폴더’도 연결했습니다.

기본 관리자 주소는 `http://127.0.0.1:18791/`입니다. PC 관리 버튼은 **PC 내부에서만 생성하는 1회용·1분 만료 티켓**을 사용합니다. 웹에서 이 티켓을 발급하는 공개 API는 없습니다. 휴대폰 로그인과 지문 검증은 기존 v0.2 방식을 유지합니다.

## 기존 자료와 직접 저장

**원본 프로그램을 종료하고 전체 자료 폴더를 별도 복사한 뒤 처음 실행하세요.** Windows 기본 자료 폴더는 `%AppData%\WanryoTalk`입니다. 해당 폴더에 원본 자료가 없고 이전 v0.2의 `%AppData%\AlphaWorkRecoveredServer\reconstructed-state.bin`이 있으면 그 폴더를 사용합니다. `-data`로 위치를 지정할 수도 있습니다.

```powershell
.\AlphaWorkRecoveredServer.exe -data "D:\AlphaRecoveredTest" -listen 127.0.0.1:18793
```

같은 Windows 계정의 DPAPI로 기존 데이터를 해독하고 다음 파일에 직접 읽고 씁니다.

| 파일 | 저장 내용 |
|---|---|
| `projects-v2.dat` | 원본 Version 14 수주·검사 단계·요청/완료/읽음 기록·납기·비밀번호·패스키·시세/일정 설정 |
| `designers-v1.dat` | 설계담당자 명단 |
| `client-notes-v1.dat` | 업체 특이사항·사진 메타데이터 |
| `connection-v1.dat` | 외부 접속·GitHub 설정 |
| `phone-push-v1.dat` | 휴대폰 구독·VAPID·전송 상태 |
| `backup-v1.dat` | 암호화 백업 설정·완료 정보 |
| `project-photos/{id}.dat` | DPAPI로 보호한 JPEG 사진 |

1. 기존 데이터 파일마다 **최초 `.bak`을 한 번만 생성**합니다. 이미 있는 `.bak`은 덮어쓰지 않고 해독 가능한 JSON인지 확인합니다. 백업 생성·검증에 실패하면 원본 직접 저장을 중단합니다. 기존 사진 파일은 덮어쓰지 않으며 새 사진은 새 ID를 사용합니다.
2. 원본 필드는 원본 JSON 형태로 갱신합니다. 기존 작업장 BoardToken·SigningKey와 알려지지 않은 최상위/수주/기록 필드도 보존합니다. 복구판의 폼 토큰 등 추가 상태는 **같은 `projects-v2.dat`의 `_RecoveredV1` 필드**에 넣습니다. 원본 Go JSON 판독기는 이 추가 필드를 무시할 수 있지만, 원본 실행 파일과의 실제 왕복 실행은 확인하지 못했습니다.
3. 새 `reconstructed-state.bin`을 만들거나 갱신하지 않습니다. 이전 검증판 파일은 백업 후 그대로 두고 원본 파일로 이관합니다. 원본과 이전 검증판이 독립적으로 변경되어 충돌하면 자동 병합하지 않고 중단합니다.
4. 여섯 파일은 준비 파일과 `.direct-write-journal.dat`로 묶어 저장합니다. 저장 완료 표시 전 종료되면 재시작 시 이전 바이트로 되돌리고, 완료 표시 후 종료되면 새 자료를 유지합니다. 현재 파일이나 복구용 이전 바이트가 예상과 다르면 중단하고 저널을 보존합니다. **프로세스 중단을 시험했으며 디스크 고장·전원 차단 내구성을 인증한 것은 아닙니다.**
5. 원본 앱이 확장 필드를 없애거나 원본 필드/보조 설정을 수정하면 다음 실행에서 원본 스키마를 다시 읽습니다. 실행 중 외부 파일 변경은 덮어쓰지 않습니다. 원본과 같은 Windows 단일 실행 뮤텍스도 사용합니다.
6. 새 비밀번호는 원본과 같은 bcrypt로 저장합니다. v0.1/v0.2 PBKDF2 비밀번호는 성공적인 비밀번호 로그인 후 bcrypt로 전환합니다. 전환 전에는 원본 형식의 모바일 비밀번호 슬롯을 비워 잘못된 인증 해시를 쓰지 않습니다.
7. 사진은 기존 JPEG를 그대로 사용하거나 PNG/WebP 등을 JPEG로 변환해 원본 사진 폴더에 넣습니다. 업체 원본 사진과 수주 사진은 독립 ID로 복사합니다. 원본 스키마의 수주당 사진 5장 한도를 넘으면 저장을 중단합니다. 변환 화질과 리사이즈가 원본과 정확히 같다는 보장은 없습니다.

`.bak`은 **최초 상태**입니다. 이후 기록까지 보관하려면 기존 암호화 자동 백업을 설정해야 합니다. 사진·복구 저널은 실패 원인 조사에 필요하므로 오류 발생 시 임의로 지우지 마세요. 새 PC에서는 Windows 계정 DPAPI가 달라지므로 폴더 복사만으로 해독되지 않을 수 있으며, PC 밖에 보관한 복구키와 암호화 백업으로 복원합니다.

## v0.2 연동 유지

- 인터넷·휴대폰: 설정에서 GitHub/고정 QR을 확인하고 인터넷 연결. Cloudflare 도구 해시 검증, 현재 서버 `/ready/{board}` 확인 후 포인터 게시. 개발 시험은 실제 운영 포인터를 변경하지 않습니다.
- Web Push·지문: 기존 VAPID 구독, 고정 Pages RP/Origin의 WebAuthn, UV·서명·카운터·일회용 흐름 검증. 모바일 실기기에서 등록/로그인/알림 수신은 별도 확인이 필요합니다.
- 시장 정보: 토스 지수·캔들 전일 종가·환율과 업비트. 키는 DPAPI 자료에 저장하며 작업자에게 보내지 않습니다. 실제 회사 IP 허용·키로 검증한 것은 아닙니다.
- 납기: OneDrive 공유 다운로드 또는 동기화 파일, 5분 갱신, 조립일정의 수주NO/발송예정일, 미정/ASAP와 충돌 구분. 첨부 일정표의 파서 시험만 했으며 실제 공유 권한은 확인이 필요합니다.
- GitHub 백업: age 암호화된 전체 백업, 다운로드·복호화 검증 후 성공 처리, 새 PC 복원. 복구키는 업로드하지 않습니다. 복구판 별도 Release를 사용하고 기존 원본 백업은 삭제하지 않습니다. 메모리 보호 상한은 256MB입니다.

상세한 기존 연동 근거는 `audit/RECOVERY-V0.2.md`, 이번 변경 근거·제한은 `audit/RECOVERY-V1.0.md`를 보세요. v0.1/v0.2 보고서는 당시 상태를 기록한 문서입니다.

## 검증과 남은 차이

Go 자동 시험에는 원본 스키마 직접 읽기·수정·재시작, 최초 백업 보존, 6개 파일 각각의 저장 중 중단/되돌리기, 완료 후 중단, 외부 변경·손상 방어, 사진 복사·JPEG, 이전 검증판 이관·bcrypt 전환, 네이티브 티켓 재사용 거부, Win32 x64 구조체 ABI, 기존 검사·푸시·패스키·연동 시험이 들어 있습니다. Chromium으로 관리자/작업자 신청·승인·완료 표시·캘린더와 설정 저장도 확인합니다.

**이 환경에서는 실제 Windows GUI/DPAPI 실행, 실제 회사 데이터·백업, 삼성 인터넷·잠금 알림과 실제 외부 계정 연동은 확인하지 못했습니다.** Windows EXE는 교차 빌드 및 정적 검사 결과입니다. 관리 창의 배치·아이콘·팝업 이동/페이드·소리·DPI/여러 모니터 동작이 원본과 똑같다고 보장하지 않습니다. PC 알림은 PowerShell 토스트에서 자체 Win32 창으로 교체했고 원본과 같은 Win32 API 계열을 사용합니다.

기존에 남아 있던 **ngrok 실행, 수주 엑셀 일괄등록, 원본 엑셀 파일·수정 내역의 직접 병합, 원본과 같은 사진 자동 청소와 대용량 백업 처리**는 이번 두 항목의 복원 범위에 포함되지 않았습니다. 따라서 v1.0이라는 배포 이름은 원본 100% 동일성 인증을 뜻하지 않습니다.

## 빌드

Go 1.27.3 이상에서 `go mod download` 후 `go test ./...`와 `go vet ./...`를 실행합니다. `build-windows.ps1` 또는 다음 명령으로 Windows x64 GUI를 빌드합니다.

```powershell
$env:GOOS='windows'; $env:GOARCH='amd64'; $env:CGO_ENABLED='0'
go build -trimpath -buildvcs=false -ldflags='-s -w -H=windowsgui' -o AlphaWorkRecoveredServer.exe .
```

Linux는 암호화를 적용하지 않는 시험용입니다. Windows `-headless -no-browser` 옵션은 GUI 없는 진단용 실행입니다. 전체 소스 ZIP에는 원본에서 추출한 웹 자산 57개가 포함되고, 회사 수주·사진·키·첨부 엑셀은 포함하지 않습니다.
