# 알파 복구 테스트판 v1.2 · 기존 프로그램과 분리

이번 ZIP은 기존 프로그램과 함께 켜서 확인하는 **격리 테스트판**입니다. 이전 v1.0 ZIP은 원본 폴더에 직접 저장하므로 테스트 용도로 사용하지 마세요. v1.0 파일은 이력 보존을 위해 남겨 두었습니다.

## 기존 회사 자료로 시험하기

1. 현재 실행 중인 **테스트판만** 트레이에서 종료합니다. 기존 운영 프로그램은 종료시키지 않습니다.
2. 새 ZIP을 압축 해제하고 **`copy-existing-data.cmd`**를 두 번 클릭합니다.
3. 같은 Windows 계정의 `%AppData%\WanryoTalk`에서 주요 데이터 파일과 `project-photos`를 **새 테스트 복사본**으로 가져온 뒤 테스트판이 열립니다. 수주·검사 기록·설계담당자·업체 특이사항·사진을 확인합니다.
4. ‘수주 · 메시지 관리’를 누르면 기존 자료에 저장된 관리자 비밀번호로 로그인합니다. 비밀번호가 없으면 테스트용 새 비밀번호를 설정합니다.
5. 관리자에서 수주를 수정하거나 작업자 화면에서 신청·승인해 보세요. 변경은 테스트 복사본에만 기록되며 원본으로 돌아가지 않습니다.
6. 다음부터는 **`continue-test.cmd` 또는 `AlphaWorkRecoveryTest.exe`**로 같은 복사본을 이어서 사용합니다. 원본의 최신 자료를 다시 가져오려면 테스트판을 종료하고 `copy-existing-data.cmd`를 다시 실행합니다. 이전 복사본과 예시 테스트 자료는 삭제하지 않습니다.

원본 파일은 읽기 전용으로 엽니다. 복사 전후 파일 목록·SHA-256과 복사된 바이트를 확인하며 원본 저장이 진행되어 자료가 바뀌면 중단하고 기존 테스트 복사본을 유지합니다. 이때 원본 저장이 끝난 뒤 다시 시도하세요. 복사에 실패하면 오류창이 뜨며 원본 파일은 수정하지 않습니다.

새 복사본은 `%AppData%\AlphaWorkRecoveryTest-v1.1\copies\copy-날짜-고유번호`에 생성합니다. 이전 시험판의 기본 폴더 이름은 그대로 유지합니다. `active-test-copy.json`은 다음 실행에 사용할 **테스트 폴더 이름만** 저장하며 운영 주소를 저장하지 않습니다. 복사본을 성공적으로 읽은 후에만 이 선택 정보를 바꿉니다.

복사 후 작업장 접근 키와 신청 폼 토큰은 시험용으로 새로 생성합니다. 접속 설정·키·외부 연동은 초기화하고 차단합니다. 기존 운영 QR·휴대폰 푸시·고정 관리자·GitHub 백업은 변경하지 않습니다. 원본의 별도 Documents 엑셀이나 수동 수정 이력은 가져오지 않으며, 복사된 검사 기록으로 테스트용 엑셀을 생성합니다.

**같은 Windows 계정에서 사용하세요.** Windows DPAPI 암호화 자료이므로 폴더를 다른 PC에 전달하거나 여기 업로드할 필요가 없습니다. `.cmd`는 같은 폴더의 `AlphaWorkRecoveryTest.exe`만 실행하며 다른 프로그램을 강제 종료하지 않습니다.

기존 자료를 가져오지 않고 처음 실행하면 예시 수주 TEST-001·TEST-002로 시작합니다. 접속 포트는 계속 **127.0.0.1:28791**, 창/트레이 이름은 ‘알파 복구 테스트판’이며 운영 자료 폴더를 `-data`로 지정하면 거부합니다.

## 외부 연동

기존 운영 서비스에 영향을 주지 않도록 이 시험판은 **외부 네트워크 전송을 차단**합니다. 운영 QR 접속 주소 게시·Cloudflare 터널·휴대폰 알림·모바일 관리자·고정 Pages 지문·GitHub 원격 백업을 사용하지 않습니다. 관련 메뉴에는 차단 안내가 표시됩니다. 시세나 OneDrive의 실제 조회도 하지 않습니다. 수동 로컬 일정 파일 읽기는 테스트 자료에만 반영합니다.

테스트 폴더에 저장된 외부 연동 설정은 시작 시 비워집니다. 운영 설정과 접속 키를 이 시험판에 넣을 필요가 없습니다. PC 자체 팝업은 외부 서버를 사용하지 않습니다.

## 기존 자료에 관하여

`%AppData%\WanryoTalk`에는 수주·기록·사진·설정 등 주요 데이터가 있지만 프로그램 소스 코드는 없습니다. DPAPI 파일은 같은 Windows 계정에서 읽어야 합니다. 접속 키가 있을 수 있으므로 폴더 전체를 채팅이나 GitHub에 올리지 마세요.

첫 실행 기본값은 별도 예시 데이터이며, `copy-existing-data.cmd`를 명시적으로 실행했을 때만 기존 자료를 복사합니다. 현재 원본 스키마 저장 구현은 테스트 폴더 안에서만 사용하며, 이전 v1.0의 ‘원본 직접 저장’ 설명은 운영 자료에 적용되지 않습니다. 이전 보고서는 `audit/RECOVERY-V1.0.md`에 이력으로 남아 있습니다.

## 검증과 제한

자동 시험으로 기존 자료 폴더 거부·원본 바이트 불변·테스트 재시작·독립 검사 신청/승인·별도 로그인 쿠키·외부 요청 차단을 확인합니다. Linux 로컬 동시 실행 및 브라우저 시험 결과와 Windows GUI 교차 빌드 결과는 `audit/build-manifest-v1.1-test.json`을 확인하세요.

실제 Windows 창·트레이·DPAPI와 회사 자료로 실행한 검증은 아직 없습니다. 원본 100% 동등성을 보장하지 않으며, 엑셀 일괄등록 등 기존 미구현 항목은 남아 있습니다.

## 소스 빌드

Go 1.27.3 이상에서 `build-windows.ps1`을 실행합니다. 출력은 `AlphaWorkRecoveryTest.exe`입니다.

테스트 자료 폴더를 바꾸려면 비어 있는 폴더를 지정하세요.

```powershell
.\AlphaWorkRecoveryTest.exe -data "D:\AlphaRecoveryTest"
```

Linux는 암호화를 적용하지 않는 시험용이며 `-headless -no-browser`로 GUI 없는 로컬 시험을 실행할 수 있습니다.
