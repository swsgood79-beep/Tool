# 알파 복구 테스트판 v1.3.1 · 기존 프로그램과 분리

이번 ZIP은 기존 프로그램과 함께 켜서 확인하는 **격리 테스트판**입니다. 이전 v1.0 ZIP은 원본 폴더에 직접 저장하므로 테스트 용도로 사용하지 마세요. v1.0 파일은 이력 보존을 위해 남겨 두었습니다.

## v1.3.1 엑셀 연결 0건 개선

엑셀 저장 설정은 **출력용 엑셀 사본 연결** 기능입니다. 엑셀만 넣어서 프로그램의 수주·완료 상태가 생성되는 기능은 아닙니다. 수주는 수주 엑셀 일괄등록으로, 기존 프로그램의 검사 기록/상태는 기존 자료 복사 기능으로 가져옵니다.

- 기존의 글자 단위 비교 대신 날짜 구분자·공백·Excel 날짜/시간 숫자·1904 날짜 체계·검사구분 공백·오전/오후·분/초 표시를 해석해 연결합니다. 분까지만 적힌 시간에 같은 수주/검사의 프로그램 기록이 여러 건이면 임의로 연결하지 않습니다. 명시된 초가 다르면 같은 기록으로 보지 않습니다.
- 엑셀 행 수 / 프로그램 완료 기록 수 / 현재 일치 수 / 읽지 못한 행을 표시합니다. 프로그램에 완료 기록이 없어서 0건인지, 파일 형식이 달라 읽지 못한 것인지 구분합니다. 파일을 연결했다는 표시가 기록 가져오기 성공을 뜻하지 않도록 설명을 보강했습니다.
- 기존 파일을 이미 넣었다면 **엑셀 저장 설정 → 현재 파일로 연결 다시 검사**를 누르세요. 새로 업로드하지 않아도 됩니다. 기존 연결/수정 기준과 메모는 보존합니다.
- ‘선택된 파일 없음’은 새 파일을 선택하지 않았다는 브라우저 표시이며, 위에 파일명이 나오면 기존 사본은 저장돼 있습니다.
- 사용자의 실제 작업완료기록.xlsx는 제공받지 않았습니다. 시험 파일로 구버전 0건을 재현하고 업그레이드/재검사/메모 유지/중복 방지를 검증한 결과이며 실제 문제 원인이 같다고 확정한 것은 아닙니다.

## 이번에 추가한 기능

- **수주 엑셀 일괄등록**: 관리자 왼쪽의 엑셀 일괄등록 → 파일 선택 → 미리보기 → 행 선택 → 등록. 최대 10MB, 한 시트 1,000건. 시트 선택·연결 새로고침·중복 제외·재전송 중복 방지를 지원합니다. 미리보기는 현재 로그인에서 30분 유지되며 프로그램을 종료하면 사라집니다.
- 제목 열은 **수주번호 / 프로젝트명**이 필수이고, **설계담당자 / 특이사항 업체 / 수주별 추가 메모**는 선택입니다. 빈 양식 내려받기도 제공합니다. 엑셀의 ‘박상준’은 ‘박상준 계장’과 비교합니다. 동명이인·미등록 이름은 추측하지 않고 직접 선택하거나 ‘없음’을 선택하게 합니다. 수식은 값을 붙여넣어야 합니다.
- 업체명을 적으면 등록된 업체의 글·사진을 연결합니다. 원본 업체를 수정하면 연결된 수주도 바뀌고, 수주별 추가 메모는 유지됩니다. 기존 수주는 덮어쓰지 않습니다.
- **작업자용 업체별 특이사항 전체 조회**: 작업자 검색창 위 ‘업체별 특이사항 전체 보기’ → 업체명·내용 검색 → 업체 펼치기 → 사진 확대. 수주에 연결하지 않은 업체도 볼 수 있으며 조회만 가능합니다. 관리자가 수정하면 약 3초 간격으로 반영합니다.
- **기존 엑셀 사본 병합**: 관리자 설정 → 엑셀 저장 설정 → 기존 .xlsx 선택 → 복사본 연결. 기존 메모·서식·수식·추가 시트를 보존하고 새 검사 완료 기록을 추가합니다. 원본 파일은 수정하지 않습니다. 최대 5MB입니다.
- 기존 엑셀 행은 수주번호·검사구분·완료일자·시간으로 연결합니다. 제목 열은 기존 6개 항목이어야 하며 날짜/시간은 YYYY-MM-DD / HH:mm:ss 형식입니다. 중복된 같은 기록은 임의로 매칭하지 않고 연결을 중단합니다. 프로그램에서 바뀐 항목만 덮어쓰며, 취소한 기록의 6개 항목은 비우되 같은 행의 별도 메모는 보존합니다. 연결되지 않은 기존 기록은 유지합니다. 외부 Excel에서 수정한 내용은 다시 업로드해야 반영됩니다.
- **문 열림 효과 기본 연결**: 작업자 첫 진입에 문이 열리는 효과를 보여줍니다. 같은 탭에서 돌아오거나 새로고침할 때는 가능한 경우 sessionStorage로 반복을 피합니다. `?entry=gate`로 다시 보거나 `?entry=skip`으로 생략할 수 있습니다. 이미지 로딩 실패/동작 줄이기 설정에는 우회 처리가 있습니다.

이미 v1.2에서 가져온 자료를 계속 쓰려면 **이 ZIP의 `continue-test.cmd` 또는 EXE**를 실행하세요. 다시 `copy-existing-data.cmd`를 실행하면 원본의 새 복사본을 만들어 이전 테스트 수정 내용과 별개로 시작합니다. 이전 버전 EXE와 번갈아 쓰지 마세요.

## 기존 회사 자료로 시험하기

1. 현재 실행 중인 **테스트판만** 트레이에서 종료합니다. 기존 운영 프로그램은 종료시키지 않습니다.
2. 새 ZIP을 압축 해제하고 **`copy-existing-data.cmd`**를 두 번 클릭합니다.
3. 같은 Windows 계정의 `%AppData%\WanryoTalk`에서 주요 데이터 파일과 `project-photos`를 **새 테스트 복사본**으로 가져온 뒤 테스트판이 열립니다. 수주·검사 기록·설계담당자·업체 특이사항·사진을 확인합니다.
4. ‘수주 · 메시지 관리’를 누르면 기존 자료에 저장된 관리자 비밀번호로 로그인합니다. 비밀번호가 없으면 테스트용 새 비밀번호를 설정합니다.
5. 관리자에서 수주를 수정하거나 작업자 화면에서 신청·승인해 보세요. 변경은 테스트 복사본에만 기록되며 원본으로 돌아가지 않습니다.
6. 다음부터는 **`continue-test.cmd` 또는 `AlphaWorkRecoveryTest.exe`**로 같은 복사본을 이어서 사용합니다. 원본의 최신 자료를 다시 가져오려면 테스트판을 종료하고 `copy-existing-data.cmd`를 다시 실행합니다. 이전 복사본과 예시 테스트 자료는 삭제하지 않습니다.

원본 파일은 읽기 전용으로 엽니다. 복사 전후 파일 목록·SHA-256과 복사된 바이트를 확인하며 원본 저장이 진행되어 자료가 바뀌면 중단하고 기존 테스트 복사본을 유지합니다. 이때 원본 저장이 끝난 뒤 다시 시도하세요. 복사에 실패하면 오류창이 뜨며 원본 파일은 수정하지 않습니다.

새 복사본은 `%AppData%\AlphaWorkRecoveryTest-v1.1\copies\copy-날짜-고유번호`에 생성합니다. 이전 시험판의 기본 폴더 이름은 그대로 유지합니다. `active-test-copy.json`은 다음 실행에 사용할 **테스트 폴더 이름만** 저장하며 운영 주소를 저장하지 않습니다. 복사본을 성공적으로 읽은 후에만 이 선택 정보를 바꿉니다.

복사 후 작업장 접근 키와 신청 폼 토큰은 시험용으로 새로 생성합니다. 접속 설정·키·외부 연동은 초기화하고 차단합니다. 기존 운영 QR·휴대폰 푸시·고정 관리자·GitHub 백업은 변경하지 않습니다. 원본의 별도 Documents 엑셀이나 수동 수정 이력은 가져오지 않으며, 복사된 검사 기록으로 테스트용 엑셀을 생성합니다.

**같은 Windows 계정에서 사용하세요.** Windows DPAPI 암호화 자료이므로 폴더를 다른 PC에 전달하거나 여기 업로드할 필요가 없습니다. `.cmd`는 같은 폴더의 `AlphaWorkRecoveryTest.exe`만 실행하며 다른 프로그램을 강제 종료하지 않습니다.

기존 자료를 가져오지 않고 처음 실행하면 예시 수주 TEST-001·TEST-002로 시작합니다. 접속 포트는 계속 **127.0.0.1:28791**, 창/트레이 이름은 ‘알파 복구 테스트판’이며 운영 자료 폴더를 `-data`로 지정하면 거부합니다.

## 외부 연동

기존 운영 서비스에 영향을 주지 않도록 이 시험판은 **외부 네트워크 전송을 차단**합니다. 운영 QR 접속 주소 게시·Cloudflare 터널·휴대폰 알림·모바일 관리자·고정 Pages 지문·GitHub 원격 백업을 사용하지 않습니다. 관련 메뉴에는 차단 안내가 표시됩니다. 시세나 OneDrive의 실제 조회도 하지 않습니다. 수동 로컬 일정 파일 읽기는 테스트 자료에만 반영합니다.

테스트 폴더에 저장된 외부 연동 설정은 시작 시 비워집니다. 운영 설정과 접속 키를 이 시험판에 넣을 필요가 없습니다. PC 자체 팝업은 외부 서버를 사용하지 않습니다.

## 기존 자료에 관하여

`%AppData%\WanryoTalk`에는 수주·기록·사진·설정 등 주요 데이터가 있지만 프로그램 소스 코드는 없습니다. DPAPI 파일은 같은 Windows 계정에서 읽어야 합니다. 접속 키가 있을 수 있으므로 폴더 전체를 채팅이나 GitHub에 올리지 마세요.

첫 실행 기본값은 별도 예시 데이터이며, `copy-existing-data.cmd`를 명시적으로 실행했을 때만 기존 자료를 복사합니다. 현재 원본 스키마 저장 구현은 테스트 폴더 안에서만 사용하며, 이전 v1.0의 ‘원본 직접 저장’ 설명은 운영 자료에 적용되지 않습니다. 이전 보고서는 `audit/RECOVERY-V1.0.md`에 이력으로 남아 있습니다.

## 검증과 제한

자동 시험으로 기존 자료 보호, 일괄등록·이름 매칭·중복·권한·업체 전체 조회·엑셀 사본 병합을 확인했습니다. 브라우저에서는 미리보기/선택/등록, 동명이인 해결, 업체 검색/사진/자동 갱신, 문 열림 중 문서 요청 1회, 검사 신청/승인과 병합 엑셀 내려받기를 확인했습니다. 이번 결과는 `audit/build-manifest-v1.3-test.json`과 `audit/browser-missing-features-v1.3.json`에 있습니다.

실제 Windows 창·트레이·DPAPI와 회사 자료로 실행한 검증은 아직 없습니다. 원본 100% 동등성을 보장하지 않습니다. 외부 연동은 시험판 격리를 위해 계속 차단합니다. 원본의 ngrok 실행·사진 자동 청소·대용량 백업 등 과거 보고서의 다른 차이까지 모두 해소한 버전은 아닙니다.

## 소스 빌드

Go 1.27.3 이상에서 `build-windows.ps1`을 실행합니다. 출력은 `AlphaWorkRecoveryTest.exe`입니다.

테스트 자료 폴더를 바꾸려면 비어 있는 폴더를 지정하세요.

```powershell
.\AlphaWorkRecoveryTest.exe -data "D:\AlphaRecoveryTest"
```

Linux는 암호화를 적용하지 않는 시험용이며 `-headless -no-browser`로 GUI 없는 로컬 시험을 실행할 수 있습니다.
