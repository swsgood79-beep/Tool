업체 특이사항의 내용·사진 수정은 이미 보관 완료된 출하 기록과 새로 저장하는 출하 엑셀에도 반영합니다. 수주별 추가 메모·사진은 별도로 유지하고 명시적으로 수주 특이사항을 수정하면 동일 검사 건의 출하 상세도 갱신합니다. 출하사진·첨부·사급품·담당자·검사 완료일·보관일은 변경하지 않습니다. 업체 원본을 삭제하면 마지막 내용을 보관합니다.

대표 관리자 이름은 **전체 → 관리자 계정 관리 → wssong 행의 이름 수정**에서 변경합니다. 과거 검사자는 같은 화면의 **기존 검사자 기록 보완**에서 선택 또는 미기록 전체에 실제 이름을 저장합니다. 이미 기록된 이름·원래 완료일·보관일은 유지합니다. [검사자 기록 안내](INSPECTION-INSPECTORS.md).

PC v1.4.86 이상은 **PC 업데이트 확인 → v1.4.91 업데이트**로 설치하세요. 모의 자료의 완료 시각·PC 재접속/CSRF·원래 기록 보존·출하 XLSX 및 Chromium PC/휴대폰 밝게·어둡게 화면을 검증했습니다. 실제 회사 자료와 Windows/Android 기기 실행은 하지 않았습니다.

## 2. 처음 실행과 업데이트

### 이미 사용 중인 회사 PC 업데이트

PC v1.4.86 이상에서는 프로그램 아래 **PC 업데이트 확인 → 새 버전 업데이트**를 사용합니다. v1.4.85 이하에서는 아래 절차를 처음 한 번 사용합니다.

1. 위의 최신 Windows ZIP을 내려받아 쓰기 가능한 폴더에 압축을 풉니다.
2. 기존 프로그램의 **종료 버튼 또는 트레이 종료**로 완전히 끝냅니다.
3. 새 `AlphaWorkComplete-Recovered.exe`를 실행합니다. 기존 운영 자료와 저장 위치를 이어서 사용합니다.
4. 이후 업데이트는 PC 창 아래 **v버전 업데이트** 버튼을 누르세요. 최신 버전일 때는 **PC 업데이트 확인**으로 표시합니다.

자료 폴더를 지우거나 빈 자료로 다시 시작하지 마세요. D드라이브 등 지정한 자료 경로도 유지합니다. 설치 폴더에 쓸 수 없거나 업데이트에 실패하면 기존 버전으로 계속 사용하며 상태 문구를 표시합니다.

### 기존 원본 프로그램에서 처음 운영판으로 전환

기존 자료를 사용하는 **같은 Windows 계정**에서 실행합니다. 첫 실행 선택창에서 기존 운영 자료 또는 테스트 자료를 선택하고, 기존 자료는 보존한 채 운영 복사본으로 시작합니다. 이후 실행은 이 운영 자료를 이어서 사용합니다. 상세 전환 안내는 [빠른 시작](START-HERE.md)을 참고하세요.

### 관리자 앱 업데이트

앱 상단 **⋮ → 앱 업데이트 확인 → 다운로드·설치**를 사용합니다. 기존 앱 위에 업데이트하면 로그인 연결과 설정을 이어서 사용합니다. Android의 설치 확인·앱 검사는 기기의 설치 절차입니다.

일반 화면·기능은 회사 PC 프로그램 업데이트로 반영됩니다. 앱 상단·기기 기능처럼 APK 자체를 변경한 경우에는 APK 업데이트도 필요합니다. **앱 v1.0.11은 업데이트 다운로드를 개선합니다. 이 수정은 PC 교체 없이 앱 업데이트만으로 적용됩니다. 구매팀 기능은 PC v1.4.82 이상에서 사용할 수 있습니다.**

## 3. 수주 확인과 작업자 사용

작업자 하단 메뉴는 **작업 · 출고 일정 · 업체 특이사항 · 토크 · 전체**입니다.

작업 메뉴에서 수주번호나 프로젝트명으로 검색하고 전체·세팅·출하·금일 완료 등의 목록을 확인합니다. 오늘 납기·다음 출고와 출고 일정은 연결된 납기 및 수주 상태를 기준으로 표시합니다. 날짜만 보고 판단하기 어려우면 수주 카드의 단계와 검사 완료 여부도 함께 확인하세요.

카드의 설계담당자를 누르면 휴대폰 전화 기능을 사용할 수 있습니다. 사급품 버튼은 사급품 상태·수령내역을, 특이사항 버튼은 작업 전 확인할 글·사진을 보여줍니다. 검사 신청은 카드의 **검사 화면 열기**에서 진행합니다.

수주에 전달할 내용은 해당 수주의 비고 기능으로 남깁니다. 토크 게시글과 별개로 해당 수주에 연결되는 메시지입니다.

## 4. 검사 신청부터 완료까지

**작업자의 신청과 관리자의 검사 완료를 구분합니다.** 신청 버튼을 눌렀다는 이유만으로 다음 단계가 완료되지 않습니다.

1. 작업자가 해당 수주의 검사 화면에서 이름을 확인하고 **세팅검사 신청**을 누릅니다.
2. 관리자 PC·관리자 휴대폰에 신청이 전달되고, 해당 수주는 관리자 확인 대기 상태가 됩니다.
3. 관리자가 수주 검사 화면을 열어 실제 검사를 진행합니다. 문제가 없으면 **세팅검사 완료**로 처리하고 작업자는 출하검사를 신청할 수 있습니다.
4. **출하검사 신청 → 관리자 검사 → 출하검사 완료**도 같은 방식으로 진행합니다.
5. 보완이 필요하면 관리자가 반려하고 작업자가 보완 후 다시 신청합니다. 작업 방식에 따라 세팅·출하를 함께 신청하는 기능도 사용할 수 있습니다.

관리자는 PC의 검사 신청 목록, 수주의 검사 화면, 알림의 확인 동선에서 검사 화면을 열 수 있습니다. 알림을 읽거나 검사 화면을 열기만 해서는 검사 완료가 되지 않습니다.

완료 처리는 인증된 관리자만 할 수 있습니다. 잘못 완료한 경우에는 관리자 검사 화면이나 검사 기록에서 취소/다시 열기를 사용합니다. 단순히 알림 읽음 여부를 바꾸는 것과 검사 완료 취소는 별도 기능입니다.

## 5. 관리자 계정·앱 로그인·화면 전환

대표 관리자 아이디는 **wssong**이며 기존 비밀번호를 사용합니다. 동료 검사자는 대표 관리자의 **전체 → 관리자 계정 관리**에서 개인 계정을 만들어 사용합니다. 비밀번호는 8자 이상으로 설정하고 개인 계정은 내 비밀번호 변경을 사용할 수 있습니다. 계정 관리 등 일부 설정은 대표 관리자만 사용할 수 있습니다.

관리자 앱 하단 메뉴는 **작업 · 출고 일정 · 검사 · 토크 · 전체**입니다. 상단에는 현재 로그인 담당자와 로그아웃 버튼이 표시됩니다.

한 번 로그인하면 **직접 로그아웃할 때까지 유지**합니다. 다른 앱을 쓰다 돌아오면 기존 업무 화면을 사용하고, 앱을 완전히 종료했다 켜면 저장된 로그인 연결을 서버에서 확인해 접속합니다. 매번 비밀번호나 지문을 요구하지 않습니다. 연결이 잠시 안 되면 연결 화면에서 재시도합니다.

처음 로그인하거나 직접 로그아웃한 경우에는 아이디·비밀번호 화면이 나옵니다. 지문 버튼은 저장된 계정 연결이 있을 때 사용할 수 있으며 사용자가 직접 눌렀을 때만 인증창을 엽니다. 지문 데이터나 비밀번호를 저장하지 않습니다. 계정/기기 연결 해제, 비밀번호 변경, 앱 데이터 삭제 등으로 저장 연결이 무효화되면 재로그인이 필요합니다.

**작업자 화면 보기:** 상단 ⋮ 또는 전체 메뉴에서 작업자 화면으로 전환하고 같은 위치에서 관리자 화면으로 돌아옵니다. 화면을 바꿔도 관리자 로그인과 앱 알림 연결은 유지합니다.

**로그아웃:** 해당 휴대폰의 저장 로그인·지문 연결·앱 알림 연결을 해제합니다. 다른 관리자 휴대폰과 독립된 PC 로그인은 유지합니다.

## 6. 관리자 PC·휴대폰·공용 PC 알림

작업자가 검사 신청이나 비고를 남기면 설정된 PC·휴대폰 연결로 전달됩니다. PC 프로그램은 Windows 알림/음성 설정을, 관리자 APK는 Android 앱 알림을 사용합니다.

관리자 앱에서 최초 한 번 [Firebase 설정](ANDROID-ADMIN-SETUP.md)을 완료하고 알림 권한을 허용합니다. 다른 검사자는 같은 회사 연결에 개인 관리자 계정으로 로그인하면 되며 각자 Firebase 프로젝트를 만들 필요가 없습니다. 앱 상단 **⋮ → 알림 소리·진동 설정**에서 Android 설정을 열어 소리를 바꿀 수 있습니다.

공용 PC에서는 작업자 화면의 **공용 PC 음성 알림**을 켜고 미리듣기로 스피커를 확인합니다. 긴급공지 음성 방송을 들을 PC는 긴급공지 음성 수신도 켭니다. 브라우저의 소리 허용·절전·백그라운드 실행 상태에 따라 수신·재생이 영향을 받을 수 있습니다. 미리듣기가 된다는 것만으로 실제 신청 수신까지 확인된 것은 아니므로 시험 신청도 확인하세요.

검사 알림이 왔을 때는 알림의 수주번호·신청자를 확인하고 해당 검사 화면에서 처리합니다. 앱 알림과 삼성 인터넷/Chrome 웹 알림은 서로 다른 알림 설정입니다.

## 7. 업체 원본 특이사항과 수주별 메모

관리자 앱에서는 **전체 → 업체 특이사항 관리 → 해당 업체의 업체 특이사항 수정**으로 들어갑니다. 전체 메뉴의 기존 업체 특이사항 위치에서 원본 관리 화면이 열립니다.

- **업체 원본:** 업체에 공통으로 사용하는 글·사진입니다. 원본 수정 후 업체 수정 저장을 누릅니다.
- **수주 연결:** 수주 등록/수정에서 업체 원본을 불러오고 자동 반영을 연결하면 원본 변경을 해당 수주에 반영합니다.
- **수주별 추가 메모:** 해당 수주에만 필요한 내용을 따로 남깁니다. 업체 원본이 바뀌어도 유지합니다.
- **작업자 조회:** 업체 특이사항 메뉴에서 등록된 업체의 글·사진을 검색해 확인합니다. 작업자는 업체 원본을 수정하지 않습니다.

업체 원본은 글 5,000자, 사진 합계 5장까지 사용합니다. 업체 원본 삭제 시 연결된 수주에는 마지막 내용이 남도록 처리합니다. 보관 완료된 출하 기록의 과거 정보는 현재 업체 원본과 구분해서 확인하세요.

## 8. 출하사진 등록과 출하 기록

관리자가 출하검사를 완료한 수주는 **출하 기록 → 출하사진 필요** 목록에서 확인합니다. 작업자는 해당 수주를 열어 완성 상태·포장 등 필요한 사진과 선택 메모를 등록합니다. 사진을 등록하면 **보관 완료**로 넘어갑니다.

**수주 한 건당 사진은 총 30장, 한 장당 업로드 제한은 8MB입니다.** 사진은 긴 변 1,600px 이내의 JPEG로 줄여 저장합니다. 보관 완료 후 빠뜨린 사진도 기존 사진을 포함한 30장 범위에서 추가할 수 있습니다. 사진을 확대하면 좌우 넘김으로 다음 사진을 볼 수 있습니다.

출하 기록에서는 수주번호·프로젝트명·고객사 검색, 전체/이번 달/지난달/기간 지정, 월별 정렬과 페이지 이동을 사용합니다. 보관 완료의 기간 분류는 **최초 보관 날짜 기준**입니다.

보관에는 사진뿐 아니라 수주 정보, 설계담당자, 세팅·출하 작업자와 검사 날짜, 해당 시점의 특이사항·사급품 상태/수령내역도 포함됩니다. 연결 납기표에서 수주가 사라지거나 출고 예정일이 바뀌어도 보관한 기록은 남습니다.

보관 자료 삭제와 검사 완료 취소는 서로 다른 작업입니다. 보관 사진을 삭제했는데 현재 수주의 검사가 완료 상태이면 출하사진 필요로 돌아갈 수 있습니다. 그 수주의 검사 완료도 취소하면 해당 검사 주기의 사진 대기 항목을 정리합니다. 과거 보관 완료 기록은 관리자 보관 관리에서 별도로 확인합니다.

## 9. 공지사항·긴급 음성 방송·토크

관리자는 공지사항 관리에서 제목·내용·사진과 게시 여부를 등록합니다. 긴급공지는 강조 테두리로, 일반공지는 일반 공지 색상으로 구분하고 작업자 화면에서 확인합니다.

긴급공지의 **음성 방송**을 누르면 수신 중인 공용 PC에 방송 요청을 보냅니다. 공용 PC의 브라우저·스피커·음성 수신 설정을 확인하세요. 공지 내용을 변경한 것과 방송 버튼을 누른 것은 별도 동작입니다.

토크는 **전체 · 작업안내 · 건의사항 · 일상생활**로 구분합니다. 글·사진·댓글·좋아요를 사용하며, 제목을 누르면 게시글 상세가 열립니다. 작성자는 해당 브라우저에서 작성한 글을 수정·삭제하고 관리자는 게시글·댓글을 정리할 수 있습니다.

토크 메뉴의 숫자는 읽지 않은 글 수입니다. 같은 기기·브라우저의 읽음 기록을 사용하며 브라우저 데이터 삭제·다른 브라우저에서는 읽음 상태가 달라질 수 있습니다.

## 10. 납기표·사급품·엑셀·시장 정보

연결된 납기표는 수주번호로 수주와 납기·사급품 정보를 연결합니다. 납기 연동 상태와 최근 조회 결과는 관리자 설정에서 확인합니다. 사급품 수령 상태의 버튼을 누르면 연결된 사급품 수령내역에서 **종류·제조사·품번·수량**을 확인하고, 내용이 많으면 표 안에서 스크롤합니다.

검사 기록 엑셀 연결은 업무 자료를 출력용 운영 사본에 저장하는 기능입니다. 엑셀 한 파일이 프로그램의 모든 수주·사진·계정 정보를 대신하는 것은 아닙니다. 납기표 연동, 수주 엑셀 일괄등록, 완료 기록 엑셀 저장은 각각 다른 기능입니다.

시장 정보는 코스피·코스닥, 비트코인·이더리움, 원·달러 환율을 표시합니다. 지수 등락률은 표시 지수와 그 기준일의 **직전 거래일 종가**로 계산하고 코인은 UTC 전일 종가 기준을 사용합니다. 기준 자료가 확인되지 않으면 등락률은 —로 표시합니다. 마지막 자료/지연 표시와 기준시각을 함께 확인하세요.

## 11. 자료 저장 위치와 백업

수주·사진·공지·토크·설정은 **회사 PC에 설정된 운영 자료 폴더**에 저장합니다. 휴대폰이나 다른 PC에서 올린 자료도 연결된 회사 PC에 보관됩니다. 실제 저장 위치는 회사 PC의 관리자 화면에서 **전체 → 자료 저장 위치**로 확인합니다.

D드라이브 등으로 옮기려면 비어 있는 전용 폴더를 지정하고 다음 실행부터 사용할 위치로 예약합니다. 프로그램을 완전히 종료한 뒤 다시 실행하면 복사·검증 후 전환합니다. 기존 자료 폴더는 보존됩니다. 기본 운영 위치는 `%AppData%\AlphaWorkCompleteRecovered`이며, 이미 별도 경로를 지정했다면 그 설정을 사용합니다.

일부 업무 파일·사진은 보호된 형식으로 저장되어 탐색기에서 일반 JPG처럼 보이지 않을 수 있습니다. 사진 확인은 프로그램을 사용하고, 전체 자료 이전은 지원하는 백업/복원 절차를 사용하세요.

GitHub 백업을 설정한 경우 사진·동영상·첨부파일과 업무 자료를 200MiB 단위로 분할·암호화해 Releases에 보관합니다. 전체 256MB 제한을 없앴으며 최근 정상 3세트를 유지합니다. [분할 백업 안내](BACKUP-SETS.md)를 참고하세요. **공개 개발 소스 저장소와 회사 자료 백업은 구분됩니다.** 복구키는 PC 밖에도 보관합니다. 새 PC/다른 Windows 계정으로 주 서버를 옮길 때는 Windows 계정에 묶인 보호 자료를 고려해 암호화 백업 복원을 사용합니다.

다른 검사자가 별도 PC에서 접속하려는 경우에는 주 서버를 옮길 필요 없이 현재 회사 서버의 관리자 주소에 자기 계정으로 로그인하면 됩니다.

## 13. 소스·빌드·검증 범위

현재 운영판의 Go 소스는 이 폴더와 소스 ZIP에 있습니다. Android 소스는 `android-admin/`, 기능별 검증 자료는 `audit/`에 있습니다. 서명키·Firebase 서비스 계정 비밀키·회사 운영자료는 공개 소스에 포함하지 않습니다.

이 프로그램은 **복구 운영판 계열**입니다. 원본 v2.x 실행파일에서 원래 소스를 100% 동일하게 복원한 것이라는 뜻은 아닙니다. 현재 구현·제한과 검증 결과는 버전별 `audit/RECOVERY-*.md` 및 빌드 manifest로 확인합니다.

Go 1.27.3 이상에서 Windows GUI 빌드 예시:

```powershell
$env:GOOS='windows'; $env:GOARCH='amd64'; $env:CGO_ENABLED='0'
go build -trimpath -buildvcs=false -ldflags='-s -w -H=windowsgui' -o AlphaWorkComplete-Recovered.exe .
```

Android는 Java 17·Android SDK 35와 별도 서명 설정을 사용합니다. 자세한 내용은 [Android 소스 안내](android-admin/README.md)를 참고하세요. 소스 ZIP의 파일 체크섬과 배포 EXE 동일 재빌드 기록은 다운로드 목록에 함께 보관합니다.

자동 테스트·브라우저 검증·서명 확인과 실제 Windows/Android 기기 실행은 구분합니다. 물리 기기의 알림·지문·카메라·설치·절전 동작은 해당 환경에서 확인해야 합니다. 변경 이력은 [CHANGELOG.md](CHANGELOG.md)에 보관합니다.

### 휴대폰에서 사진 추가

관리자 APK 1.0.11의 ‘앨범에서 선택’을 누르면 **갤러리에서 선택 · 파일에서 선택 · 카메라로 촬영**이 나옵니다. 삼성 갤러리가 설치되어 있고 사진 선택을 지원하면 직접 열며, 다른 기기는 갤러리 선택 창을 사용합니다. 촬영 버튼은 카메라를 바로 엽니다. 파일 선택은 Android 문서 선택기를 사용합니다. 갤러리·구글 포토에서 선택한 JPG/PNG/GIF/WebP를 추가할 수 있고, HEIC는 JPG로 변환해야 합니다.

사진을 선택하면 추가 장수와 미리보기를 확인한 후 ‘추가 사진 저장’을 누릅니다. 모바일에서 가상 파일 목록 생성에 의존하던 처리를 제거했습니다. 오류가 나면 선택한 사진을 유지하므로 다시 저장할 수 있습니다. 성공이 확인된 뒤에만 화면을 이동합니다. 수주당 기존 사진과 합쳐 최대 30장, 각 8MB이며 원래 보관일과 기존 사진은 유지합니다. 실제 삼성 기기의 갤러리 실행은 기기에서 확인해야 합니다.

### 출하사진 일부만 삭제

관리자 앱·PC에서 **전체 → 출하 기록 → 보관 완료 → 해당 수주 → 사진 아래 ‘삭제’**를 누릅니다. 선택한 사진을 확인하고 ‘이 사진 삭제’를 누르면 한 장만 삭제합니다. 취소하면 변경하지 않습니다. 일반 작업자에게는 삭제 버튼이 없습니다. 나머지 사진·담당자·검사 완료 상태·최초 보관일은 유지됩니다. 추가하려고 선택해 둔 사진이 있으면 먼저 저장하거나 추가를 취소해야 합니다.

마지막 사진 삭제는 기존 전체 삭제와 같은 기준입니다. 현재 검사 완료 수주에 연결되어 있으면 ‘출하사진 필요’로 되돌아갑니다. 현재 수주와 같은 검사 주기로 연결되지 않은 과거 보관 기록이면 마지막 사진과 보관 자료를 함께 삭제합니다. 확인창에 해당 동작을 표시합니다. 저장 성공 후 다른 곳에서 참조하지 않는 사진 파일도 정리합니다.

## 14. 구매팀 호출

별도 앱을 설치하지 않습니다. 현재 앱에 구매팀 계정으로 로그인하면 **호출 목록 · 완료 내역 · 전체**만 표시됩니다. 검사 관리자는 기존 화면을 그대로 사용합니다. 권한은 서버에서도 분리하며 구매팀 계정은 검사/수주 관리 주소에 직접 접속해도 사용할 수 없습니다.

대표 관리자에서 **전체 → 관리자 계정 관리 → 계정 권한 ‘구매팀 · 호출 전용’**으로 실제 담당자의 계정을 만들고 **구매팀 호출·알림 설정**에서 수신 담당자를 지정합니다. 구매 담당자는 같은 앱 v1.0.11에 로그인하고 알림을 허용합니다. 기존 Firebase를 재사용하며 새 프로젝트·별도 Android 앱 등록은 필요 없습니다. 자세한 절차는 [구매팀 호출 시작하기](PURCHASING-SETUP.md)를 참고하세요.

작업자는 수주카드에서 **구매팀 호출 → 이름 확인 → 구매팀에 호출 보내기**로 끝납니다. 요청 종류/메모/작업자 호출 내역은 없습니다. 구매 담당자에게 수주번호·제품명·호출자·접수시간을 전달하고, **완료하고 다음 호출 보기**로 오래된 미완료 건부터 처리합니다. 완료 내역은 회사 PC 자료에 보관됩니다. 같은 사람의 처리 전 중복 호출과 응답 유실 재전송은 중복 등록하지 않습니다.

구매팀 호출 알림과 기존 검사 알림은 계정·알림 채널로 분리됩니다. 구매팀도 관리자와 동일하게 기기별 로그인 연결을 사용하여 직접 로그아웃하기 전까지 앱 종료·재시작·업데이트 후 로그인을 복구합니다. 같은 APK인 만큼 앱 자체 업데이트는 공통으로 안내됩니다. 회사 PC·프로그램·인터넷은 계속 실행되어야 합니다. 실제 휴대폰 잠금화면/FCM 동작은 기기 확인이 필요합니다.

## 15. 앱 업데이트가 바로 시작되지 않을 때

앱 v1.0.11은 ‘업데이트’를 누르면 로그인·작업 입력 상태와 무관하게 다운로드를 바로 시작하고 진행률을 표시합니다. 다운로드는 입력 내용을 지우지 않으며, 설치 단계만 로그인 연결이나 저장 작업이 끝날 때까지 기다립니다. 인터넷의 일시적인 오류는 최대 3회 자동 재시도하고, 실패 시 ‘다시 시도’ 버튼을 제공합니다.

완료된 APK와 동의한 업데이트 요청을 앱 캐시에 보관합니다. 화면 재생성·재실행 시 상태를 읽고 파일을 다시 검증해 이어갑니다. 설치 창을 취소하거나 ‘나중에’를 누른 경우에는 **⋮ → 앱 업데이트 확인**에서 다시 설치할 수 있습니다. Android가 앱 프로세스를 종료한 미완료 다운로드는 재실행 후 다시 받으며, 파일 캐시를 Android가 삭제한 경우에도 다시 다운로드해야 합니다. 캐시 재사용 시에도 SHA-256·패키지·새 버전·기존 서명을 확인하고, Android 설치 확인은 사용자가 누릅니다.

이 수정은 앱에 포함되므로 기존 앱에서 업데이트가 계속 실패한다면 표의 **APK 다운로드**로 v1.0.11을 받아 기존 앱 위에 설치하세요. 앱을 삭제할 필요가 없으며 기존 로그인·계정·알림 설정은 유지합니다. PC 프로그램이 v1.4.82이라면 이번 다운로드 수정만을 위해 PC를 교체할 필요는 없습니다. 실제 휴대폰의 설치·복귀 흐름은 기기 확인이 필요합니다.
